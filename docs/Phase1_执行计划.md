# ViralDNA Phase 1 详细执行计划

> 文档状态：执行中
> 开始日期：2026-08-02
> 代码仓库：https://github.com/wojimmy666-code/viral-dna
> 产品范围：单视频分析，不包含账号分析与视频模型生成

## 1. 阶段目标

Phase 1 交付一个可内测的“单视频逆向拆解与复刻提示词工作台”。用户上传视频文件或粘贴抖音、小红书公开视频链接后，可以得到：

1. 带时间戳的详细分镜。
2. 人物、服装、场景、产品、道具和风格元素表。
3. 视频 Hook、节奏、冲突、情绪、价值点和互动触发点分析。
4. 模型无关的 Prompt IR。
5. 通用版和 Seedance 版逐镜头提示词包。
6. 替换人物、服装、场景等元素后的新提示词版本。
7. Markdown、JSON 和 ZIP 导出。

Phase 1 不生成视频，也不承诺仅靠提示词像素级复制原片。验收目标是还原视频的镜头结构、主体动作、视觉语言、节奏和叙事功能。

## 3. 一期成功指标

### 3.1 产品指标

- 用户能在 2 分钟内完成一次视频导入。
- 分析过程始终展示当前阶段、进度和失败原因。
- 用户能从分镜列表一键定位到视频时间点。
- 用户能在 3 步内完成一次元素替换并获得新提示词。
- 所有 Prompt Pack 可复制并可导出机器可读 JSON。

### 3.2 技术目标

- 分析任务成功率目标不低于 95%。
- 三分钟视频 P95 分析时长目标不超过 10 分钟。
- 分镜边界 F1 目标不低于 0.90，容差 ±0.3 秒。
- 核心人物、服装、场景人工判断准确率目标不低于 85%。
- 所有模型结果必须通过 JSON Schema 校验。
- 所有爆点结论必须引用时间戳证据。
- 同一输入、同一分析版本可复用缓存，不重复付费调用模型。

### 3.3 复刻提示词验收

研发阶段人工选择不少于 20 个视频，将导出的提示词复制到目标视频模型中验证：

- 镜头数量和顺序。
- 主体、场景和主要道具。
- 动作和运镜。
- 整体风格与灯光。
- 跨镜头连续性。

提示词可执行性由至少两名评审者按 1～5 分打分，平均目标不低于 4 分。

## 5. 工作分解结构

### 5.1 M0：基础与决策

#### 仓库

- 初始化 `main` 分支。
- 配置远程仓库。
- 建立 `.gitignore`、README 和环境变量模板。
- 建立 `apps/web`、`services/api` 和 `docs`。
- 已补充 GitHub Actions：Web 构建、Python 测试和 lint。

#### 模型 POC

- 准备 30 条已获得使用权的视频。
- 覆盖口播、产品展示、探店、美妆、剧情、快剪和无对白内容。
- 对比至少两个多模态 Provider。
- 记录精度、耗时、Token、费用、结构化输出成功率。
- 模型 ID 通过配置注入，不写死在业务代码中。

### 5.2 M1：首个纵向切片

#### API

- `POST /videos/link`：创建链接视频记录。
- `POST /videos/upload`：接收文件并创建视频记录。
- `POST /videos/{id}/analyses`：创建分析任务。
- `GET /analyses/{id}`：查询进度。
- `GET /analyses/{id}/events`：SSE 状态流。
- `GET /videos/{id}/report`：读取报告。
- `POST /videos/{id}/replacement-versions`：生成替换版本。

首轮使用确定性的模拟分析器，先验证产品交互、数据结构和任务编排；真实处理器按相同接口替换。

#### Web

- 桌面端工作台框架。
- 文件上传与链接导入切换。
- 分析任务进度和阶段状态。
- 总览、分镜、爆点、元素替换和提示词标签页。
- 分镜点击定位视频时间。
- 替换表单和版本结果。
- Prompt 复制与 JSON 下载。

### 5.3 M2：媒体证据层

#### 媒体探测

- 使用 `ffprobe` 获取格式、时长、帧率、分辨率、音轨和编码。
- 对 MIME、扩展名和真实容器进行交叉校验。
- 统一生成 H.264/AAC 1080P 分析代理文件。

#### 分镜

- PySceneDetect/FFmpeg scene score 作为基础。
- 普通镜头提取开始、中间、结束帧。
- 1.5 秒以下快速镜头自适应增加采样。
- 保存镜头 contact sheet 和代表关键帧。
- 支持后续人工修正边界。

#### ASR 与 OCR

- ASR 输出句子级和词级时间戳。
- OCR 识别字幕、贴纸、价格和品牌文字。
- 连续帧 OCR 去重。
- 将语音、OCR 和镜头合并为统一时间线。

### 5.4 M3：多模态事实提取

- 每个镜头以关键帧、上下文字幕和相邻镜头摘要为输入。
- 第一轮只提取可观察事实，不分析爆款原因。
- 输出人物、服装、动作、场景、道具、产品、景别、机位、构图、运镜、灯光、色彩和转场。
- 为事实保存 `evidence_frame_ids`、时间戳和置信度。
- 使用视觉 Embedding、人脸聚类和 VLM 复核生成稳定实体 ID。
- 对冲突结果执行规则检查和 AI Critic 复核。

### 5.5 M4：爆点与 Prompt 编译

#### 爆点分析

- 前三秒 Hook：25 分。
- 节奏和留存结构：20 分。
- 情绪、冲突和反转：15 分。
- 信息或结果价值：15 分。
- 视觉记忆点：10 分。
- 收藏、分享、评论触发：10 分。
- 平台原生感：5 分。

每条结论输出观察事实、时间段、作用机制、置信度、风险和可复用建议。

#### Prompt IR

- 全局风格与视频规格。
- 稳定实体定义。
- 跨镜头连续性锁。
- 逐镜头主体、动作、场景、机位、运镜、灯光和声音。
- 负面约束。
- 目标模型 Adapter。

### 5.6 M5：元素替换

- 支持替换人物、服装、场景、产品、道具和整体风格。
- 用户选择保留动作、构图、镜头、灯光、节奏等锁定项。
- 场景替换自动处理灯光、环境声和道具的依赖关系。
- 人物替换不默认改变服装和动作。
- 生成新 Prompt Package，而不是覆盖原始版本。
- 输出字段级 diff 和受影响镜头清单。

### 5.7 M6：验证与内测

- 建立黄金标注数据集。
- 单元测试、契约测试、端到端测试和视觉 QA。
- 记录每一步耗时、模型、Token 和估算成本。
- 视频哈希和模型结果缓存。
- 文件生命周期、主动删除和自动清理。
- URL SSRF 防护、域名白名单、重定向次数和下载大小限制。
- 真人素材授权提示和内容使用权确认。
- 内测部署、日志、错误追踪和恢复手册。

## 7. 风险与降级

| 风险 | 影响 | 降级方式 |
|---|---|---|
| 抖音/小红书链接无法稳定读取 | 链接导入失败 | 明确提示并回退文件上传，不使用登录绕过 |
| 快切镜头被 VLM 漏掉 | 分镜和 Prompt 不完整 | 本地分镜和自适应抽帧先于 VLM |
| 模型产生幻觉 | 报告不可信 | 事实与推理解耦，所有结论引用证据 |
| 模型升级导致输出漂移 | 回归失败 | 固定分析版本、Schema 和黄金测试集 |
| 成本随视频时长线性增长 | 商业模式不可控 | 自适应抽帧、缓存、分层模型和调用预算 |
| 人物替换涉及肖像权 | 合规风险 | 权利确认、授权提示、资产删除和审计字段 |

## 8. 完成定义

一个任务只有同时满足以下条件才算完成：

1. 功能实现并通过主要错误路径验证。
2. 数据结构和接口文档同步更新。
3. 有自动化测试或明确的人工验收用例。
4. 没有把模拟结果标记为真实 AI 结果。
5. Web 构建、API 测试和设计 QA 通过。
6. 新增模型调用记录版本、耗时和成本信息。
