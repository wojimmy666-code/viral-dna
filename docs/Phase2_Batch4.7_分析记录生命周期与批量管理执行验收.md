# Phase 2 Batch 4.7：分析记录生命周期与批量管理执行验收

## 1. 本批目标

当工作区中的分析记录持续增加时，用户可以通过高密度单列列表快速检索记录，并将暂时不用的记录归档、将无效记录移入回收站，或在回收站中恢复和永久删除。第一期同时支持多选批量操作。

本批次只管理“分析记录”的生命周期，不删除资产库中的共享资产，也不改变视频分析状态的含义。

## 2. 已实现范围

### 2.1 三种生命周期

- 当前记录：正常使用中的记录。
- 已归档：暂时收起但仍完整保留的记录。
- 回收站：等待恢复或永久删除的记录。
- 分析状态（待分析、分析中、已完成、失败）与生命周期相互独立。
- 从回收站恢复时，记录返回移入回收站前的“当前记录”或“已归档”位置。

### 2.2 方案 B 高密度列表

- 桌面端使用单列数据列表，显示复选框、缩略图、名称、时长、状态、来源、一级目录、更新时间和更多操作。
- 左侧“分析记录”下嵌套当前记录、已归档、回收站及各自数量。
- 窄屏将生命周期入口切换为正文顶部的紧凑分段栏。
- 页面只显示一个生命周期主标题；结果数和目录筛选状态合并在主标题旁，避免重复标题占用空间。
- 返回分析记录或后台刷新时保留现有列表，不再用加载面板卸载全部记录；同一应用会话内已经加载的缩略图直接复用已加载状态。
- 真实首次加载使用骨架层与图片交叉淡入，避免骨架瞬间消失后短暂露出空白底色。
- 支持名称／链接／作者搜索、状态筛选、目录筛选、排序、分页和每页 20／50／100 条。

### 2.3 单条与批量操作

| 所在位置 | 单条／批量操作 |
|---|---|
| 当前记录 | 归档、移入回收站 |
| 已归档 | 恢复到当前记录、移入回收站 |
| 回收站 | 恢复、永久删除 |

- 列表复选框始终可见，表头复选框只选择当前页。
- 选中记录后，页面底部显示悬浮批量操作栏。
- 翻页或切换生命周期时会清理不可见记录的选择状态，避免误操作。
- 永久删除必须再次确认；普通归档、移入回收站和恢复不弹确认框。
- 操作成功或失败通过账户消息与 Toast 反馈。

### 2.4 数据安全

- 永久删除只允许对回收站中的记录执行。
- 永久删除采用记录墓碑状态，已删除记录不再出现在列表、详情、缩略图、更新和导出接口中。
- 记录关联的共享视频或资产对象继续保留，避免误删资产库中仍被其他项目使用的内容。

## 3. 主要接口

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/v1/records?lifecycle=active|archived|trashed` | 按生命周期分页查询并返回三类数量 |
| `PATCH` | `/api/v1/records/{record_id}/lifecycle` | 修改单条记录生命周期 |
| `PATCH` | `/api/v1/records/batch/lifecycle` | 批量归档、恢复或移入回收站 |
| `DELETE` | `/api/v1/records/{record_id}` | 永久删除一条回收站记录 |
| `DELETE` | `/api/v1/records/batch` | 批量永久删除回收站记录 |

## 4. 人工验收流程

### 4.1 页面结构与密度

1. 打开“分析记录”。
2. 确认桌面端左侧显示“当前记录 / 已归档 / 回收站”及数量。
3. 确认正文主标题旁显示结果数，筛选栏和列表之间不再重复一行标题。
4. 确认每条记录均有复选框和缩略图；长名称被截断，不挤压其他列。
5. 分别使用状态、目录、排序和搜索，确认结果与数量同步刷新。
6. 将每页数量切换为 20、50、100，并验证上一页、下一页和页码。

### 4.2 当前记录批量归档

1. 在当前记录中选择两条可用于验收的记录。
2. 确认底部出现“已选择 2 条 / 归档 / 移入回收站 / 取消选择”。
3. 点击“归档”。
4. 确认账户消息提示归档完成，当前记录数量减少，已归档数量增加。
5. 进入已归档，确认两条记录仍保留缩略图、分析信息和创作方案入口。

### 4.3 恢复与原位置保持

1. 在已归档中选择一条记录，点击“移入回收站”。
2. 进入回收站选择该记录，点击“恢复”。
3. 确认记录返回“已归档”，而不是错误地返回当前记录。
4. 对一条原本位于当前记录的记录重复上述操作，确认恢复后返回当前记录。

### 4.4 回收站与永久删除

> 永久删除不可恢复，请只使用专门创建的测试记录验收。

1. 将一条测试记录移入回收站。
2. 在回收站选择它并点击“永久删除”。
3. 取消确认一次，确认记录未发生变化。
4. 再次点击并确认删除，确认记录从回收站消失且数量减少。
5. 如果该记录引用了资产库共享资产，进入资产库确认共享资产仍存在。

### 4.5 响应式与可用性

1. 桌面宽度约 1426px：确认全部列可见，底部批量栏居中且不遮挡关键操作。
2. 平板宽度 768px：确认生命周期切换栏进入正文，来源与更新时间列按规则隐藏，页面无横向溢出。
3. 手机宽度 390px：确认筛选器单列、列表保留缩略图／名称／操作，底部批量栏完整位于视口内。
4. 使用键盘 Tab 检查搜索、筛选、复选框、更多菜单和分页均有可见焦点。

## 5. 自动化与实机结果

- Web 单元测试：57 / 57 通过。
- Web 生产构建：通过；仅保留既有的 Vite 大包体积提示。
- Chrome 重复进入页面采样：表格全程保留，加载面板数量为 0；4 张已加载缩略图全部保持 `loaded`，骨架透明度为 0，应用错误日志为 0。
- 记录生命周期 API 定向测试此前已通过，覆盖三类列表数量、批量迁移、恢复原归档位置、仅允许从回收站永久删除以及保留共享视频对象。
- 2026-08-11 已使用根目录 Python 3.11 虚拟环境补跑 API 全量回归；连同 Batch 4.8.1 新增用例共 188 项通过，Ruff 全量通过。此前“找不到 Python”来自受限执行上下文无法访问用户目录中的基础解释器，虚拟环境本身无需重建。
- Chrome 实机只执行了只读切换和复选框选择，没有对用户现有记录执行永久删除。

## 6. 验收结论

分析记录三生命周期、高密度方案 B、分页、单条操作和批量操作已经具备人工验收条件。永久删除的真实浏览器验收必须使用专门测试记录；API 全量回归已经补跑通过。
