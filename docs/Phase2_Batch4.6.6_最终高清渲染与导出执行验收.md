## 2. 冻结版本与并发规则

每次导出请求都必须携带 `expected_revision_id`。服务端只读取这个已保存、不可变的时间线版本，不读取尚未保存的页面草稿。

- 时间线版本不一致时返回 `409`，避免错用过期剪辑参数；
- 同一时间线、清晰度、字幕模式和质量组成稳定的请求指纹；
- 相同指纹仍有排队或运行任务时直接复用，不重复启动 FFmpeg；
- 修改时间线后可以创建新导出；旧版本成片与清单仍保留；
- 最终校验通过后才把方案推进到 `export`，失败或取消不会伪装成已交付。

## 3. 输出规格

### 3.1 清晰度

- `720p`：按画幅比例把短边设为 720 像素；
- `1080p`：按画幅比例把短边设为 1080 像素；
- `project`：保持方案时间线中的原始输出尺寸；
- 所有尺寸自动取偶数，横版、竖版、方形画幅均不裁切内容。

例如，9:16 竖版输出分别为 720 × 1280、1080 × 1920；16:9 横版分别为 1280 × 720、1920 × 1080。

### 3.2 字幕

- `burned`：把字幕烧录进画面，适合直接发布到抖音、小红书等平台；
- `embedded`：保留 MP4 内嵌字幕轨，并同时归档独立 WebVTT；
- `none`：输出无字幕的清洁版画面。

### 3.3 编码质量

- `standard`：偏向较小文件；
- `high`：偏向最终交付质量，也是 UI 默认值；
- 成片统一为 MP4、H.264 视频和 AAC 音频，并启用 `faststart`。

## 4. 工作区产物

每次导出使用独立目录，旧产物不会被覆盖：

```text
records/<record_id>/productions/<project_id>/
├─ timelines/
│  ├─ timeline.json
│  └─ revisions/<revision>.json
└─ exports/
   ├─ jobs/<export_job_id>.json
   └─ <export_job_id>/
      ├─ final.mp4
      ├─ subtitles.vtt       # 字幕模式需要时存在
      ├─ cover.jpg
      ├─ manifest.json
      └─ intermediate/
```

`manifest.json` 使用 `viral-dna-final-export/v1`，记录项目、分析记录、时间线版本、导出设置、产物相对路径和完整校验摘要。工作区只保存相对路径，下载接口负责解析受控文件，避免前端直接读取任意本地路径。

## 5. 校验门禁

FFmpeg 完成后，服务端使用 ffprobe 和文件哈希执行最终门禁：

- 成片文件存在且大小大于 0；
- 实际时长与冻结时间线时长在允许误差内；
- 输出宽高与请求规格一致；
- 视频编码为 H.264；
- 预期有音轨时存在 AAC 音轨；
- 内嵌字幕模式存在字幕轨，烧录模式不要求独立播放器字幕轨；
- 保存帧率、文件大小和 SHA-256。

只有 `validation_summary.valid=true` 才会生成完成态和交付清单。校验错误保存在任务中并通过消息中心提示，便于修复后重新导出。

## 6. API

### 6.1 任务

- `POST /api/v1/productions/{project_id}/timeline/final-renders`
- `GET /api/v1/productions/{project_id}/timeline/final-renders`
- `GET /api/v1/productions/{project_id}/export-jobs/{job_id}`
- `POST /api/v1/productions/{project_id}/export-jobs/{job_id}/cancel`

创建请求示例：

```json
{
  "expected_revision_id": "<timeline_revision_id>",
  "resolution": "1080p",
  "subtitle_mode": "burned",
  "quality": "high"
}
```

### 6.2 产物

- `GET /api/v1/productions/{project_id}/export-jobs/{job_id}/content`：浏览器内播放；
- `GET /api/v1/productions/{project_id}/export-jobs/{job_id}/download`：下载 MP4；
- `GET /api/v1/productions/{project_id}/export-jobs/{job_id}/subtitles`：读取 WebVTT；
- `GET /api/v1/productions/{project_id}/export-jobs/{job_id}/cover`：读取封面；
- `GET /api/v1/productions/{project_id}/export-jobs/{job_id}/manifest`：下载交付清单。

任务状态沿用 `viral-dna-render-job/v1`，并通过 `kind=final` 与低清预览任务物理区分。状态包括 `queued`、`running`、`succeeded`、`failed` 和 `cancelled`。

## 7. UI 设计

“导出成片”是创作方案工作流的最后一步，页面采用双栏布局：

- 左侧选择清晰度、字幕模式和编码质量，并即时显示输出尺寸、格式和字幕摘要；
- 默认选择 1080P、烧录字幕和高质量；
- 右侧显示最新高清成片，播放器保留原生播放控件并使用 `object-fit: contain`；
- 最新成片右上角提供下载，播放器下方显示尺寸、编码和校验结果；
- 导出期间只在工具栏显示紧凑进度和取消按钮；
- 完成、失败和取消通过账户消息中心通知，不额外占用主页面空间；
- 页面底部保留所有导出历史，可分别下载成片或 `manifest.json`；
- 1080px 以下改为单栏，窄屏下设置项与操作按钮继续自适应。

## 9. 人工验收流程

1. 双击 `scripts/start.bat`，打开一条已经完成“剪辑合成”的创作方案。
2. 点击步骤条“导出成片”，确认顶部显示的冻结时间线版本、画幅和时长正确。
3. 依次选择 720P、1080P 和方案尺寸，确认竖版、横版或方形方案的输出宽高始终按比例变化且为偶数。
4. 切换烧录字幕、内嵌字幕和无字幕；切换标准、高质量，确认摘要同步更新。
5. 为节省首次验收时间，可先选择“720P + 标准 + 烧录字幕”，点击“开始高清导出”。
6. 确认页面显示紧凑进度和“取消”；右上角消息中心出现排队／运行通知。
7. 导出完成后，确认消息中心出现成功通知，最新成片可以播放、暂停、拖动进度，画面完整且未被裁切。
8. 点击最新成片下载按钮，确认获得 `final.mp4`；点击历史中的“清单”，确认获得 `manifest.json`。
9. 打开清单，核对 `timeline_revision_id`、清晰度、字幕模式、宽高、时长、文件大小和 64 位 SHA-256。
10. 使用另一组清晰度或字幕设置再次导出，确认历史中同时保留两条任务，旧成片仍可下载。
11. 再启动一次导出并立即取消，确认任务变为“已取消”，消息中心有取消记录，既有成功成片不受影响。
12. 返回剪辑合成，修改并保存时间线，再进入导出；确认顶部版本号递增，新任务绑定新版本，而旧版本成片和清单仍保留。

验收通过标准：步骤 1～12 均符合预期；任何失败任务都必须显示明确错误，且不得把方案标记为已完成。
