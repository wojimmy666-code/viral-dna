2026-09-06。仅调整 Skill 图片阶段，沿用现有产品的配色、字号、候选和人工采用流程；原视频项目仍保留原有分镜缩略图导航。

## 使用方式

1. 打开 Skill 项目的「分镜图片」。左侧只显示分镜编号、时间和状态，不显示任何缩略图或图片占位框。
2. 点击「一键生成全部分镜图」。系统先保存当前编辑，再显示生成前确认区：冻结的图片模型、尺寸、画面数、每画面候选数、总图片数和预计费用。
3. 点击「确认生成」才提交任务。默认只生成缺少可用候选的有效画面；已采用或已有待采用结果的画面跳过。一个分镜有多个画面时逐个处理，不限制分镜数量。
4. 全部任务复用现有图片生成入口，最多同时执行 3 个画面任务。每个画面仅使用自己的提示词及绑定引用，不把项目的全部素材传给模型。
5. 顶部显示实际完成数、生成中、排队、耗时和心跳；候选持久化后即刷新对应分镜，不等整批结束。左侧始终保持文字列表。生成不等于采用，必须人工确认图片后进入视频阶段。
6. 「重新生成全部」单独确认；保留历史候选和已经采用的图片，新结果不会自动替换采用结果。

## 停止、断线与重启

- 「停止排队」只停止尚未提交的画面，已提交上游的任务继续收尾，避免丢失已计费结果。
- 关闭页面、切换页面或刷新不会取消后台任务；再次进入会读取持久化批次状态。
- 服务重启后显示中断状态，点击「继续未完成任务」核对现有任务并恢复。已完成任务不重新提交。
- 超时、服务中断及其他结果不明的远程任务标为「需核对」，不会自动发起第二次付费请求。下载失败也不等同于上游未生成。
- 若上游结果未知，需先核对服务商任务或恢复已有产物；当前没有通用的服务商历史任务查询 API，不能承诺自动取回所有未知远程结果。
- 用户在排队期间修改提示词、画面或引用，原排队项会提示输入变化；检查后恢复。请求已发出后再编辑，新候选仍保留，但不会覆盖新的提示词或已采用图片。
- 移入回收站前停止批次与子任务，永久删除项目时清理其批次记录。

## 性能实测

本地 Vite + API，项目 `298db928-ddc7-489a-8889-e66ca00326a4`，11 个分镜；非严格基准，首次加载受开发环境与缓存影响。

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| 左侧分镜接口响应体 | 134,054 字节，含完整提示词/预览 | 5,624 字节，导航摘要，减少约 96% |
| 初始 API 请求 | 约 50–52 次 | 35 次 |
| 首次可操作 | 约 4.8 秒 | 约 4.0 秒 |
| 第一次切换分镜 | 分镜详情 + 视频草稿请求 | 仅分镜详情请求，选中态即时反馈 |
| 返回已看过且未修改的分镜 | 重复请求 | 0 次请求，使用当前版本缓存 |

- 图片阶段不预加载视频生成草稿、时间线、导出历史和版本历史。
- 相同并发 GET 合并；不缓存写操作、失败或跨会话数据。
- 数据库按当前项目/分镜筛选，避免跨项目全量反序列化。
- 生成模型调用不再持有项目编辑锁；提交结果时重新读取最新分镜，防止并发覆盖。
- 生成心跳局部更新，左侧文字列表独立 memo；候选变化时刷新导航与对应详情。

- 1440px 浏览器实测：初始 API 无失败；图片阶段无无关阶段请求；看过的分镜再次切换无请求。
- 1920、1440、1280、1024、768、390px 均无页面横向溢出；桌面左侧 232px，较窄桌面 220px，移动端单列。
- 浏览器模拟生成：整批未完成时已显示第 1 个画面图片，顶部显示 `完成 1/11`、进度、心跳；左侧没有图片。停止后刷新仍可继续未完成任务。
- 验证仅使用本地模拟模型及浏览器响应夹具，没有提交真实付费生成，没有修改用户项目的提示词、候选或采用状态。
