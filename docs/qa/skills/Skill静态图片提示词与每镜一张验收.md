# Skill 静态图片提示词与每镜一张验收

> 验收记录：正文中的测试结果和界面描述对应当时批次，不表示本轮重新完成全部人工验收。当前流程及已替代规则见 [现行功能说明](../../features/README.md)。

## 调整范围

- 图片候选选择不再弹出“候选已选择，请继续人工确认”。选中样式、数据刷新、人工采用和失败提示保留；选择不等于批准。
- 图片提示词去除“连续性锁定”“主体一致性”段落，以及全片风格、禁用内容和其他图片约束中的运镜、跨帧、时序要求。保留主体、场景、构图、焦段、静态机位、景深、光线、材质与参考产品准确性；视频提示词不改动。
- 共用静态投影同时用于新分镜编译、旧项目读取、编辑正文、复制所用数据、生产图片视图和实际生成网关，覆盖远程模型与本机 ImageGen。旧快照、内容哈希与历史候选不重写。
- 新手动批量每个有效分镜只生成 1 张；多画面分镜选择按 index 排序的第一画面，其他画面保留并允许独立生成。不继承项目默认候选数或单镜候选数，费用按实际一张计算。
- 单镜独立生成仍可一次多张，Look Test 候选数量不受本次批量规则影响。
- 恢复旧批次保持原模型、尺寸、数量和画面集合，不改写已提交任务。自动补缺仍覆盖必需画面，每画面一张，避免多画面分镜无法完成。

## 人工验收

1. 刷新已有 Skill 项目的分镜图片页：编辑器和复制内容不出现上述两个段落；静态摄影描述仍保留，视频提示词保持原内容。
2. 选择某张候选：选中状态变化，无该条 Toast；只有人工采用后才更新批准状态。
3. 将项目或单镜候选数设置为多张，点击“一键生成全部分镜图”：摘要为“每镜 1 张”，N 个有效分镜对应 N 张；任务实际 candidate_count 为 1。
4. 多画面分镜参与批量时只生成主画面；独立进入该分镜可给其他画面生成，也可一次生成多张。
5. 再次主动批量生成仍产生新候选，历史和已采用图片保留。恢复旧批次时仍沿用旧任务的冻结参数与待完成画面。

## 已执行验证（2026-09-06）

- 97 项后端相关回归通过，包含静态投影、旧数据只读与重复读取稳定性、视频提示词不变、批量默认多张覆盖、主画面排序、旧多图批次恢复、远程／本机单镜多图、Look Test、生产快照及网关。
- 前端主测试 270 项通过，前置测试通过；实际事件处理函数验证候选选择无 Toast／无自动批准，批量请求覆盖默认数量并在网络重试时保持幂等。
- Ruff、git diff --check 和前端生产构建通过；构建仍有既有大包体积提示。
- 本机服务重载前确认没有运行中的分析、生成、批量或 Look Test 任务；两个已有不可变 ProductionSeed 校验通过，没有迁移或改写。
- 浏览器连接不可用后使用独立隐藏测试窗口，检查现有 15 镜头项目的 1600px 与 390px 视口：每镜 1 张／共 15 张，实际图片编辑器已清理，无横向溢出或脚本异常。所有业务写请求被拦截，没有创建项目、改变采用状态或触发真实图片／视频生成。

本规则取代之前批量文档中“每个画面按默认候选数生成”的描述；原有模型选择、分辨率、预算和人工审核要求继续有效。
