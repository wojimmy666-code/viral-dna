# 平台链接读取与分析超时

## 处理规则

- 抖音收藏页 `user/self?modal_id=...` 已按视频编号转成 `/video/...`，不依赖收藏页本身可公开访问。
- `link_auth_required` 表示平台要求登录或人机验证，不是链接格式错误。更新「平台连接」中的登录状态后手动重试；仍受平台限制时可上传有权使用的视频文件。
- 新版仅在明确登录、验证码或 HTTP 401 时使用 `link_auth_required`；HTTP 403 为 `link_access_denied`，429 为 `link_rate_limited`，平台 5xx 为 `link_platform_unavailable`。采集器笼统的 `Fresh cookies` 错误不能证明登录过期：优先保留实际传输原因，没有具体原因则使用 `link_metadata_unavailable`。
- `VIRAL_DNA_LINK_TIMEOUT_SECONDS` 默认 `120`：包含登录凭据准备、匿名读取、需要登录后的重试、下载及元数据处理，不在每次重试时重新计时。
- `VIRAL_DNA_ANALYSIS_TIMEOUT_SECONDS` 默认 `900`：整个真实分析的自动执行上限，包含读取来源和全部分析阶段；本机浏览器的人工等待单独限时，不消耗自动执行额度。配置为正的有限秒数，无效值回退默认值。写入开发环境 `.env.local` 或部署 `api.env` 后重启 API 生效。
- 超时持久化 `failed`、具体错误码及结束时间。保留原视频、历史报告，不自动再次提交任务或切换模型。新版本的超时规则不追溯接管旧进程中已启动的任务。

## 取消边界

链接读取使用独立 Python/yt-dlp 子进程；超时或取消时按该子进程 PID 终止进程树，等待退出后才清理登录临时文件。不会结束其他项目或浏览器进程。未成功读取时不进入模型分析。

整个分析超时会取消本地编排及等待中的请求，不继续写入成功报告。FFmpeg 处理沿用已有取消清理；已提交给远程模型的计算和计费不保证被供应商取消，本地同步识别库中的线程也可能继续完成当前计算，但不再推进该分析。

## 前端状态

当前项目按分析 ID 恢复订阅，切换项目或卸载时解除订阅并忽略旧响应。SSE 与每 2 秒的串行状态查询互为补充；单次查询 10 秒未返回则取消并显示连接异常，继续尝试恢复。不会因超过旧版 60 次查询上限而放弃跟踪。

后端失败显示「分析未完成 / 已停止」及原因，允许手动重新分析；登录问题额外提供平台配置入口。前端断网不等同于后台取消，不将网络失败伪造为任务失败。

## 平台连接与一链接流程

- 导入后显示「已导入 · 未验证」，本机检查只更新 Cookie 数量和 `last_checked_at`，保留上次网络成功/失败。`last_tested_at` 记录真实网络测试，`last_success_at` 记录成功读取；旧 `last_validated_at` 兼容保留但不再作为本机卡片的网络验证依据。
- 卡片的「测试视频链接」默认折叠，使用与下载相同的独立采集进程、凭据策略、代理和抖音兼容读取；只读取元数据，不下载、不调用模型。自动执行最多 45 秒，且不超过链接总时限；本机专用浏览器的人工等待独立限时。连接在测试中被更新或断开时，旧测试结果不得覆盖新配置。
- 主流程仍为粘贴链接、确认已有分析参数及使用权限、一次提交，之后自动下载 → 媒体预处理 → 分镜与模型分析 → 报告。测试链接不是前置门禁，不自动选择其他模型或突破成本上限。
- 抖音 web-detail 失败时，补充一次正常公开分享页读取；仅接受页内 JSON 明确返回的当前视频 ID，不执行脚本、不使用第三方解析服务、不生成验证签名或解决验证码。分享页没有返回视频地址则保留具体失败，不能把页面 HTTP 200 当作视频可读取。
- 此类 Cookie 兼容问题也见于 [yt-dlp 上游问题记录](https://github.com/yt-dlp/yt-dlp/issues/9667)。不能假定升级采集器或重导 Cookie 就能解除访问限制。

## 第一阶段：本机抖音专用浏览器

### 范围与使用

- 新建项目只提交一个链接，先走常规采集；抖音遇到访问受限、明确登录要求、无媒体信息或读取超时后，自动切换专用浏览器，下载成功后进入原有分析流水线。不自动重提收费任务、不改变用户选择的分析模式或模型。
- 本机「平台连接 → 抖音 → 专用采集浏览器」可主动连接。普通下载被拒绝不等于人工验证；只有专用页面实际显示登录或验证要求，才提示在该窗口操作。完成后继续同一分析 ID，不要求重新建项目；平台持续拒绝则停止报错。
- 使用已安装的 Edge（优先）或 Chrome、独立持久化配置，不读取/接管日常浏览器配置目录。已导入 Cookie 只作为初始登录信息；忽略过期或不兼容条目，不因单个条目失败而阻止打开浏览器。旧导出文件不会反复覆盖专用窗口中新完成的登录。
- 登录操作完成只表示交互结束，不显示“视频验证成功”；可用性以实际目标视频读取为准。只接受页面返回的目标视频 ID 和受支持媒体域名，不抓推荐视频替代，不生成验证签名、不自动解验证码、不使用第三方解析服务。

### 配置与边界

- `scripts/start.bat` 的本机桌面启动默认启用 `VIRAL_DNA_BROWSER_ASSIST_ENABLED=1`，可在 `.env.local` 显式设为 `0`；启动器补齐 `services/api[browser-assist]` 可选依赖。直接启动 API 则需要显式启用。生产环境默认关闭。
- 只有 Windows 交互桌面、回环地址访问、无代理转发请求头、已安装浏览器及 Playwright 时开放；Windows 服务 Session 0、远程地址和 IIS 转发请求不会弹出浏览器。控制接口还检查当前账户/用户/设备所有权，其他用户不能控制或看到任务。
- 常规下载尝试最多 30 秒，然后共享剩余的 `VIRAL_DNA_LINK_TIMEOUT_SECONDS`（默认 120 秒）；人工等待使用 `VIRAL_DNA_BROWSER_HUMAN_TIMEOUT_SECONDS`（默认 300 秒），不占链接与分析自动执行额度。子进程另有总时限兜底，浏览器挂起也不会无限等待。
- 单用户同设备同时只占用一个专用配置，包括取消后尚在回收的进程。取消、超时或关闭窗口会停止采集；只回收本项目拥有的子进程树。API 重启后的旧未完成分析标记为中断，可手动重试。
- 浏览器配置默认位于本机 ViralDNA 配置目录下的 `browser-assist/<account>/<user>/<device>/douyin`，可通过 `VIRAL_DNA_BROWSER_ASSIST_ROOT` 更改。不属于资产库，不参与资产同步、迁移或账户存储额度；Cookie 值、签名媒体 URL 不写入公开状态、日志或报告。
- 第二阶段云端/本机助手桥接不在本次范围内，正式服务器行为不变。
