# 复刻与改进：两阶段创意验收

日期：2026-09-19。范围：本项目本机代码、隔离数据和模拟模型；未执行真实付费创意生成，未推送或部署正式服务器。

## 用户流程

1. 打开分析报告的“复刻与改进”，选择品类档案，可补充想法。
2. 点击“生成 3 个简短创意”。默认展示片名、简述、记忆画面；展开查看关键场景、品类适配与借鉴/改变。
3. 可以“只换这一条”，另两条内容和 ID 不变；“换一批创意”保留旧批次。
4. 必须显式选择一个方向，才可“展开这个创意”。补充想法同时用于重写和展开。
5. 检查完整方案、所需资产、风险以及逐镜图片/视频提示词，点击“确认分镜，进入制作”。随后沿用现有制作界面编辑分镜与提示词。确认前后均不会自动触发生图/生视频。

## 模型和数据规则

- 使用当前文案模型配置中 `replication_plan` 对应的路由；明确的可重试供应商错误遵循后台允许的回退开关。结果格式校验失败、请求超时或连接异常即停止，不因切换模型追加付费调用；超时/连接中断无法确认上游是否已经执行。请求冻结目标模型，并记录实际解析模型。
- 输入包含品类完整快照，尤其 `display_name`、`brief`、全部卖点、品牌、人群及禁用表述；纳入原报告的 `viral_reasoning.narrative_structure`（缺失时用 overview）及视觉机制。
- 原始补充要求随快照保留。创意首先迁移表达方式，不把“JK”降为“女装”，不以第一个卖点替代创作。
- 三方向由模型动态创作，不硬编码三种模式或示例片名。允许共同使用非线性蒙太奇；模型进行语义维度自查，本地检查明显重复。自查不等于客观创意评分，真实创意质量仍需用户验收。
- 文本分析调用默认温度仍为 0.1；仅短创意请求使用 0.85，展开使用 0.65。
- 新方案镜头数量、播放顺序、标题、时长与提示词从新镜头列表构建，不回填原片分镜。来源镜头 ID 只是可选参考，不自动引入原片画面、时间段、原音或字幕。初始 Seed、版本快照保留创意方案；恢复缺失分镜时仍从该 Seed 恢复。
- 旧 v1–v3 批次保留可读，新 v4 使用现有账户级 `viral_concept_sets` 表，不迁移或覆盖用户原有方案。后续品类修改不改变已生成内容。

## 任务与异常

- 生成、单条重写、展开是显式 POST；GET 读取报告、任务或历史不会触发模型。旧版 GET 隐式补充模型分析已移除，分析模型仍由显式分析流程运行。
- 任务先持久化再异步执行，客户端按任务查询；同分析同时仅一项创意任务。相同请求 ID 返回原任务，不重复调用模型；不同内容复用同 ID 返回冲突。
- 整个模型任务最长 240 秒。创意及其中文校正请求单独采用连接 10 秒、读取 180 秒、写入 30 秒、连接池 10 秒的 HTTP 等待策略；各阶段等待限制不等于任务总时长。普通分析和凭据检查仍沿用原模型超时配置，不修改共享 Provider。失败/取消/重启中断均进入终态，保留原结果，不自动重试、不返回规则模板。
- 停止只保证取消本机等待；无法保证上游请求撤销或免计费。费用未回报明确显示“不代表免费”。记录排队、模型、总耗时与停止时间，费用按供应商 usage 和冻结价格记录，并汇入模型账本及分析累计费用。
- 发布重复请求复用已创建方案，路由沿用账户隔离与项目编辑租约；编辑/生成入口不会扩大项目权限。

### 既有边界

- 自动化验收不调用真实付费模型，不能把示意创意当作模型实际效果，也不承诺每次创意都符合审美偏好。

## 补充想法逐条落实修复（2026-09-20）

用户案例：“多场景切换，并且都是全世界标志性的场景”。只读核对确认原话已进入请求，重建提示词的指纹与账本一致；实际返回的普通地铁、街道等场景未体现世界地标。原因不是输入丢失，而是要求的优先级和逐结果核对不足。

- 当前补充想法成为所有**新生成**创意的共同要求，优先于原片画面、品类默认场景与已有创意的冲突细节，但不覆盖真实产品事实、禁用表述或输出/安全规则。不内置 JK、地标或固定三方向模板。
- 新快照增加 `creative_brief`：保留完整原文，并将原文片段编号以供核对。片段仍需连同完整上下文理解；超过 24 个片段时合并相邻片段，不截断或丢弃要求。提示词版本为 `creative-ideas-v3` / `creative-expanded-v3`，内容契约为 `creative-content-v3`。
- 同一次模型回答中，每条新创意/完整方案都返回 `brief_checks`，包含要求编号、落实说明、适用场景范围和关键画面/分镜原文依据。程序检查每项要求是否有记录、是否声明满足、引文是否真实存在于对应场景，以及声明适用全部场景时是否逐场景覆盖。要求原文由服务端写回，不能由模型换成更容易满足的条件。
- 缺失记录、未满足、引文不在正文或全场景覆盖不完整时，任务以 `creative_brief_unmet` 结束，不把这批内容作为成功结果，不自动重试、不调用额外的要求提取或评审模型；原批次和计费/耗时保留。有效结构化返回仍保存在当前账户的模型账本中，便于排查。
- 换一批、单条重写、展开均使用当前输入框的完整要求。刷新/选择历史会回填对应批次的要求；未发送的手动编辑不会被轮询覆盖。API 省略或传 `null` 表示继承，显式空字符串表示清空；非空新文本是完整替换，不自动拼回已删除条件。
- 单条重写只检查新生成的这一条，另外两条的 ID、内容、原落实说明均不改写，也不冒充已符合修改后的新要求。要让三条都遵循新要求，应使用“换一批创意”。展开可调整所选旧创意中与当前要求冲突的细节。人工编辑完整方案后清除旧模型落实说明，避免沿用未经复核的结论。
- 按用户要求删除页首创作说明、品类快照说明和“旧批次不会被覆盖”说明，不留占位。按 impeccable 的信息精简原则，新落实说明只出现在已有折叠详情或完整方案的折叠区，默认不展开；历史和快照机制保留。
