# 登录续期与原地恢复验收

实施日期：2026-09-20。业务规则见 [独立账户与企业协作](../../features/accounts/account-system-implementation.md)。

## 项目入口与编辑权获取顺序修复（2026-09-22）

- 用户反馈重启后点击项目停留在列表并提示“当前项目为只读，请先取得编辑权”。代码与真实入口函数的隔离测试确认：原入口先调用受编辑权保护的 `/records/:id`，成功后才跳转；而 `AccountRoot` 只有在项目路由才申请租约，形成首次进入的先后顺序错误，并非这条报错本身能证明数据损坏或 Cookie 失效。
- 入口改为保存检查 → 路由跳转 → 原账户壳层取得编辑权 → 挂载工作台并读取详情。方案数量和通知入口携带按项目绑定的路由状态，在重新挂载及详情初始化后恢复方案／分镜／候选目标；保存失败留在原页，迟到跳转不覆盖新导航。未修改后端权限、租约期限、数据库或真实项目锁，其他成员占用仍使用只读快照。
- `app-routing.test.mjs` 执行真实 App 事件函数：冷启动入口修复前失败、修复后通过，并覆盖 Skill／不在当前列表中的项目、保存失败、过期导航、方案入口、通知及详情初始化后的目标保留。完整前端回归与生产构建通过，保留既有大 chunk 提醒。
- 新增 `project-entry-browser.test.mjs`，组合真实入口函数与 `AccountRoot`，在隔离浏览器和模拟 API 中验证等待租约期间零详情请求、授权后读取、直接刷新、方案与通知跨重新挂载恢复、占用只读、释放占用后显式进入编辑。全程无提前读取受保护详情，无真实账号、模型调用或业务数据写入。复现：`node --experimental-websocket --test apps/web/tests/project-entry-browser.test.mjs`。

## 范围与边界

- 个人和企业成员使用 12 小时滑动窗口、7 天最长会话；admin 使用 2 小时滑动窗口、24 小时最长会话。
- 续期复用当前登录令牌，每 5 分钟最多延长一次，Cookie 同步更新，不创建新用户或新会话。登录身份变化、退出、改密、停用仍独立生效。
- 只接受当前窗口的真实输入、点击、滚动与拖拽活动；后台请求、编辑锁和模拟 DOM 事件不续期。标签页广播不包含凭据或内容，并通过服务器核实；Web Locks 不可用时仍有服务器节流。
- 网络失败保留内容并退避重试状态检查；真实登录失效暂停业务请求。重新登录在原页完成，后端要求原用户 ID；成功后重新申请编辑锁，冲突只读，不自动重放生成、保存或消费请求。
- 草稿保护是当前页面内存保护，不是跨刷新持久化；退出/刷新前仍可复制或下载已挂载提示词。
- 使用原认证表结构，不迁移真实账户数据；本轮自动化测试使用临时数据库、虚拟时钟和临时浏览器，不调用真实模型。

## 自动化覆盖

后端 `test_account_session_lifetime.py` 覆盖双会话的滑动/最长期限、只读不续期、已过期/注销/改密/停用拒绝复活、并发续期、编辑锁最长时限、Cookie 标志、来源/CSRF/跨标签页身份校验和原用户重新登录。原账户仓库、输入规则与租户隔离测试共同回归。

前端 `session-activity.test.mjs`、`account-client.test.mjs` 覆盖持续输入、拖拽/滚动、闲置/后台/伪事件、前后端独立、断网退避、唤醒过期、跨标签页核验、撤销与迟到响应、监听清理、暂停期间业务请求拦截。

`account-browser.test.mjs` 在隔离 Chromium 中检查 1280px/390px 原地登录、错误密码/错误用户、键盘关闭与焦点、等待验证期间不卸载编辑器、保留同一个输入 DOM 及文本、占用冲突保持只读、重新取得编辑权后继续编辑、不重放失败的业务请求；同场回归既有登录、账户管理、顶栏和存储页面。

## 升级后人工检查

1. 旧页面先保存或复制未提交内容，再刷新加载新版本；已失效的登录重新登录一次。
2. 持续编辑时在网络面板观察 `/auth/refresh`：约每 5 分钟一次，Cookie 与返回的到期时间同时更新。
3. 页面后台闲置、只轮询生成进度不应持续发送续期；返回前台先检查登录状态。
4. 超时后原页点击「重新登录」，验证失败、关闭窗口不丢内容；成功且项目空闲后才能继续提交。
5. 另一成员占用项目时，保留原文本并提示占用，不能强行覆盖；原版本冲突检查继续生效。

## 重启／刷新后项目只读恢复（2026-09-23）

- 确认问题：原编辑锁已经过期，页面仍显示首次申请时的持有人；只读快照虽每 10 秒刷新内容，却没有重新查询或申请编辑权。刷新时新文档申请早于旧文档释放也会进入此状态。
- 前台只读页每 5 秒查询一次 `/projects/:id/edit-lease`，聚焦、回到前台、网络恢复和页面恢复时立即检查；服务器确认空闲后才调用普通 `acquire`，写入前仍需有效编辑令牌。
- 不删除数据库锁，不按用户名放行，不抢占有效编辑者，不延长登录期限。隐藏标签页不会自动申请；未提交草稿的失效编辑器保留手动恢复流程。
- 重试保留只读快照，按钮防重复提交。异常响应、超时和断网均保留只读并重试；过期异步响应、跨项目与跨会话恢复无效。
- 验收：`tests/project-lease-recovery.test.mjs` 覆盖 9 类边界；`tests/project-entry-browser.test.mjs` 使用开发版 React StrictMode，复现旧文档延迟释放、其他编辑者占用和自动恢复，保留方案／分镜通知目标，确认取得租约前不读取编辑接口。所有浏览器数据与 API 均为隔离模拟，无真实账号或模型调用。
- 本轮结果：完整前端回归、14 项设计检查、文档检查和生产构建通过；账户浏览器 20 项与项目入口浏览器 1 项通过；账户仓库／会话寿命／HTTP 隔离后端 32 项通过。保留既有大 chunk 提醒。本轮真实浏览器插件连接不可用，改用隔离 Chromium 验收；本地 Vite 已返回新增恢复模块，未操作用户标签页、真实租约或后端进程。
