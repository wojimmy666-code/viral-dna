# Phase 2 后续方向：多图参考转场与跨镜头连续性

更新时间：2026-08-10

文档状态：分镜内多画面与有序多图视频基础已经实施；跨分镜桥接转场仍作为候选 Batch 4.9，具体模型和交付时间待后续确认

## 0. 已实施基础与剩余边界

2026-08-10 已先落地“一个分镜内部包含多个画面”的基础能力：

- 一个 `ShotPlan` 仍对应一段不超过模型上限的独立生成视频。
- `ShotPlan.visual_beats` 保存图1、图2……的稳定顺序、时间比例、图片提示词、独立候选与采用状态，以及到下一画面的转场语义。
- 每个画面可以从源视频重新选帧，也可以独立进行文生图或图片编辑；所有必需画面确认后，才可进入该分镜的视频生成。
- 视频 Gateway 接收不可变的 `OrderedReferenceFrame[]`，保存每张图的候选 ID、文件哈希、时间比例和转场参数，并把图号编译进提示词。
- 当前只开放明确声明“多图参考＋有序引用”的模型；不支持任意有序多图的模型直接禁用，禁止静默退回单图模式。
- 首个开放实现为百炼 `wan2.7-r2v-2026-06-12`。官方文档声明最多 5 个图／视频混合参考、纯图片参考时输出 2～15 秒整数、720P／1080P；当前系统只提交图片参考。
- 历史提示词中出现“第一部分／第二部分”等明确多场景结构时，首次打开方案会自动迁移为多个画面；历史图保留在图1并要求复核。

本次没有实现相邻两个独立分镜之间的桥接节点、连续性协议、中间过渡帧和桥接视频。下文 Batch 4.9 仍专门描述这一跨分镜层，不与已经实现的分镜内画面轨道混为一谈。

官方能力依据：

- [万相 2.7 参考生视频 API](https://help.aliyun.com/zh/model-studio/wan-video-to-video-api-reference)
- [wan2.7-r2v 模型能力与价格](https://help.aliyun.com/zh/model-studio/wan2-7-r2v)

## 1. 背景与结论

当前每个分镜已经可以用多张有序画面图生成一段视频，但相邻两个独立分镜仍由各自的参考图和提示词分别生成。即使相邻提示词描述相似，模型仍可能在跨分镜边界产生人物身份漂移、动作重新开始、人物位置跳变、服装或道具变化、镜头轴线反转等问题。

后续不再把转场仅作为时间线中的叠化参数，也不依赖两个独立提示词碰巧生成一致边界。系统应把转场升级为连接两个分镜的第一类生产节点，并采用以下策略：

1. **多图／视频参考生成桥接片段作为主策略**：同时把转场前状态、转场后目标、原视频转场运动和固定资产交给模型。
2. **先生成中间关键帧、再生成桥接视频作为推荐执行路径**：先用低成本图片确认人物、动作和空间连续性，再调用视频模型。
3. **上一段尾帧接力作为兼容策略**：模型只支持首帧生视频时，把已确认尾帧作为下一段首帧。
4. **纯独立提示词仅作为最后降级方案**：必须明确显示连续性保障较低，不能静默降级。

该方向不替换现有分镜视频生成，而是在相邻已确认分镜之间增加可审核、可重试、可回退的桥接层。

## 2. 目标与非目标

### 2.1 目标

- 同时约束转场前后的主体身份、服装、道具、动作阶段、画面位置、运动方向和镜头关系。
- 复用原视频转场片段或采样帧作为运动、节奏和遮挡方式参考。
- 支持人物、产品、服装、场景和风格资产的明确角色绑定。
- 为一个转场保存多个中间帧和视频候选，允许人工切换、采用、取消采用和保留历史。
- 上游分镜变化时只使相关转场过期，不删除已付费生成的候选。
- 根据不同模型能力自动选择生成策略，并记录模型、输入快照、费用和降级原因。
- 将已确认桥接片段写入受控时间线，继续复用现有预览、最终渲染、账户通知和导出能力。

### 2.2 非目标

- 不在本批重新生成对白、声音克隆或口型同步。
- 不承诺任意模型都能精确复现原转场；能力不足时必须阻止调用或显示降级策略。
- 不把产品扩展成完整专业剪辑器。
- 不在方案阶段预先绑定某一家厂商或尚未验证的模型 ID。

## 3. 总体工作流

```text
分镜 A 已确认视频／尾部多帧 ─┐
分镜 B 已确认目标首帧       ─┤
原视频转场片段／采样帧      ─┼→ 转场参考包
人物、产品、服装和场景资产  ─┤       ↓
连续性协议                  ─┘  中间关键帧候选
                                   ↓ 人工确认
                              桥接视频候选
                                   ↓ 人工确认
                              写入受控时间线
```

推荐执行顺序：

1. 从原视频分析结果和相邻分镜边界创建转场节点。
2. 提取分镜 A 尾部连续帧、原转场样本和分镜 B 目标首帧。
3. VLM 生成结构化连续性协议，不直接依赖一段不可解析的自然语言。
4. 用户确认或锁定人物、动作、位置、镜头和视觉约束。
5. 先生成一至三张中间过渡关键帧。
6. 用户选择中间帧后，再生成 0.5～2 秒桥接视频候选。
7. 自动质检只提供风险提示；用户最终决定采用哪个候选。
8. 已采用桥接片段进入时间线，沿用原音轨或现有音轨策略。

## 4. 角色化转场参考包

参考图不能只按上传顺序传入。每个输入必须保存稳定角色、来源和优先级，Provider Adapter 再把标准角色映射到具体厂商参数。

### 4.1 标准参考角色

| 角色 | 必需 | 用途 |
|---|---:|---|
| `source_tail_frame` | 是 | 分镜 A 已确认的最后清晰画面 |
| `source_tail_sequence` | 推荐 | 分镜 A 尾部二至三帧，用于判断动作方向和速度 |
| `target_head_frame` | 是 | 分镜 B 希望到达的首帧状态 |
| `target_head_sequence` | 可选 | 分镜 B 开头一至二帧，补充目标动作方向 |
| `original_transition_video` | 推荐 | 原视频转场小片段，作为运动和节奏参考 |
| `original_transition_frame` | 可选 | 不支持视频参考时使用的二至四张采样帧 |
| `identity_reference` | 按需 | 人物身份和外貌资产 |
| `product_reference` | 按需 | 产品外观、文字和结构资产 |
| `wardrobe_reference` | 按需 | 服装款式、颜色和材质资产 |
| `scene_reference` | 按需 | 场景布局和环境资产 |
| `style_reference` | 可选 | 色彩、光线和视觉风格参考 |
| `intermediate_keyframe` | 推荐 | 已确认的中间过渡关键帧 |

### 4.2 参考优先级

默认优先级如下：

```text
固定人物／产品身份
> 已确认的转场前后边界帧
> 已确认中间关键帧
> 原视频转场运动参考
> 场景和风格参考
```

每个模型的最大图片数、视频参考数和角色能力必须来自能力目录。超过上限时由系统要求用户精简或明确选择降级方案，禁止 Adapter 静默丢弃参考输入。

## 5. 连续性协议

每个相邻分镜之间保存一个结构化 `ContinuityContract`，至少包含：

### 5.1 主体连续性

- 人物或产品资产 ID。
- 外貌、发型、服装和可见标志。
- 身体朝向、面部朝向和视线方向。
- 动作阶段，例如“右手已抬至肩部，下一步继续向上”。
- 手持物、接触关系和左右手约束。

### 5.2 空间连续性

- 主体在画面中的归一化边界框和中心位置。
- 主体面积比例和景别。
- 前景、主体和背景层级。
- 人物、产品和道具之间的相对位置。
- 进入、离开和持续运动方向。

### 5.3 镜头连续性

- 机位高度、拍摄方向、焦段和景深。
- 固定、平移、推拉、环绕、甩镜等运动方式。
- 镜头轴线和屏幕方向。
- 转场前后的目标构图。

### 5.4 视觉连续性

- 时间、天气、主光方向和色温。
- 曝光、对比度、主色调和背景关系。
- 允许变化与禁止变化的项目。

连续性协议由 VLM 根据原视频证据生成，用户可以锁定关键字段。生成请求必须保存当时的协议快照，后续修改不能改变历史任务的输入含义。

## 6. 生成策略与自动选择

### 6.1 首尾帧＋原转场视频参考

适用于同时支持首尾帧和参考视频的模型。以 A 尾帧作为严格起点、B 首帧作为目标终点，原转场片段只提供运动、遮挡和节奏参考。这是优先级最高的策略。

### 6.2 中间关键帧＋首尾帧生成

先生成中间关键帧并人工确认，再把时间有序的关键帧组交给视频模型。该方式增加一次审核，但最容易在正式视频生成前发现身份、动作或空间错误。

### 6.3 直接多图参考生成桥接视频

适用于支持多图但不支持严格双关键帧的模型。请求必须明确图片角色和时间顺序，并默认生成多个候选。该方式具有较强语义连续性，但不能宣称首尾像素完全一致。

### 6.4 尾帧接力

适用于只支持首帧图生视频的模型。先提取 A 的已确认尾帧，再以该帧启动后续动作。系统需要把提示词改写为“延续当前动作”，禁止把动作从头描述一遍。

### 6.5 提示词降级

模型不支持参考媒体时，只把连续性协议注入提示词。UI 必须显示“低连续性保障”，并说明哪些输入未被模型消费。

## 7. 转场类型

| 类型 | 主要约束 | 推荐策略 |
|---|---|---|
| 连续动作 | 身份、姿势、位置和运动方向严格一致 | 首尾帧或中间关键帧桥接 |
| 匹配剪辑 | 主体轮廓、位置、颜色或动作形态匹配 | 多图桥接 |
| 遮挡转场 | 遮挡进入、覆盖和离开时机 | 原转场视频参考 |
| 甩镜／运动模糊 | 运动方向、速度和模糊节奏一致 | 原转场视频参考或专用桥接片段 |
| 推拉／缩放 | 构图中心和缩放轨迹一致 | 双关键帧控制 |
| 场景切换 | 身份保持，场景允许在遮挡区变化 | 资产参考＋桥接片段 |
| 硬切 | 不要求逐帧连续，只保持必要主体资产 | 无桥接视频或普通时间线切换 |

系统可根据原视频分析推荐类型，但用户能够手动切换。选择“硬切”时不应强制产生模型费用。

## 8. 模型能力与代码抽象

新增独立的 `TransitionGenerationProvider` 或在统一 Provider 契约中引入明确的 transition capability，不能把桥接请求伪装成普通单分镜请求。

能力目录至少声明：

```text
supports_multi_image_reference
supports_first_frame
supports_last_frame
supports_reference_video
supports_intermediate_keyframes
supports_video_extension
supports_video_to_video
max_reference_images
max_reference_videos
supported_duration_range
supported_aspect_ratios
```

标准请求包含：

- `transition_plan_id`
- `source_shot_id` 与 `target_shot_id`
- 角色化参考输入列表
- 连续性协议快照
- 转场类型、时长、画幅和输出分辨率
- 模型、执行模式、候选数量和预算上限
- 输入指纹、幂等键和价格快照

各厂商 Adapter 继续物理隔离。业务服务只消费标准结果：候选媒体、首尾帧、缩略图、质量报告、Provider 任务 ID、用量、预计／实际费用和标准错误。

## 9. 数据模型建议

### 9.1 `TransitionPlan`

- `id`
- `project_id`、`revision_id`
- `source_shot_id`、`target_shot_id`
- `transition_type`
- `strategy`
- `duration_ms`
- `continuity_contract`
- `status`
- `input_fingerprint`
- `created_at`、`updated_at`

### 9.2 `TransitionReferenceBinding`

- `transition_plan_id`
- `role`
- `asset_id` 或 `media_evidence_id`
- `sequence_index`
- `priority`
- `source_revision`

### 9.3 候选和质检

中间帧与桥接视频可以复用现有 `GenerationRun`、`GenerationCandidate`、`ProviderTask` 和 `ApprovalEvent`，但需要新的生成类型和引用关系。另保存 `ContinuityReport`：

- 身份一致性
- 服装／产品一致性
- 姿态和动作阶段一致性
- 主体位置与尺寸连续性
- 运动方向和光流连续性
- 镜头与色彩连续性
- 风险项、检测版本和证据帧

## 10. 状态、失效和回退

转场节点状态建议为：

```text
draft
→ references_ready
→ keyframe_generating
→ keyframe_review_required
→ video_generating
→ video_review_required
→ approved
```

任一步均可进入 `failed`、`cancelled` 或 `stale`。

以下变化只使关联转场过期：

- A 的采用视频、出点或尾帧改变。
- B 的采用图片、采用视频、入点或目标首帧改变。
- 连续性锁、资产绑定、转场类型或时长改变。

旧中间帧、旧视频候选和费用记录永久保留，用户仍可查看或重新采用。系统不得自动删除已生成文件。重新采用旧候选时，需要明确提示它是否基于旧边界状态。

## 11. 提示词编译

转场提示词由结构化字段编译，不允许前端手工拼接厂商专用字符串。标准结构为：

```text
起始状态
目标状态
动作路径
转场方式
固定身份和资产
镜头与空间约束
允许变化
禁止变化
```

示例：

> 严格延续 `@转场前尾帧`。人物身份、白色服装、右手持物和当前姿势保持一致；人物右手从肩部继续向上，不能重新开始动作。参考 `@原视频转场` 的近景遮挡和从左向右运动，在 1.2 秒内自然过渡到 `@转场后首帧`。最终人物位置、身体朝向和构图与目标帧一致。禁止身份漂移、肢体突变、服装变化、额外人物和镜头轴线反转。

## 12. UI 方案

### 12.1 时间线和分镜列表

在相邻分镜之间显示转场节点：

```text
分镜 1
   │
   ├─ 转场 1→2 · 多图桥接 · 1.2 秒 · 待确认
   │
分镜 2
```

节点显示类型、策略、时长、状态、模型和费用。硬切节点显示零模型费用。

### 12.2 转场工作台

工作台分为四个区域：

1. **参考区**：A 尾部帧、原转场、已确认中间帧、B 目标首帧和绑定资产，所有媒体显示角色标签。
2. **连续性设置区**：人物、服装、动作、位置、镜头、光线等锁定项。
3. **生成设置区**：转场类型、策略、模型、时长、分辨率、候选数和预计费用。
4. **候选区**：循环播放、首尾帧对比、与原转场并排播放、质量提示、选择、采用、取消采用、下载和历史候选。

支持半透明叠加 A 尾帧与候选首帧、候选尾帧与 B 首帧，以便快速检查位置和构图偏差。

## 13. 自动质量检查

生成后检查：

- 人脸和主体身份相似度。
- 服装颜色、纹理和产品结构。
- 人体关键点、动作阶段和手部异常。
- 主体边界框位置、面积和运动方向。
- 道具是否存在及其相对位置。
- 光流、镜头运动、轴线和构图跳变。
- 光线、色温、曝光和主色调差异。
- 文件、时长、编码、帧率和首尾帧可读性。

文件损坏、时长或编码不合规属于阻断错误；语义连续性评分默认只提示风险，不阻止用户采用。后续积累黄金样本后再评估是否增加可配置门槛。

## 14. 时间线、音频与合成

- 桥接视频默认不承担对白生成，音频继续由时间线统一映射。
- 原音轨连续时，桥接区间沿用原音轨；无有效原音轨时使用静音或现有音轨策略。
- 分镜主体视频可以保留短头尾余量，桥接片段在时间线上受控覆盖该区间。
- 首尾像素不完全一致时，可以使用短叠化或光流补偿，但必须保存合成参数，不能覆盖候选原文件。
- 转场确认后才进入最终高清渲染；上游变化会使对应预览和最终导出过期。

## 15. 成本、恢复与通知

- 中间关键帧和桥接视频分别估价、计费和展示实际成本。
- 默认先低分辨率预览，确认后再生成正式桥接视频。
- 单个转场失败不阻塞其他转场任务，支持幂等重试和服务重启恢复。
- 余额不足、能力不支持、生成完成和生成失败通过账户通知系统提示。
- 重新生成前显示预计费用、已花费用和受影响范围。
- 请求指纹相同且候选文件有效时允许复用结果，避免重复计费。

## 16. 候选交付拆分

如果后续确认进入开发，建议拆分为：

1. **Batch 4.9.1：转场域模型与工作台骨架**
   建立 TransitionPlan、参考绑定、连续性协议、状态机、相邻分镜节点和版本失效规则。
2. **Batch 4.9.2：中间关键帧闭环**
   实现多图参考包、提示词编译、中间帧生成、候选历史和人工确认。
3. **Batch 4.9.3：桥接视频 Provider**
   接入首个已验证的国内多图／首尾帧视频模型，完成能力校验、异步任务、费用和余额处理。
4. **Batch 4.9.4：连续性质检与受控时间线**
   实现连续性报告、风险提示、桥接片段插入、音轨映射、低清预览和上游失效传播。
5. **Batch 4.9.5：人工验收与成本基线**
   使用连续动作、匹配剪辑、遮挡转场、甩镜和硬切样本验收，记录成功率、重试次数和平均费用。

Batch 4.9 仅是当前路线中的候选编号；开始实施前仍需确认模型可用性、API 能力、价格和验收样本。

## 17. 验收方向

- 一个连续动作样本中，B 不再从动作初始状态重新开始。
- 一个位置敏感样本中，人物在转场前后的屏幕位置和运动方向保持合理连续。
- 一个换场景样本中，人物和服装保持一致，场景只在指定遮挡区变化。
- 用户可以查看原转场、边界帧、中间帧和所有历史视频候选。
- 用户可以取消采用、切换旧候选或只重新生成一个转场。
- 不支持多参考的模型会在提交前明确阻止或要求用户确认降级。
- 修改相邻分镜后，只有相关转场和下游渲染变为过期。
- 每次模型调用都具有可追溯输入快照、模型快照、费用和 Provider 任务状态。

## 18. 风险与待确认事项

- 不同模型对“多图参考”“首尾帧”和“参考视频”的定义不同，需要真实 API 验证，不能只根据产品宣传声明能力。
- 参考图片过多可能降低模型遵循度，需要在模型级能力目录中设定默认数量和硬上限。
- 生成视频可能语义连续但首尾像素不一致，因此仍需边界比较和受控合成。
- 原视频转场可能包含受版权保护的独特素材；系统应把它用于结构和运动参考，不默认复制水印、人物或品牌元素。
- 自动连续性评分不能替代人工审核，首版不应把未经校准的评分设为硬门禁。
- 复杂跨场景变换可能需要遮挡、甩镜或运动模糊来隐藏不可避免的形态变化，UI 应允许用户明确选择这些策略。
