# Phase 2 Batch 4.6.1～4.6.5：剪辑时间线与低清预览执行验收

更新时间：2026-08-08  
状态：已实现，待人工验收

> 2026-08-11 更新：剪辑工作台已抽离为独立 `video-editor` 模块，时间线可直接从已采用的视频候选初始化，并新增 A2 附加音频轨。旧剪辑准备记录仍兼容读取，但不再是进入编辑阶段的必要条件。

## 1. 本批结论

本批把 Batch 4.5.3 的 `editing-handoff.json` 转换为正式、可修改、可回退的受控时间线，并完成低清预览闭环。

已完成范围：

- 4.6.1：`timeline.json`、时间线领域模型、不可变 `TimelineRevision` 快照；
- 4.6.2：时间线查询、修改、校验、历史查看和历史恢复 API；
- 4.6.3：片段、音轨、字幕、预览和版本历史组成的受控时间线 UI；
- 4.6.4：原视频音轨映射、逐条字幕、直接切换／淡入淡出／叠化；
- 4.6.5：FFmpeg 低清预览、持久化 `RenderJob`、进度、取消、失败重试入口和账户消息通知。

本批不包含 4.6.6 最终高清成片与导出归档，也不混入生成视频自带音频，不实现 TTS、声音克隆或口型同步。

## 2. 文件与版本设计

一个创作方案进入 `editing` 后，首次读取时间线会幂等消费交接清单并生成：

```text
records/<record_id>/productions/<project_id>/
├─ timelines/
│  ├─ editing-handoff.json
│  ├─ timeline.json
│  ├─ revisions.json
│  └─ revisions/
│     └─ 0001-<timeline_revision_id>.json
└─ renders/
   ├─ jobs/<render_job_id>.json
   └─ previews/<render_job_id>/
      ├─ preview.mp4
      ├─ preview.vtt
      └─ intermediate/
```

`timeline.json` 使用 `viral-dna-timeline/v1`，保存：

- 方案画幅、尺寸、帧率和总时长；
- 视频片段顺序、启用状态、候选引用、入点、出点、变速和时间线区间；
- 片段音量、原音轨区间与全局音轨策略；
- 字幕文本、启用状态、片段相对时间与全局时间；
- 片尾转场种类和时长；
- 当前校验警告及最近一次预览任务指针。

每次保存不覆盖历史快照，而是创建新 `revision_id` 和递增版本号。恢复历史版本同样创建新版本，不回写或删除旧快照。

## 3. 受控编辑规则

### 3.1 片段

- 可以停用片段，但时间线必须至少保留一个启用片段；
- 可以向前／向后调整顺序；
- 可以修改入点、出点和成片时长；
- 播放速率由“裁剪后候选时长 ÷ 成片时长”确定性计算；
- 播放速率低于 `0.5x` 或高于 `2x` 只显示节奏风险，不静默修改参数；
- 保存请求必须携带 `expected_revision_id`，版本冲突返回 `409`。

### 3.2 转场

- `none`：直接切换；
- `fade`：在片段内部执行淡入淡出，不改变总时长；
- `crossfade`：相邻片段叠化，总时长扣除重叠区间；
- 转场最长 2 秒，且不能超过相邻任一片段时长的一半；
- 最后一个启用片段不能设置片尾转场。

### 3.3 音轨与字幕

- 原音轨始终来自被分析的源视频，不读取生成候选的原生声音；
- 支持连续原音轨、逐片段映射和全局静音；
- 单片段可独立静音、调整音量；全局可调整音量并启用响度标准化；
- 字幕从交接清单中的独立字幕优先导入，没有独立字幕时使用对白；
- 字幕可逐条启用／停用和修改文本；重排片段后按片段相对时间重新定位；
- 预览同时封装 `mov_text` 字幕轨，并输出浏览器可加载的 `preview.vtt`。

## 4. API

### 4.1 时间线

- `GET /api/v1/productions/{project_id}/timeline`
- `PUT /api/v1/productions/{project_id}/timeline`
- `GET /api/v1/productions/{project_id}/timeline/validation`
- `GET /api/v1/productions/{project_id}/timeline/revisions`
- `GET /api/v1/productions/{project_id}/timeline/revisions/{revision_id}`
- `POST /api/v1/productions/{project_id}/timeline/revisions/{revision_id}/restore`

### 4.2 低清预览

- `POST /api/v1/productions/{project_id}/timeline/preview-renders`
- `GET /api/v1/productions/{project_id}/render-jobs/{job_id}`
- `POST /api/v1/productions/{project_id}/render-jobs/{job_id}/cancel`
- `GET /api/v1/productions/{project_id}/render-jobs/{job_id}/content`
- `GET /api/v1/productions/{project_id}/render-jobs/{job_id}/subtitles`

预览任务使用 `viral-dna-render-job/v1`，保存排队、运行、成功、失败和取消状态，以及进度、产物路径、错误码和时间戳。服务重启后发现未完成的孤立任务会标记为中断，并提示重新生成。

## 5. FFmpeg 预览管线

1. 按片段入点／出点截取不可变候选文件；
2. 按播放速率变速并缩放、补边到方案画幅，最大边限制为 960 像素；
3. 生成直接切换、淡入淡出或叠化的视频轨；
4. 从源 WAV 按片段区间截取，执行变速、片段音量、全局音量和可选响度标准化；
5. 对叠化连接使用音频交叉淡化，其他连接顺序拼接；
6. 生成 WebVTT，同时封装字幕、AAC 音轨和 H.264 视频；
7. 使用 `+faststart` 生成可在浏览器中立即播放的 `preview.mp4`。

Windows 子进程使用无窗口标志，避免 FFmpeg 弹出命令行窗口。任务支持运行中取消；取消或服务关闭时会终止子进程并持久化最终状态。

## 6. UI 设计

剪辑合成页使用全宽任务布局：

- 顶部：片段数、总时长、版本历史、保存和生成预览；
- 左侧主区：按方案画幅完整显示的视频播放器，以及视频／原音轨／字幕三条轨道；
- 右侧检查器：片段、音轨、字幕三个标准属性页；
- 版本历史使用页内渐进展开，不使用阻断式弹窗；
- 未保存修改时禁止生成预览，避免渲染状态与界面草稿不一致；
- 渲染进度在工具栏紧凑显示，完成／失败／取消结果进入账户消息中心；
- 1080px 以下检查器移到主区下方，700px 以下操作按钮和字段改为单列；
- 横版、竖版和方形媒体均使用 `object-fit: contain`，不裁掉画面或原生播放控件。

## 8. 人工验收流程

1. 打开一个已进入“剪辑合成”的创作方案，确认首次进入后显示全部已交接片段及缩略图。
2. 选择任一片段，调整入点、出点和成片时长，保存后确认版本号递增。
3. 调整两个片段顺序、停用一个非必要片段，确认轨道顺序与总时长更新。
4. 在非末尾片段选择“淡入淡出”或“叠化”，设置合法时长并保存。
5. 切换原音轨／静音，调整全局和片段音量；编辑或停用一条字幕并保存。
6. 打开版本历史，恢复一个旧版本，确认系统创建新版本且旧版本仍可查看。
7. 点击“生成低清预览”，确认工具栏显示进度，任务完成后右上角收到消息。
8. 播放预览，确认画面未裁切、播放控件可见、顺序／转场／声音／字幕符合时间线。
9. 再次生成预览并点击取消，确认任务最终为“已取消”且消息中心有记录。
10. 修改时间线但不保存，确认“生成低清预览”不可用并有明确提示。
