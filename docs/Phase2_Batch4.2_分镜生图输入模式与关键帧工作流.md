# Phase 2 Batch 4.2：分镜生图输入模式与关键帧工作流

更新时间：2026-08-05

状态：本切片已实现并通过自动化测试；本轮没有调用真实付费模型，也没有自动提交或推送 Git。

## 1. 已实现的产品规则

### 两种生图输入模式

每次生成都会记录 `input_mode`：

- `keyframe_edit`：文字 + 图片。发送当前关键帧，并按绑定关系附带人物、产品、服装、场景等参考图。
- `text_to_image`：纯文生图。只发送提示词和负面约束，主动排除关键帧与所有参考图。

百炼 Qwen Image、本机通用 CLI 和 Codex + ImageGen 包装器共用同一协议。模型或工具必须声明对应能力，不支持时会在调用前拒绝请求。

### 单次生图引擎选择

全局设置继续保存国内 API 和本机工具配置，分镜工作台可为每次生成选择：

1. `default`：使用全局当前模式。
2. `remote_api`：本次使用国内大模型 API。
3. `local_tool`：本次使用本机 ImageGen/CLI。

未配置的引擎会在 UI 中禁用。失败后不会自动切换引擎，避免不可预期的费用和输出差异。

### 默认一帧与人工选帧

- 每个分镜创建时只有一个分析阶段生成的默认关键帧。
- 默认 AI 候选数量调整为 1，单次仍可选择 1～4 张。
- 用户可在当前分镜时间范围内播放源视频、拖动进度条并选择新关键帧。
- 用户可直接确认当前关键帧，不调用图片模型，成本为 0。
- AI 重绘为可选操作。
- 更换关键帧会创建新 Revision、归档旧候选、清除旧审批，并使已有下游视频结果过期。
- 从历史 Revision 创建分支时，人工选择的关键帧会复制到新分支。

## 2. UI

分镜图片工作台新增：

- 当前关键帧来源和时间点。
- “从视频重选”按钮与视频选帧弹窗。
- “直接使用此帧”零模型调用入口。
- “关键帧编辑（文字 + 图片）/纯文生图（仅文字）”选择器。
- “默认/国内大模型 API/本机 ImageGen”引擎选择器。
- 1～4 张候选数量选择器，默认值为 1。
- 本次模式、引擎和预计成本提示。
- 本机工具代理模式：自动读取 Windows 系统代理、手动 HTTP/HTTPS 代理或禁用代理。
- “测试网络与登录”入口；只验证 ChatGPT HTTPS 连通性和本机 Codex 登录，不生成图片。
- 失败候选直接显示后端错误码、错误信息、处理建议和“重试生成”按钮文案。

## 3. API 与数据

新增接口：

- `GET /api/v1/productions/{project_id}/source-video`
- `GET /api/v1/production-shots/{shot_plan_id}/source-keyframe`
- `POST /api/v1/production-shots/{shot_plan_id}/source-keyframe`
- `POST /api/v1/production-shots/{shot_plan_id}/source-keyframe/approval`
- `POST /api/v1/settings/image-generation/test-local-network`

图片生成接口新增 `input_mode`，并继续允许用 `execution_mode` 覆盖本次引擎。业务请求不能主动指定 `simulated` 或 `source_frame`；`source_frame` 只由“直接使用此帧”流程生成，用于明确记录没有模型调用。

`ShotPlan` 新增关键帧工作区相对路径、时间点和来源；`GenerationRun` 新增输入模式。关键帧文件、输入快照、候选、缩略图、元数据和结果清单均保存在对应工作区目录。

请求指纹包含输入模式，纯文生图与关键帧编辑不会误命中同一缓存。

## 4. 安全与成本

- 纯文生图不会读取或发送工作区图片。
- 自定义关键帧只能位于当前项目的当前分镜目录。
- 视频选帧时间必须位于当前分镜区间。
- 远程与本机模式不会自动互相降级。
- 直接使用源关键帧时，预估和实际成本均为 0，成本来源为 `unmetered`，执行摘要记录 `model_call: false`。
- 自动化测试使用 MockTransport、假 CLI 和假帧提取器，没有触发真实百炼或 ImageGen 付费调用。

### 本机 Codex 代理规则

- 默认 `system` 模式读取 Windows 当前用户代理；在非 Windows 环境中回退到 `HTTPS_PROXY/HTTP_PROXY`。
- `manual` 模式只接受不含账号密码的 HTTP/HTTPS 主机与端口。
- `disabled` 模式明确直连，不会隐式继承服务进程代理。
- 有效代理会以 `HTTP_PROXY/HTTPS_PROXY` 大小写两组变量注入本机工具进程，并由 Codex 子进程继承。
- 运行快照只记录代理来源和是否启用，不记录代理地址。
- 网络检测不调用图片模型，不产生图片候选或项目成本。
