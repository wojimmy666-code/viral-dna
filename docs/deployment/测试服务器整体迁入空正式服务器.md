# 测试服务器整体迁入空正式服务器

状态：跨机迁移工具及隔离测试；不是实际迁移完成记录。适用于 **正式端尚未初始化、没有任何需保留账户或业务数据**。本轮没有停服、读取/打包真实账户、上传数据或修改 IIS。

## 与其他工具的区别

- 本文迁移账号、企业成员、密码哈希、完整账户工作区、资产、项目、生成历史与容量。导入后无需再次初始化，使用测试端原手机号/密码，admin 也使用测试端原密码。
- [资产同步](资产同步与容量配置.md)导入媒体到已有服务器账户，不迁移身份库或完整项目。
- [同机账户目录迁移](账户目录统一与旧账户迁移.md)只改变当前机器的路径，不能当作本文的跨机导入命令。

**这是账号业务数据迁移，不是整台电脑克隆。** 不迁移 `.env`、IIS、证书、Windows 服务账户、安装工具、平台级模型/Skill 配置、通知库或本机授权。已保存的项目及 Skill 版本快照随账户工作区保留；平台配置需在正式机另行核对。DPAPI 加密的平台 Cookie、OSS/同步凭据以及本机模型授权需要重新配置，不要直接复制密文当作授权成功。

## 安全边界

- 工具只用 Python 3.11+ 标准库，入口为 [transfer-installation.py](../../scripts/maintenance/transfer-installation.py)。不会联网、连接 GitHub、安装软件或启停服务。
- `export`、`import` 和 `recover` 不加 `--apply` 时只预览。SQLite 只读连接可能生成正常 WAL/SHM 辅助文件，不改变业务记录；完整迁移包里的数据库会转换为无 WAL 的关闭快照，可重复校验。
- 实际操作要求显式确认停服；导入还要求确认目标为空，以及提供测试端生成的清单 SHA-256。新版 API 与工具共用互斥锁，但旧进程可能没有锁，因此必须人工确认所有写入者已停止。
- 两端 API 源码指纹必须一致，工作区 Schema 也必须匹配。预览会拒绝未完成生成任务、缺失原件、未登记工作区、目录联接/符号链接和非法路径。云端独有的对象必须先在来源应用补齐本地副本；工具不会隐式下载或调用付费模型。
- 包是一个以 `.vdna-migration` 结尾的目录，**不是 ZIP 执行包**。包括所有成员及私有业务内容，只通过受控文件传输或加密介质交付，不放在 IIS 可访问目录，不提交 GitHub。清单哈希应单独保存；哈希是完整性校验，不是加密。
- 所有账户都迁移，不按手机号合并、不覆盖已初始化服务器。正式端仅有空 Schema 的身份库可以接受，会保留原件；任何已有账户、目录登记、账户目录文件或旧工作区业务数据都会阻止导入。
- 原始账号、用户、项目、工作区、资产和存储位置 ID 保留；正式机获得新的设备 ID。旧登录会话、邀请/重置链接、项目编辑锁和同步设备令牌失效，尚未激活的成员需重新发送激活链接。
- 导入副本清除旧同步连接、上传断点、同步任务、预留量和媒体访问租约，不让旧设备任务自动续跑。容量上限、原件、独立历史和回收站业务记录保留；首次启动重新清点。
- 使用短的包目录名。媒体文件扫描、复制和校验使用 Windows 扩展路径处理超过 260 字符的文件名，目录登记和业务数据中仍保留普通路径；不改注册表、不截短业务文件名。数据库及部署根目录仍应保持简短。权限不足或磁盘不足时保留原件/未发布副本，不要删除整个目录绕过检查。

## 1. 两端准备（正式端不要初始化）

1. 待工具提交后，通过 SSH 更新两端源码到同一版本；确保没有未同步的 API 本地修改。正式端不要先创建空账户来“接收”数据。
2. 按[备份与恢复](升级备份与恢复.md)准备独立备份。Git 更新不备份账户数据。
3. 在测试端核对实际运行的配置文件。以下以当前仓库 `D:\Projects\ViralDna` 为例；如果运行的 API 来自其他目录或使用 `VIRAL_DNA_ENV_FILE`，请填写那个实际配置文件。
4. 工具读取指定文件。测试端未填写身份路径时按应用默认规则定位当前 Windows 用户的 `%LOCALAPPDATA%\ViralDNA`；**不会读取另一个进程的环境变量覆盖值**。预览路径必须与实际 API 对照，必要时用下面的专用配置明确指定。

仅列路径的专用配置可参考 [migration-source.env.example](../../scripts/maintenance/migration-source.env.example)，不需要复制模型密钥。正式端必须明确配置 `VIRAL_DNA_AUTH_DB_PATH`、`VIRAL_DNA_ACCOUNT_CATALOG_PATH`、`VIRAL_DNA_ACCOUNTS_ROOT`，三者位于同一专用数据目录，账户根目录名称为 `accounts`。

## 2. 测试端预览

在测试端 PowerShell 执行（Python 路径按实际安装位置填写）：

```powershell
$transferPython = 'C:\Users\HUAWEI\AppData\Local\Programs\Python\Python312\python.exe'
$transferTool = 'D:\Projects\ViralDna\scripts\maintenance\transfer-installation.py'
$transferEnv = 'D:\Projects\ViralDna\.env.local'
$transferBundle = 'D:\test-data.vdna-migration'
& $transferPython $transferTool export --env-file $transferEnv --bundle $transferBundle
```

核对：身份库位置、账户目录登记、各账户工作区来源、账户/成员数量、各业务表记录数、文件量和预计容量。未绑定到当前身份库的旧工作区不会被自动并入；旧的保留副本会在 `excluded_legacy_copy` 明确提示，不会再次打包制造重复数据。

新开通但还没有工作区数据库的账户，须先在来源应用登录/完成工作区初始化并再次核对，不能把“目录缺失”默认为空账户。

## 3. 测试端停写并导出

等生成、分析、同步、导出结束，关闭所有本项目 API/写入进程；仅关闭浏览器不等于停止写入。确认维护窗口后执行：

```powershell
& $transferPython $transferTool export --env-file $transferEnv --bundle $transferBundle `
  --apply --confirm-api-stopped
```

工具复制当前身份库和每个账户工作区，SQLite 备份包含已提交 WAL 数据。检测到来源变化就不发布迁移包。成功会输出 `exported: true`、账户/文件统计和 `manifest_sha256`。请单独保存该 SHA-256。

原数据不删除，测试端密码/会话不被工具修改；已清理的临时会话只发生在导出副本。导出后测试端不要继续新增正式业务，否则这些增量不在包内。不要在两边同时写入同一份业务历史。

重复导出使用新目录名；现有包不覆盖。失败的 `.vdna-migration.pending-*` 保留用于排查，不表示导出成功。

## 4. 拷贝到正式端并预检

把完整 `test-data.vdna-migration` 目录拷贝到：

```text
C:\Projects\ViralDNA\.server\migration\test-data.vdna-migration
```

只拷贝迁移包，不覆盖 `.server\config`、`.server\iis`、`.server\tools` 或运行环境。正式端 PowerShell：

```powershell
$transferPython = 'C:\Projects\ViralDNA\.server\tools\python\python.exe'
$transferTool = 'C:\Projects\ViralDNA\scripts\maintenance\transfer-installation.py'
$transferEnv = 'C:\Projects\ViralDNA\.server\config\api.env'
$transferBundle = 'C:\Projects\ViralDNA\.server\migration\test-data.vdna-migration'
$transferDigest = '替换为测试端输出的64位manifest_sha256'
& $transferPython $transferTool import --env-file $transferEnv --bundle $transferBundle `
  --manifest-sha256 $transferDigest
```

必须得到 `preview: true`、`target_empty: true`。工具逐文件检查内容与大小、数据库和资产原件，不仅检查包是否存在。磁盘要能容纳迁移包、完整目标副本、原始空配置备份及余量。预检失败不要手动改清单或删除身份库绕过。

## 5. 正式端停服并导入

在 `scripts\deploy-server.bat` 选择 **4**，并确认没有其他 ViralDNA API。手动 IIS 模式不会操作 IIS；维护期间可手动停止 **ViralDNA 这个站点**，不影响其他网站。

```powershell
& $transferPython $transferTool import --env-file $transferEnv --bundle $transferBundle `
  --manifest-sha256 $transferDigest --apply --confirm-api-stopped --confirm-empty-target
```

实际目标取现有 `api.env`，标准部署为：

```text
C:\Projects\ViralDNA\.server\data\
├─ accounts.sqlite3
├─ account-catalog.json
├─ accounts\<账户UUID>\
└─ installation-migrations\<操作UUID>\
   ├─ operation.json
   ├─ previous\       原始空身份库/登记/目录（存在才备份）
   └─ rolled-back\    异常回退时保留的副本
```

先准备完整副本并转换路径，安装工作区与目录登记，最后发布身份库。只重写业务 JSON 中匹配旧工作区的路径字段，不全局替换提示词或媒体字节。需要 `imported: true` 才表示导入完成。工具不自动启动服务，也不删除迁移包。

## 6. 异常中断与恢复

普通安装错误会回退已安装项并恢复原件。突然断电、强杀进程或回退本身失败时，身份库旁会保留 `accounts.installation-migration.json`。**新版 API 会拒绝启动，禁止直接删除这个标记。**

确认仍停服后先预览恢复：

```powershell
& $transferPython $transferTool recover --env-file $transferEnv
```

核对操作 UUID 与备份目录，再执行：

```powershell
& $transferPython $transferTool recover --env-file $transferEnv `
  --apply --confirm-api-stopped --operation '替换为恢复预览中的操作UUID'
```

恢复会回退这次导入，恢复为空服务器；不删除迁移包或账号副本。若目标或备份出现未预期变化则停止，不能覆盖外部新数据。恢复完成后重新预检再导入。导入已经成功且标记已移除时不能使用 `recover` 当作清空服务器命令。

## 7. 启动验收

1. 用部署菜单 **2** 编译并启动包含本次工具/保护逻辑的新版本；不要直接用菜单 3 启动旧发布版本。
2. 本机打开 `http://127.0.0.1:8080/login`，应显示登录而不是初始化；用测试端原手机号密码登录。后台使用测试端原 admin 密码。
3. 检查企业成员共享、个人账号隔离、项目/资产目录、原图/视频下载、生成历史及容量。等待首次存储清点完成，再验证新的上传或生成。
4. 核对工作区均位于正式端 `accounts\<账户UUID>`，不再依赖测试机磁盘。重新配置平台 Cookie、模型、OSS 或同步等连接，不照搬测试机密文。
5. 确认正常后手动启用 ViralDNA IIS 站点，进行 HTTPS 登录、媒体访问和跨账户隔离验收。保留原数据及独立备份，不自动删除测试端目录。
