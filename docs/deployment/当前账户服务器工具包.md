# 单目录 Windows 服务器部署工具包

适用：Windows Server x64，服务器当前登录的管理员账户，目标目录固定 `C:\Projects\ViralDNA`。不创建专用 Windows 服务账户，不建立 `ViralDNA-runtime` 目录。

状态：已准备工具、配置生成器及离线测试；没有在目标服务器安装、启动或验证 IIS。工具包不是完全离线的应用镜像：编译仍需访问 npm、PyPI，IIS 角色安装可能需要 Windows 安装源。

如果同一服务器还承载其他网站，并且你已经手动配置了 ViralDNA 的 IIS 站点、证书与反向代理，请在完成本工具包的 02 / 03 后改用[手动 IIS 启动更新包](手动IIS启动更新包.md)，不要继续执行下面的自动 IIS 配置步骤。更新包会保留现有 IIS 配置，只管理本项目内部服务。

## 最终目录

```text
C:\Projects\ViralDNA\                 Git 仓库根目录，main 分支
├─ apps\、services\、scripts\……        更新 Git 后出现
└─ .server\                           唯一的项目运行目录，不纳入 Git
   ├─ tools\                          Git、Node、Python、FFmpeg、Caddy、WinSW
   │  └─ installers\                  Python、IIS Rewrite、ARR 安装包
   ├─ setup\                          复制即用的部署入口和完整控制器
   ├─ config\                         deploy.json、api.env、IIS 归属记录
   ├─ data\                           账户、资产、项目、生成历史、凭据
   ├─ cache\                          构建依赖下载缓存
   ├─ iis\site\web.config             IIS 只指向这里，不暴露项目目录
   └─ deployment\                     独立构建版本、服务、日志
```

IIS、URL Rewrite、ARR 是 Windows 系统组件，按微软规定安装在系统位置；Windows 服务注册信息、证书库和 SSH 用户身份配置仍由系统管理。项目工具、Python、依赖环境、配置及业务数据都在上述项目目录内。

外部访问经 IIS 转发到本机 Caddy，再到 API。Caddy 用于提供编译后的前端和实时 API 转发，只监听回环地址，不另占公网端口。API 仍为一个进程。

## 第 1 步：在服务器创建目录

用后续实际运行服务的 Windows 管理员账户登录，创建：

```powershell
New-Item -ItemType Directory -Path C:\Projects\ViralDNA -Force
```

已有目录时不要删除、覆盖已有项目或数据。已有代码必须是本项目的 `main` 分支；存在本地修改时脚本会停止，不会强制覆盖。

## 第 2 步：复制准备好的文件

准备电脑上的最终交付目录是 `D:\ViralDNA\server-package`。把它里面的 **`.server` 文件夹**复制到服务器 `C:\Projects\ViralDNA`，得到 `C:\Projects\ViralDNA\.server`。

不要把准备目录 `D:\ViralDNA` 整体复制过去；其中原来的 `config`、`setup` 和说明属于旧的双目录准备结果，已被这个新包替代。不要把 `server-package` 这一层再嵌套到服务器项目里。

右键“以管理员身份运行”：

```text
C:\Projects\ViralDNA\.server\setup\02-prepare.bat
```

它会先按 SHA-256 清单验证复制完整性，然后把 Python 安装到 `.server\tools\python`，自动填写当前 `计算机名\用户名`，创建 `.server\config\deploy.json` 和数据目录。其他工具已经是便携版，不改系统 PATH。若提示需要重启，先重启服务器再重试此步骤。

没有默认网站密码、初始化码、模型密钥或测试电脑的账号数据。`deployment.preview.json` 仅供查看路径，真正使用的是服务器生成的 `deploy.json`。重复准备保留已有配置；不要在现有生产 `.server` 上直接覆盖一整套新工具包。

准备器只给当前管理员补充“作为服务登录”权限，不新建用户、不重置密码。首次注册项目服务时仍需输入当前 Windows 账户的真实密码，不能使用 PIN；更改 Windows 密码后需同步维护服务登录密码。服务将拥有该管理员的权限。

## 第 3 步：更新 Git

### 首次配置 GitHub SSH 读取权限

若服务器当前账户已有可用 GitHub SSH 凭据，可跳过创建密钥。没有时，在管理员 PowerShell 中执行下列命令；如果指定密钥已存在，不要覆盖：

```powershell
New-Item -ItemType Directory -Path "$env:USERPROFILE\.ssh" -Force
& 'C:\Projects\ViralDNA\.server\tools\git\usr\bin\ssh-keygen.exe' -t ed25519 -C 'ViralDNA-server' -f "$env:USERPROFILE\.ssh\id_ed25519"
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
```

把输出的 **公钥**添加到本仓库 GitHub → Settings → Deploy keys，通常只需读取权限。私钥留在服务器，不复制测试电脑的私钥。脚本使用非交互 SSH；若给密钥设置口令，需要先让当前会话的 SSH agent 加载它，否则更新会失败。

首次连接并核实主机指纹：

```powershell
& 'C:\Projects\ViralDNA\.server\tools\git\usr\bin\ssh.exe' -T git@github.com
```

指纹必须与 [GitHub 官方公布的指纹](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints)一致才确认。出现 `successfully authenticated` 即认证成功；GitHub 不提供 shell，因此这条测试命令返回非零退出码并不一定表示认证失败。22 端口受限时参考 [SSH 走 443 端口](https://docs.github.com/en/authentication/troubleshooting-ssh/using-ssh-over-the-https-port)，仍是 SSH，仓库远程地址不改为 HTTPS。

### 拉取代码

右键“以管理员身份运行”：

```text
C:\Projects\ViralDNA\.server\setup\03-update-git.bat
```

首次会在已含 `.server` 的根目录初始化 `main` 并拉取代码；已有仓库只做快进更新。远程固定为 `git@github.com:wojimmy666-code/viral-dna.git`。`.server` 会加入本仓库的本地 Git 排除规则，即使拉到旧版代码，也不会被当成未提交源码或构建输入。

这一步只更新代码，不编译、不关闭服务、不推送 GitHub。存在非本项目文件、其他分支、远程地址不符、冲突或本地修改时停止处理。

## 第 4 步：配置 IIS

右键“以管理员身份运行”：

```text
C:\Projects\ViralDNA\.server\setup\04-configure-iis.bat
```

入口安装缺少的 IIS 角色，按顺序安装已校验微软签名的 URL Rewrite、ARR，创建 ViralDNA 专用站点与应用程序池。站点物理目录只指向 `.server\iis\site`。不会操作默认站点，不执行 `iisreset`，不开放防火墙。

注意：IIS 角色安装、ARR 代理启用、30 分钟超时及关闭代理响应缓冲是**服务器级设置**。如果同机还有其他站点，请在维护窗口执行并检查其兼容性。仅本站关闭 IIS 响应缓存和额外压缩，保留 API 实时事件、查询参数、原始 Host、客户端地址及 HTTPS 协议信息。上传请求上限设为 2 GiB；实际业务文件限制与账户容量仍由应用控制。

初始 IIS 地址为 `http://127.0.0.1:8081`，只允许服务器本机访问。配置完站点保持停止，等第 5 步编译成功再由部署控制器启动。IIS 使用 Windows 内置的应用程序池身份，仅可读取代理目录；它不是额外创建的 Windows 登录账户。API 与 Caddy 服务均使用当前管理员。

同名站点或应用程序池已有其他用途时脚本拒绝接管。IIS 或 Python 安装要求重启时，先重启，再重新运行对应步骤；不得忽略失败提示继续。

## 第 5 步：编译运行

右键“以管理员身份运行”：

```text
C:\Projects\ViralDNA\.server\setup\05-run.bat
```

首次已在第 3 步更新代码，所以按 **2：编译 + 启动**。按提示输入当前 Windows 管理员密码；密码只交给 Windows 服务管理器，不写进配置或命令行。

菜单保持：

1. 更新 GitHub + 编译 + 启动。
2. 编译 + 启动。
3. 启动最近一次成功构建。
4. 关闭。

1、2、3 都先关闭本站 IIS 入口和本项目服务，再执行操作。更新失败不覆盖旧构建，也不删除账户数据。构建在 `.server\deployment\releases` 下使用独立 Node 依赖和 Python 虚拟环境；依赖缓存位于 `.server\cache`。

首次启动后，在服务器浏览器打开 `http://127.0.0.1:8081/login`，完成网站 admin 及首个个人／企业账户初始化，再配置模型供应商密钥。工具包中的控制器可以独立工作，不依赖这些新脚本已推送到 GitHub；当前阶段日常部署也继续使用 `05-run.bat`。仓库的新版本部署入口在提交更新后，也会自动识别 `.server\config\deploy.json`。

## 初始化后：绑定正式域名和证书

尚未提供实际域名与证书，工具包不会虚构它们，也不会预先暴露未初始化网站。

1. 菜单按 4 关闭，再按 0 退出。
2. 将正式 TLS 证书导入 Windows“本地计算机 → 个人”证书库，必须含私钥并覆盖实际域名。
3. 编辑 `.server\config\deploy.json` 的 **Iis 对象**：`SiteUrl` 改为 `https://你的域名`，`AllowPublicAccess` 改为 `true`，`CertificateThumbprint` 填入证书指纹（40 位十六进制，无空格）。**顶层** `SiteUrl` 仍为 `http://127.0.0.1:8080`，顶层 `AllowPublicAccess` 仍为 `false`。
4. 在 `.server\config\api.env` 的 `VIRAL_DNA_CORS_ORIGINS` 中追加实际 HTTPS 域名，保留内部和探测地址。
5. 再运行 `04-configure-iis.bat` 更新本站 HTTPS/SNI 绑定，配置 DNS，并仅按需开放公网 443。不要暴露 8000、8080、8081、18080、12019。
6. 重新打开 `05-run.bat` 按 3。控制器会检查账户已初始化、API/Web 健康和 IIS 域名访问成功，再启用自动启动。

不要只在 IIS 管理器中额外添加绑定而不同步配置；控制器会拒绝不匹配的绑定，避免绕过初始化限制。证书续期更换指纹后按上述停服、更新配置、重新绑定步骤处理。

## 验收与维护

在真实服务器上验收：登录及退出、刷新前端路由、图片／视频上传与播放、生成过程中逐个结果显示、HTTPS Cookie、停止与重新启动、重启后的自动启动。

数据保存在 `.server\data`，不会随 Git 更新、重新编译或关服清除，但必须另做异机备份。工具包不包含现有业务资产；旧资产同步及跨机 DPAPI 凭据迁移按 [备份恢复](升级备份与恢复.md)另行处理，不能把工具复制等同于迁移完成。

复制后、首次准备前可单独验证：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Projects\ViralDNA\.server\setup\verify-bundle.ps1
```

该清单只用于验证原始交付包；运行后编辑配置会导致对应哈希变化，这是正常的，不应覆盖已运行服务器以追求清单一致。

工具来源、版本、大小与 SHA-256 记录在 `.server\bundle-manifest.generated.json`。Node、Git、FFmpeg 下载包核对发布方摘要；Python 和 IIS 安装包校验签名；Caddy、WinSW 记录官方 HTTPS 来源和本地校验值，本地哈希不等于发布方签名。IIS 配置依据 [微软反向代理文档](https://learn.microsoft.com/en-us/iis/extensions/url-rewrite-module/reverse-proxy-with-url-rewrite-v2-and-application-request-routing)，内部代理头处理见 [Caddy 官方文档](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)。

开发端检查：`npm run test:server-prepare`、`npm run test:server-single-root`、`npm run test:deploy`、`npm run test:launcher`、`npm run check:scripts`、`npm run check:docs`。离线测试不安装 IIS，不注册服务，不修改 Windows 账户。
