# 账户目录统一与旧账户迁移

状态：2026-09-11。适用于本次账户目录规则更新后的代码。工具未在正式服务器或真实测试工作区执行；本说明不是迁移完成记录。

## 统一规则

首次账户、后续个人账户和企业账户统一为：

```text
<VIRAL_DNA_ACCOUNTS_ROOT>\<账户UUID>\
├─ .viraldna\workspace.json          工作区身份
├─ .viraldna\workspace.db            项目、资产、逻辑目录等业务索引
├─ .viraldna\durable-storage.sqlite3 长期存储、容量、同步账本
├─ objects\                          文件对象及长期原件
└─ records\                          项目过程文件
```

正式部署配置的父目录为 `C:\Projects\ViralDNA\.server\data\accounts`；测试环境可配置其他父目录，账户内部规则不变。企业成员共享账户目录，不按登录用户复制一套。

`.server` 仍然是正式部署工具的布局，不要求开发启动器和正式 Windows 服务采用同一种启动方式。本次不移动工具、IIS 配置、运行账户或编译目录。

## 全新初始化与旧数据升级

- 全新安装：在本机完成首次设置，直接创建标准账户目录；不会仅因启动 API 就创建 `legacy-workspace`。配置中的 `VIRAL_DNA_WORKSPACE_ROOT` 仅保留为兼容导入来源或显式本机开发工作区。
- 尚未启用账户系统、但旧工作区已有数据：首次设置仍要求确认归属。系统复制整个已确认工作区，保留身份和引用，校验后绑定标准目录。不得同时运行旧版写入进程。原目录保留。
- 已初始化的账户：启动新版仍读取现有绑定，不自动移动。先停服再使用以下工具，不能改名文件夹、手工改 ID 或删除数据库重做初始化。

## 迁移前准备

1. 确认源码已包含本次更新，保留当前已知可用的应用版本。
2. 等待生成、分析、导出、同步结束。按[升级备份与恢复](升级备份与恢复.md)做独立的一致性备份；迁移产生的同磁盘副本不能代替异机备份。
3. 预留完整工作区副本及数据库备份所需的物理空间。迁移不重置额度，也不删除超过默认额度的已有媒体。
4. 在服务器管理员 PowerShell 中准备以下变量（这里只引用路径，不修改配置）：

```powershell
$migrationPython = 'C:\Projects\ViralDNA\.server\tools\python\python.exe'
$migrationTool = 'C:\Projects\ViralDNA\scripts\maintenance\migrate-account-workspaces.py'
$migrationEnv = 'C:\Projects\ViralDNA\.server\config\api.env'
```

工具只需要 Python 标准库，直接运行仓库中的迁移代码，不依赖正在服务的旧编译版本。它不会读取密码并登录、连接 GitHub、上传资产、安装依赖或修改 IIS。测试机使用实际 Python 路径、源码位置和配置文件；配置必须明确包含身份库、账户目录登记及账户根目录三项绝对路径，不要覆盖现有配置。

## 1. 预览

```powershell
& $migrationPython $migrationTool --env-file $migrationEnv
```

输出每个账户的 UUID、名称、现有路径、目标路径及状态。`standard` 表示已经统一，`needs_migration` 表示需要迁移。预览使用只读数据库连接，不改业务记录、配置或账户绑定；SQLite 自身可能产生正常的 WAL/SHM 辅助文件。它不是数据库恢复命令，不会在缺少身份库时创建空数据库。

## 2. 停服后迁移一个明确账户

在部署菜单选择 **4**，停止本项目 API/Web；同时关闭直接启动的开发 API、旧版本进程及其他写入任务。手动 IIS 模式不操作 IIS，更不会停止其他网站。新版 API 持有迁移锁；旧版没有该锁，所以无论是否能获取锁，都必须确认所有 API 已停止。

重新预览，核对账户 UUID 与来源路径，然后将下面两个示例值替换为预览结果：

```powershell
& $migrationPython $migrationTool --env-file $migrationEnv --apply `
  --account-id '替换为预览中的账户UUID' `
  --source 'C:\Projects\ViralDNA\.server\data\legacy-workspace' `
  --confirm-api-stopped
```

工具只迁移指定账户，不会批量猜测目标；来源确认值必须与当前登记完全一致。身份库、账户目录登记不能放在待迁移工作区内；目标已存在、路径相互包含、身份不匹配、符号链接／目录联接或复制时仍发生写入都会中止，不覆盖或合并。

执行顺序为：

1. 获取与新版 API 互斥的迁移锁。
2. 在身份库旁的 `workspace-layout-backups\<时间戳-唯一ID>` 备份身份库、账户目录登记与迁移清单。包含身份信息，按私有备份管理。
3. 复制工作区到独立待完成目录；普通文件比较 SHA-256，SQLite 使用备份 API 包含已提交的 WAL 数据，并检查数据库副本。复制期间检测来源变化。
4. 保留所有业务 ID、账户归属、文件相对路径与存储额度；不重建成另一个账户。
5. 验证成功后发布目标目录，并在身份数据库事务中更新账户绑定，同时更新匹配的账户目录登记。
6. 输出完成报告、备份路径；原工作区不删除。普通异常会回退本次绑定及登记修改，未完成副本保留在账户根目录的 `.layout-*.pending`，不自动清理用户目录。

迁移期间突然断电或进程被强杀，不等同于正常异常回退。重新启动前先查看备份里的 `migration.json`、当前账户绑定和目标身份文件；若清单仍是 `prepared`，不要直接删除目标或恢复整份旧库覆盖其他账户。原工作区、迁移副本和数据库备份都保留，可据此核对后恢复。

重复执行先预览：账户已经指向标准目录时，用当前来源值执行会返回 `changed=false`；不要反复使用过时的来源路径。存在未完成副本时先核对失败原因，不用删除整个 accounts 目录解决冲突。

## 3. 启动与验收

1. 部署新版应用后，用菜单 2 编译启动，或在新版已成功编译后选 3。迁移工具不自动启动服务。
2. 登录原手机号，检查项目、资产、目录、采用状态、原图／视频读取和存储额度。
3. 企业成员应仍共享同一账户，其他账户不可访问这些文件。已有用户、密码和邀请关系不变。
4. 检查账户绑定已是 `accounts\<账户UUID>`；重启后不回退旧目录。
5. 完成验收和独立备份前保留旧目录。不要同时启动旧数据副本进行写入，也不要自动把旧目录当成同步源上传第二次。

跨机器把测试机资产导入正式账户属于[资产同步](资产同步与容量配置.md)，与本工具的“同一账户在同一台机器内调整物理目录”不同。本工具不会迁移 Windows DPAPI 密钥身份，不会重置、复制或合并不同账户。
