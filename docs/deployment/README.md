# 部署流程

状态：按当前仓库代码整理，2026-09-09。尚未接入真实目标服务器；这组文档不表示已经上线、上传真实资产或完成灾备演练。

## 按顺序操作

1. [本地环境与启动](本地环境与启动.md)：先验证本机运行，区分开发启动器和服务器常驻服务。
2. [服务器部署](服务器部署.md)：准备持久化目录、构建前端、启动单个 API 进程并配置 HTTPS。Windows 环境使用 [一键部署菜单](Windows服务器一键部署.md)。
3. [账户初始化](账户初始化.md)：在部署本机完成 admin 与首个账户设置，再开放外部访问。
4. [资产同步与容量配置](资产同步与容量配置.md)：核对目标账户后同步，设置个人／企业容量。
5. [升级备份与恢复](升级备份与恢复.md)：发布前备份，保留可恢复的数据与应用版本。
6. 仅当视频模型需要公网媒体地址时，配置 [OSS 媒体暂存](OSS媒体暂存配置.md)。

## 三种存储不要混用

| 用途 | 位置与生命周期 | 是否等同于长期云端保存 |
| --- | --- | --- |
| 本地工作区 | 当前电脑的账户媒体、数据库和任务结果 | 否；需要连接器上传并确认成功 |
| 账户服务器存储 | 目标服务器的持久化磁盘、账户账本和独立生成历史 | 是，但仍须单独备份；不代表磁盘永不损坏 |
| OSS 媒体暂存 | 向模型提供短期签名 URL，任务结束／租约到期后清理 | 否；不能把暂存 URL 作为资产主地址或备份 |

## 上线前必须明确

- 服务器操作系统、HTTPS 域名、运行服务的系统账户、持久磁盘位置和独立备份位置。
- 当前按单个 API 进程部署，不宣称支持多实例任务调度或 SQLite 网络共享盘。
- Windows 本机凭据采用 DPAPI；异机恢复、Linux 部署及相关本机能力必须分别验证，不直接照搬 Windows 密钥文件。
- 未收到明确授权，不上传已有账户资产、不重启正在执行真实任务的服务，也不自动向 GitHub 推送。

产品规则见 [账户与存储](../features/README.md)，历史方案见 [归档索引](../archive/README.md)，不要把历史批次文档当作部署步骤。
