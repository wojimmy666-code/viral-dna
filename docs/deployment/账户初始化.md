# 账户初始化

状态：现行流程。首次设置只在尚未初始化时执行；已开通系统不能通过删除数据库重新初始化。

测试服务器已经有账户、正式服务器完全为空且要完整迁入时，**不要在正式端重复初始化**，按[测试服务器整体迁入空正式服务器](测试服务器整体迁入空正式服务器.md)导入后使用原账号登录。

## 1. 操作前确认

- 等待真实分析、生成、同步和导出任务结束，并备份旧工作区及账户配置。
- 核实 API 实际使用的账户目录、身份数据库与旧工作区路径，避免用空目录启动后误以为旧数据丢失。
- 使用 `VIRAL_DNA_AUTH_MODE=password`，先限制服务在部署本机访问，初始化完成后再开放公网。

## 2. 首次设置

1. 在部署本机打开 `/login`；本地启动器默认地址为 `http://127.0.0.1:4174/login`。
2. 尚未初始化时，页面自动显示首次设置。不需要初始化码，不读取 token 文件，也没有默认密码。
3. 设置独立的 `admin` 密码。
4. 明确现有工作区属于个人账户还是企业账户，填写账户／企业名称、负责人手机号、姓名和前端密码。
5. 确认数据归属后提交。所有账户（包括首次账户）统一使用 `VIRAL_DNA_ACCOUNTS_ROOT\<账户UUID>`。全新安装直接创建标准目录，不创建特殊的 `legacy-workspace`。

如果配置的旧工作区已有数据，首次设置中的归属确认会授权将该工作区复制到标准账户目录：保留账户、工作区、项目及资产 ID，校验文件和 SQLite 副本后提交绑定，旧目录保留。不扫描或合并其他工作区。复制期间应停止全部旧进程和写入任务；大工作区须预留足够磁盘空间。

已经初始化的实例不会因升级自动搬动数据；请按[账户目录统一与旧账户迁移](账户目录统一与旧账户迁移.md)停服预览、备份并迁移，不删除身份数据库重新初始化。

前端登录名强制为中国大陆 11 位手机号，不能使用姓名或邮箱替代；手机号全局唯一。密码至少 8 位，不要求字母、数字和符号组合；当前输入上限为 128 个字符。

接口同时核验客户端为本机来源、请求使用本机 Host，并在事务中防止重复初始化。无桌面服务器可由部署管理员建立受控的本机访问通道，例如仅转发 loopback Web 端口的 SSH 隧道；必须核验实际请求满足本机限制。不要把初始化接口开放公网，不要通过关闭认证或放宽来源检查绕过限制。

## 3. 初始化后

| 入口 | 登录主体 | 能做什么 |
| --- | --- | --- |
| `/login` | 独立个人／企业用户，手机号登录 | 使用本账户项目与资产；企业成员共享本企业数据 |
| `/admin/login` | 固定 `admin` | 开通／停用账户、平台配置、手动容量调整 |
| 账户菜单「企业成员」 | 企业负责人 | 邀请、移除本企业成员；普通成员无此管理权限 |

两套会话独立。后台登录不等于进入某个前端账户，也不自动获得私有项目访问权。个人与企业不能在同一个登录用户下切换空间。

新账户通过后台开通，企业成员由负责人邀请；激活与密码重置链接经可信渠道交付，不写入文档、日志或 Git。忘记密码走重置流程，不删除认证数据库。

## 4. 无费用检查

- 新账户可以登录自己的空工作区；旧数据只出现在已确认归属的账户。
- 两个不同账户不能访问彼此项目、资产和媒体 URL。
- 同企业成员能看到共享数据，同时打开同一项目时仅一个会话可编辑。
- 停用账户、移除成员、修改密码后，旧会话或编辑权按规则失效。
- 原有生成历史仍可读取；如首次存储清点尚未完成，先等待清点，不重复初始化。

账户模型与编辑锁详情见 [独立账户与企业协作](../features/accounts/account-system-implementation.md)。下一步是 [资产同步与容量配置](资产同步与容量配置.md)。
