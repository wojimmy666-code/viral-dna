# 资产同步与容量配置

状态：功能已实现并经过隔离测试；实际服务器地址和目标账户尚未绑定，本轮没有上传真实资产。

## 1. 前置条件

- 发送端与接收端均运行兼容版本 ViralDNA，并分别完成 [账户初始化](账户初始化.md)。
- 接收端提供可验证证书的 HTTPS 源站、持久化磁盘和独立备份。
- 同步对象是当前本地账户登记的资产及生成历史，不扫描电脑全部目录，不读取其他账户资产，也不是项目数据库双向合并。
- 首次启用会后台清点现有媒体。清点完成前可浏览，但新的上传、生成及首次同步需要等待，不能绕过清点规避容量核算。

## 2. 配置目标服务器

1. 发送端 admin 进入「账户管理 → 同步服务器设置」。
2. 填写接收端 HTTPS 源站，例如 `https://video.example.com`，不要附带 `/api/v1`、路径、参数、账号或密码。
3. 此配置对应 `VIRAL_DNA_SYNC_SERVER_URL`。不要把接收端配置成向自身同步。

系统不接受 HTTP 或重定向作为同步目标。部署时如果 TLS 在反向代理终止，API 必须正确识别受信代理转发的 HTTPS scheme。

## 3. 连接并确认账户

1. 本地账户负责人进入「资产库 → 连接服务器并同步」，或账户菜单的存储管理。
2. 使用服务器账户的手机号与密码登录；目标须与本地账户同类型，个人不能连接到企业账户反之亦然。
3. 核对服务器地址、目标账户名称及归属后，明确确认目标账户。
4. 确认连接后，新生成结果开始自动上传；需要补齐历史存量时，再点击「一键同步到服务器」。

密码仅用于连接时登录，不作为长期同步凭据保存。连接器使用专门的可撤销设备令牌；令牌有效期 30 天，失效后由负责人重新连接。Windows 本地凭据使用 DPAPI，不能把凭据文件复制到另一台机器当作迁移登录。

## 4. 一键同步与恢复

- 保留资产名称、目录、标签、媒体原件及生成时的提示词／模型等元信息。
- 内容按 SHA-256 去重；分块上传、断点续传，完整文件校验且服务端登记成功后才确认已同步。
- 同一账户反复点击不会因为同名而重复造资产；服务器上的人工修改优先保留，不静默覆盖。
- 关闭浏览器不停止本地 API 的任务；电脑关机或 API 停止期间不会上传，重新启动后恢复。
- 失败可重试；短期断线保留断点。分块 7 天无活动后可清理临时断点，从保留的本地原件重新传输，不删除长期原件。
- 更换目标必须先断开、重新登录并确认。同一目标保留同步记录；不同目标重新核算待同步内容。
- 本地原件保留。提示“已生成但待同步／容量不足”时不等于云端已保存，必须排查后重试。

## 5. 容量配置

| 账户 | 默认额度 | 计量范围 |
| --- | --- | --- |
| 个人 | 2 GB | 该账户资产与生成结果 |
| 企业 | 10 GB | 所有成员共享，不按成员重复分配 |

1 GB = 1,000,000,000 字节。账户内相同原件只计一次，加入资产库不重复计量；系统缩略图、可重建缓存不计用户额度，回收站仍占容量。

在**目标服务器**用 admin 打开「账户管理 → 用户与容量」，核对账户名称，输入新额度及备注后保存。调整留有审计记录，不得低于已用与预留之和；本期没有在线购买或自动升级。

新的任务先检查／预留容量。实际产物超出估算时优先保全已生成文件，再阻止新的任务；若服务器暂时无法接收，完整结果仍保留在本地等待扩容，不伪报上传成功。额度是逻辑限制，管理员还需另行监控物理磁盘及备份空间。

## 6. 本地清理与云端清理

生成历史独立于“采用”及“加入资产库”；再次生成或删除项目不会自动删除独立历史。

本地存储页管理的是本地记录。释放云端容量，需要使用页面里的「服务器存储管理」入口，在服务器账户上明确操作。两边回收站独立，本地删除不向服务器传播，服务器已永久删除的记录也不会被普通重试自动恢复。

永久删除必须先移入回收站、明确确认，且不能仍被项目、资产或时间线引用。不要手工删除媒体目录来绕过引用检查。

## 7. 实际接入验收

先使用少量测试资产验证目录、名称、校验和、预览／下载、重复同步、断线恢复和容量拦截；确认后再同步真实存量。大批真实文件开始传输前，应向账户负责人说明目标、数量与预计容量。

技术边界见 [账户存储、生成历史与同步](../features/accounts/account-storage-and-sync.md)，与 [OSS 临时媒体中转](OSS媒体暂存配置.md) 无关。
