# 本地环境与启动

状态：现行流程，依据仓库启动器与依赖清单整理；以下命令在仓库根目录执行。不要在真实分析、生成或导出任务运行时重启服务。

## 1. 环境准备

- Windows；Node.js 20.19+、npm、Python 3.11+。
- 媒体分析、预览与导出需要可执行的 FFmpeg 和 ffprobe；可用 `VIRAL_DNA_FFMPEG_PATH`、`VIRAL_DNA_FFPROBE_PATH` 指定路径。
- ASR／OCR 为可选依赖；本机图片和深度推理工具也需要独立配置，启动网站不等于这些工具已经可用。

只读检查：

```powershell
node --version
npm --version
python --version
ffmpeg -version
ffprobe -version
```

## 2. 启动现有项目

```powershell
.\scripts\start.bat --no-browser
```

启动器会检查依赖、API 进程与工作区 Schema；若现有 ViralDNA API 已过期，可能受控重启。发现其他程序占用端口时会报错，不应手动按端口批量结束进程。

入口路径保持不变，内部实现位于 `scripts/dev/`；本机 ImageGen 适配器位于 `scripts/imagegen/`。不要再引用整理前的根目录内部脚本路径。正式 Windows 服务使用独立的 [部署入口](Windows服务器一键部署.md)。

- 前端：`http://127.0.0.1:4174`。
- API 健康检查：`http://127.0.0.1:8000/health`。
- 不带 `--no-browser` 时会打开浏览器。
- 首次启动后按 [账户初始化](账户初始化.md) 操作，不需要初始化码。

常规双击模式会打开 API／Web 终端；关闭对应的本项目终端或使用其 `Ctrl+C` 停止。若使用外部项目启动器的 managed 模式，则通过该启动器停止，避免留下重复进程。

## 3. 手工开发启动

仅新环境缺少虚拟环境时执行 `python -m venv .venv`，不要覆盖现有运行环境。

```powershell
npm ci
.\.venv\Scripts\python.exe -m pip install -e "services/api[dev]"
```

需要本地 ASR／OCR 时再安装可选依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -e "services/api[local-ai]"
```

分别在两个终端运行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn viral_dna_api.main:app --app-dir services/api/src --host 127.0.0.1 --port 8000
```

```powershell
npm run dev:web -- --host 127.0.0.1 --port 4174 --strictPort
```

手工运行 Web 时也应限制到 loopback；不要把 Vite 开发服务器当作公网生产服务器。

## 4. 配置与检查

以 [环境变量示例](../../.env.example) 为字段参考，不覆盖已有 `.env.local`。API 配置优先读取进程环境，其次读取 `.env.local`；可通过进程环境 `VIRAL_DNA_ENV_FILE` 指定独立文件。Vite 的前端变量属于构建／开发配置，不会自动等同于 API 配置文件。

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8000/health
npm run test:web
npm run build:web
```

健康响应应标识 `service=viral-dna-api`；构建成功只表示前端可打包，不表示模型凭据、真实生成和远端同步已验证。真实生成会消耗费用／配额，需单独确认后执行。

服务器长期运行请继续阅读 [服务器部署](服务器部署.md)，不要复用开发终端作为无人值守服务。
