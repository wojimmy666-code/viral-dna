# Phase 2：可组合视频生成输入与模型能力路由

> 状态：已实现第一版契约、后端路由与分段视频工作台；普通动作／参考视频的素材绑定接口已预留，只有模型目录声明能力且存在实际绑定时才允许提交。

## 1. 目标

视频生成不再被固定成“确认分镜图 + 资产 + 深度视频”的单一路径。每个分镜独立保存一份生成输入计划，用户可以按模型能力组合：

- 仅提示词：文生视频；
- 提示词 + 已确认分镜图；
- 提示词 + 人物、场景、服装或产品等项目图片资产；
- 提示词 + Provider 托管人物；
- 提示词 + 动作／参考视频；
- 提示词 + 深度控制视频；
- 上述媒体输入的合法组合。

提示词始终存在，不做开关。音频不属于视频模型生成输入：原声、配乐、音量、淡入淡出和混音统一由独立视频剪辑模块处理。

## 2. 领域契约

### 2.1 `VideoGenerationInputPlan`

```json
{
  "schema_version": "viral-dna-video-input-plan/v1",
  "sources": ["project_assets", "depth_control"]
}
```

可选 `sources` 只有：

| 值 | 含义 | 前置校验 |
| --- | --- | --- |
| `approved_images` | 已确认分镜图片 | 必需画面均已确认 |
| `project_assets` | 提示词中关联的项目图片资产 | 资产存在、未归档、权利已确认 |
| `provider_managed_assets` | Provider 托管人物 | 模型支持、Provider 匹配、已绑定 |
| `reference_video` | 动作或镜头参考视频 | 模型支持且分镜已绑定视频素材 |
| `depth_control` | 全场景深度控制视频 | 模型支持且存在已启用、质检通过的深度资产 |

契约中没有 `audio`。后端、前端和测试均禁止把音频作为生成输入来源。

### 2.2 粗粒度输入模式

输入计划保留精确来源，`input_mode` 只用于统计和兼容旧记录：

- `text_to_video`
- `image_to_video`
- `multi_image_to_video`
- `video_to_video`
- `hybrid_reference_to_video`

任务完成后以实际提交给 Provider 的图片、托管资产和控制视频数量重新计算模式，避免仅凭 UI 开关误判。

### 2.3 模型能力

`VideoGenerationCapability` 独立声明：

- `text_to_video`
- `image_to_video`
- `reference_video`
- `depth_control_video`
- `managed_assets`
- `reference_route`
- `supported_input_sources`（由上述能力计算并随模型目录返回）

前端不按厂商名称猜测能力。切换模型后，不受支持的新输入不能勾选；已经勾选但新模型不支持的输入仍可取消，不会把用户锁死在错误状态。

## 3. 请求与执行流程

1. 用户修改提示词、模型或输入开关；非 Revision 级的生成设置写入分镜草稿。
2. 点击生成时先保存提示词，使用服务端返回的新 Revision。
3. 请求同时提交 `input_plan`；后端根据实际输入生成最终 `input_mode`。
4. 后端只校验用户主动选择的输入，不再全局要求确认图片或深度视频。
5. Provider 网关只解析、暂存并发送被选择的素材。
6. 输入快照写入精确计划、最终路由清单和被排除素材，便于成本审计与问题定位。
7. 生成视频本身不带入原声；进入视频剪辑后再处理音轨。

## 4. UI 规则

“生成输入”位于视频提示词之前：

- “提示词”固定选中，并提示“生成前自动保存”；
- 其余来源是紧凑的多选卡片；
- 卡片显示已确认图片数、已关联资产数或托管人物名称；
- 不支持的能力显示“当前模型不支持”；
- 未选择任何媒体时显示“文生视频”；
- 深度控制面板仅在主动选择“深度控制”后出现；
- 已确认分镜故事板仅在主动选择“分镜图片”后出现；
- 页面不提供任何音频生成选项。

## 5. 兼容边界

- 新建分镜草稿默认是文生视频，避免无意上传原视频或真人素材。
- 旧生成任务没有 `input_plan` 时，按“已确认分镜图”读取，不会错误要求项目资产。
- 不迁移、覆盖或自动勾选用户已有的项目资产、托管人物和深度控制。
- 普通动作／参考视频当前采用能力门控：模型与素材绑定任一缺失时禁用或阻止提交，不会暗中把完整原视频发送给 Provider。

## 6. 自动化回归

重点覆盖：

- 输入来源唯一性、模式推导及音频缺席；
- 草稿保存、重启恢复与旧任务回填；
- 文生视频、单图、多图、图片 + 深度混合模式；
- 模型能力目录与 Provider 路由；
- 未选择项目资产时不会触发资产必填；
- 旧的有序多图、托管人物和深度控制流程继续可用；
- 前端生成前自动保存提示词并提交 `input_plan`。

## 7. 人工验收

### 7.1 文生视频

1. 进入“创作方案 → 分段视频”。
2. 选择支持文生视频的 Seedance 2.0 或 MiniMax H3。
3. 保持全部可选媒体未选中，确认模式显示“文生视频”。
4. 修改提示词并点击生成。
5. 确认提示词已自动保存，任务没有要求分镜图片、资产或深度视频。

### 7.2 分镜图片

1. 勾选“分镜图片”。
2. 若必需画面未确认，生成按钮应给出明确阻止原因。
3. 确认画面后再次生成，输入快照只应包含已确认画面，不应自动加入项目资产。

### 7.3 项目资产

1. 在图片提示词中通过 `@目录/资产` 关联人物或场景图。
2. 勾选“项目资产”，确认卡片数量正确。
3. 生成后检查任务输入快照：只包含实际关联且已确认使用权的图片资产。

### 7.4 托管人物与深度

1. 选择支持托管人物的 Seedance，并绑定一个 Provider 演员。
2. 只勾选“托管人物”时，不应再强制要求深度视频。
3. 额外勾选“深度控制”后，深度面板才出现；没有可用深度资产时应阻止生成。
4. 生成并启用深度资产后，确认请求同时包含演员 Asset ID 和深度视频 URL。

### 7.5 模型切换与音频边界

1. 勾选一个仅部分模型支持的输入后切换模型。
2. 不支持的已选输入应显示异常状态，但仍能点击取消。
3. 检查整个“生成输入”区域，没有音频开关、音频上传或生成音频参数。
4. 进入视频剪辑，确认原声和附加音轨仍由剪辑模块处理。
