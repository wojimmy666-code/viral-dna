# 分镜自由数量与恢复验收

## 已实现规则

- Skill 的镜头数量、范围与案例密度只作为创作建议；生成、编辑保存、生产种子和视频时间线不设镜头数量上限。
- 接受任意非零镜头列表，不按目标数量补齐、裁减或重试。0 个镜头允许保留编辑草稿，但禁止人工确认与进入生成。
- 人工增删保留已有稳定镜头 ID、提示词及历史产物，同步段落引用、实际数量与时长。目标时长容不下全部镜头时保留全部镜头与正帧长，页面提示时长差异。
- 文案调用前记录模型；心跳仅更新存活时间，不模拟完成百分比。终止时读取最新进度，显示模型、结束时间、耗时和具体错误。
- 模型完整返回及逐镜完成结果保存为持久化检查点。失败时展示已编译草稿；恢复复用结果、跳过完成镜头，不再次计算已发生的费用。
- 检查点绑定简报、风格、Skill、运行契约、素材与声明。草稿已有人工修改时禁止恢复覆盖；继续处理与重新生成按真实恢复能力显示。
- 服务重启后先恢复检查点状态，不自动重发模型请求。

## 人工验收

1. 刷新 Skill 的“大纲与分镜”页，历史失败任务应显示结束时间与实际耗时，不再显示运行中心跳。
2. 用户主动重新生成后，13 个镜头不会再因“不等于 15”失败。
3. 修改、增加、删除镜头，等待保存并刷新，核对内容与稳定顺序。
4. 测试环境模拟编译失败后，应显示已完成草稿与“继续处理”；修改草稿后，不允许旧任务覆盖。

本次未调用真实文案、图片或视频模型。旧失败任务若没有保存原始返回，无法直接恢复其中的 13 个镜头，需要由用户主动重新生成；旧错误记录不会被伪造为成功。
