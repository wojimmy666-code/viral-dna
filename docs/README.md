## 目录边界

- `architecture/`：架构、数据模型和输入协议；原始设计里的规划段落不自动代表已实现。
- `features/`：当前功能规则；部署操作链接到专门的部署文档。
- `deployment/`：安装、启动、初始化、同步、升级和备份恢复，注明实际验证范围。
- `design/`：唯一 UI 设计契约的入口及参考图，不再维护另一套字体规范。
- `qa/`：按功能分类的验收记录，截图放 `screenshots/`；旧测试结果保留原日期和范围。
- `roadmap/`：待确认／待核对的规划，不能当作当前产品能力或上线承诺。
- `archive/`：已被替代的计划和实现记录，只用于追溯。

## 维护规则

1. 新文档放入对应目录，根目录只保留本索引；优先更新同主题文档，避免每次微调新增重复说明。
2. 标明现行、规划或历史，以及适用范围和验证日期；未做付费验收、尚未上线必须明确保留。
3. 规范以 [Web 设计契约](../apps/web/DESIGN.md) 和实际代码为准；有冲突先核对代码与用户确认，不把旧计划直接改写成已完成。
4. 移动文件同时更新 Markdown 链接、根 README 和截图引用；只删除已确认无独立价值的内容。
5. 文档不保存密码、Cookie、令牌、签名下载地址和真实用户资产；部署实例配置应脱敏。
6. 文档变更后运行 `node scripts/check-docs.mjs`，检查链接、引用和索引覆盖。
