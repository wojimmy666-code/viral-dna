## 1. 本批次目标

将当前“临时分析一次”的原型升级为可长期使用的本地项目工作台：用户可以指定一个本地工作区，视频源文件、分析产物和导出文件统一归档；分析记录可检索、重命名、归入一级目录并重复打开；所有面向用户的中文结果统一为简体中文。

本批次不实现账号分析、多级目录、记录删除、云同步、多人协作和视频生成模型对接。

## 2. 核心设计

### 2.1 单一活动工作区

- 系统同一时间只使用一个活动工作区。
- 首次升级默认兼容仓库现有的 `storage/`，也允许在 GUI 中填写并切换到其他绝对路径。
- API Key 等密钥继续保存在应用配置中，不写入工作区。
- 切换工作区前执行可写性和目录结构校验；失败时不改变当前工作区。
- 工作区路径写入本机运行配置，重启后自动恢复。

### 2.2 工作区目录

```text
<workspace>/
├─ .viraldna/
│  ├─ workspace.json
│  └─ workspace.db
├─ records/
│  └─ <record_id>/
│     ├─ source/
│     │  ├─ original.<ext>
│     │  └─ metadata.json
│     ├─ analyses/
│     │  └─ <analysis_id>/
│     │     ├─ report.json
│     │     ├─ timeline.json
│     │     ├─ proxy.mp4
│     │     ├─ audio.wav
│     │     ├─ subtitles.srt
│     │     ├─ model-responses/
│     │     └─ shots/
│     └─ exports/
│        └─ <analysis_id>/
└─ temp/
```

数据库和 JSON 元数据只保存相对工作区路径。物理目录使用稳定 UUID，记录或目录改名不移动底层文件。

### 2.3 数据对象

- `Folder`：一级逻辑目录，只有名称和排序信息；空目录归属显示为“未分类”。
- `AnalysisRecord`：一个被分析的视频项目，拥有名称、来源、目录、视频 ID、最新分析 ID、状态和时间信息。
- `AnalysisJob`：一次具体分析。同一记录重新分析会创建新版本，不覆盖旧结果。
- `ExportArtifact`：由服务端生成并归档的报告、提示词包、转写或字幕文件。

### 2.4 兼容与迁移

- 保留旧 `stored_path` 和旧产物 URL 的兼容读取。
- 首次打开旧工作区时，将现有视频和报告补建为分析记录。
- 旧文件采用“复制、校验、登记”的迁移策略，不自动删除原文件。
- 数据库使用显式 schema 版本；迁移失败时保留原数据库并返回可读错误。

### 2.5 简体中文边界

- ASR、字幕、OCR 和模型原始证据保持原文，便于审计。
- 写入报告、时间轴可读字段和导出文件前统一执行繁体转简体。
- 模型提示中明确要求返回简体中文，服务端仍做确定性兜底转换。
- 旧报告在迁移时生成简体化版本，不破坏原始证据文件。

## 3. API 计划

### 工作区

- `GET /api/v1/workspace`：读取活动工作区和统计信息。
- `POST /api/v1/workspace/validate`：验证候选目录。
- `PUT /api/v1/workspace`：创建或切换活动工作区。

### 一级目录

- `GET /api/v1/folders`
- `POST /api/v1/folders`
- `PATCH /api/v1/folders/{folder_id}`

### 分析记录

- `GET /api/v1/records`：支持关键词、目录、状态和排序查询。
- `GET /api/v1/records/{record_id}`：返回记录、视频、分析版本和最新报告。
- `PATCH /api/v1/records/{record_id}`：重命名或移动至一级目录。
- `POST /api/v1/records/{record_id}/analyses`：基于原视频创建新分析版本。

### 导出

- `POST /api/v1/records/{record_id}/exports`
- `GET /api/v1/records/{record_id}/exports`
- `GET /api/v1/exports/{export_id}/download`

## 4. 前端计划

- 在“模型与设置”中加入工作区卡片：显示路径、状态、磁盘写入校验结果以及切换入口。
- 将侧边栏“分析记录”从占位导航升级为记录页。
- 记录页提供关键词搜索、一级目录筛选、状态筛选、时间排序和卡片／列表展示。
- 支持新建／重命名一级目录、重命名记录、移动记录。
- 点击记录恢复视频、报告、镜头、爆点和提示词，无需再次调用模型。
- 在报告页提供重新分析入口，并清晰展示历史分析版本。
- 下载和导出均由服务端归档后再提供下载。

## 6. 验收标准

- 用户可通过 GUI 指定可写的本地工作区，重启后仍使用该路径。
- 上传和链接下载的视频进入对应记录的 `source/`；新分析产物进入对应 `analyses/<analysis_id>/`。
- 关闭并重新启动服务后，历史记录、目录、报告和视频仍可查询和打开。
- 记录可搜索、重命名、移动到任意一级目录；目录可创建和重命名。
- 重复打开历史记录不会产生模型费用；手动重新分析才创建新任务和新成本记录。
- 提示词包、报告、旁白／转写和字幕导出文件保存在工作区并可下载。
- 所有面向用户的中文报告和导出内容为简体中文；原始证据仍可追溯。
- 旧 `storage/` 数据升级后仍可读取，迁移过程不删除原文件。
- 后端测试、前端构建和 Sites 兼容测试全部通过。
