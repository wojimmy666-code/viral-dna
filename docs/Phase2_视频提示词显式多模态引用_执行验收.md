# Phase 2：视频提示词显式多模态引用

更新时间：2026-08-19

## 1. 目标

视频提示词不再只是一段无法追踪来源的文字。用户可在提示词中输入 `@`，显式选择本次生成要使用的具体对象：

- 项目图片资产，例如 `@资产/小喵酱/面部`；
- 已采用分镜图，例如 `@分镜图/图1-人物出场`；
- Provider 托管角色，例如 `@托管角色/小喵酱`；
- 已启用深度视频，例如 `@深度视频/分镜动作1`；
- 已绑定的普通参考视频，例如 `@参考视频/舞蹈动作`。

界面展示可读名称，持久化数据使用对象 UUID。目录或资产名称变化不会改变对象身份，也不会把名称当作 Provider 的真实参数。

## 2. 数据契约

`ShotPlan.video_prompt_mentions[]` 是提示词引用的唯一事实来源：

```json
{
  "reference_kind": "project_asset",
  "reference_id": "0e65c993-3487-4ec6-9801-c9de5d72f4bb",
  "label": "资产/小喵酱/面部",
  "role": "actor_identity",
  "order": 1
}
```

支持的 `reference_kind`：

| 类型 | 对应生成输入 | 典型用途 |
| --- | --- | --- |
| `project_asset` | `project_assets` | 人物、场景、服装、产品外观 |
| `approved_image` | `approved_images` | 构图、首帧和画面顺序 |
| `provider_managed_asset` | `provider_managed_assets` | Seedance 等模型的托管人物身份 |
| `reference_video` | `reference_video` | 动作或运镜参考 |
| `depth_control` | `depth_control` | 动作、空间深度和遮挡关系 |

`role` 明确素材职责。Provider 编译器必须保持职责隔离，禁止把动作参考中的人物身份、场景或服装错误继承到结果中。

## 3. UI 与交互

1. 在“视频提示词”输入框输入 `@`。
2. 弹出素材选择器，按项目图片、已采用分镜图、托管角色、深度视频和参考视频分组展示。
3. 选中后插入可读标记，并在输入框下方显示引用标签。
4. 点击标签右侧删除按钮会同时删除正文标记和结构化引用。
5. 选择引用会自动启用相应的“生成输入”；用户仍可查看生成输入计划。
6. 如果用户关闭引用所需输入、删除正文标记、切换到不支持该输入的模型，生成按钮被禁用并给出具体原因。
7. 点击生成时先自动保存提示词、负面约束和结构化引用，再创建视频任务。

## 4. Provider 编译

后端按引用顺序解析素材并建立不可变输入快照：

- 图片引用进入有序 `reference_frames`；
- 托管角色进入 Provider `asset://` 绑定；
- 深度视频经媒体暂存服务自动上传私有 OSS，并使用短期签名 HTTPS URL；
- 引用清单写入 `reference_manifest.prompt_mentions`，用于成本审计、故障诊断和结果复现；
- 正向提示词增加中文职责约束，例如“`@资产/小喵酱/面部：人物身份`”。

没有对应能力的模型不会收到不支持的输入。普通参考视频只有在分镜已经建立有效视频绑定后才出现在 `@` 菜单中；系统不会把原视频偷偷作为普通参考视频提交。

## 5. 服务端校验

保存提示词时校验：

- 项目资产存在、未归档且已确认使用权；
- 分镜图片仍处于已采用状态；
- 托管角色已绑定到当前分镜；
- 深度视频已启用且通过可用性校验；
- 普通参考视频已绑定、已启用且媒体类型为视频；
- 同一个对象不能重复引用，顺序必须唯一。

生成视频时再次校验：

- `@标记` 仍存在于提示词正文；
- 对应生成输入已启用；
- 当前模型声明支持所需图片、托管角色、普通视频或深度视频能力；
- Provider Key、媒体暂存和引用数量满足模型限制。

## 6. 人工验收

### 6.1 项目人物资产 + 深度视频

1. 打开一个已存在人物资产、已生成深度视频的分镜。
2. 在视频提示词输入 `@`，选择人物资产和深度视频。
3. 确认提示词出现两个可读标记，下方出现两个可删除标签。
4. 打开“查看生成输入计划”，确认项目资产和深度控制均已启用。
5. 点击生成，确认无需单独点击“保存提示词”。
6. 查看任务输入快照，确认包含两个稳定 UUID 和各自职责。

### 6.2 Seedance 托管角色

1. 选择支持 Provider 托管角色的 Seedance 模型并绑定演员。
2. 输入 `@`，选择该托管角色。
3. 确认生成输入自动包含托管人物，提示词中不需要手写 Asset ID。
4. 切换到不支持托管角色的模型，确认生成按钮被禁用并提示切换模型。

### 6.3 删除与失效

1. 点击某个引用标签的删除按钮，确认正文中的同名 `@标记` 同步删除。
2. 重新插入引用后，手工关闭对应生成输入，确认生成按钮被禁用。
3. 删除正文中的 `@标记`，确认结构化引用自动清理。
4. 重载页面，确认正文、引用标签、输入计划和顺序保持一致。

## 7. 当前边界

- 本阶段不提供任意本地视频直接上传为普通参考视频的入口；只有已建立绑定的视频和深度控制视频可显式引用。
- 每种模型最终如何映射输入仍由独立 Provider Adapter 决定，前端不拼装厂商请求。
- 引用名称只服务于阅读和编辑，任何 Provider 调用都必须使用已校验 UUID 解析出的真实对象。
