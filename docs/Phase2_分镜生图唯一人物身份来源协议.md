# Phase 2：分镜生图唯一人物身份来源协议

更新日期：2026-08-14
协议版本：`exclusive-identity-source/v1`

## 1. 目标

当分镜绑定人物身份资产时，系统不能再把原视频关键帧人物和参考人物当成权重相近的普通参考图。两张输入图必须承担互斥职责：

- 图像 1：原视频关键帧，只提供姿态、构图、动作关系、机位、运镜意图和光影逻辑；
- 图像 2：唯一人物身份来源，提供年龄、五官、脸型、肤色和可识别身份；
- 其他图像：按产品、服装、场景、风格或布局角色依次附加；
- 图像 1 与图像 2 冲突时，人物身份服从图像 2，姿态与构图服从图像 1。

该协议解决的是输入职责、排序、提示词和失败边界。它不会把普通多图模型虚构成专用 FaceID 模型，也不等同于已经实现自动人脸相似度验收。

## 2. 数据与排序契约

每个分镜当前最多允许一个 `ReferenceRole.IDENTITY` 绑定。人物身份资产必须是 `ReferenceAssetType.PERSON`。

图片输入按以下稳定顺序编译：

1. 原视频关键帧；
2. 唯一人物身份资产；
3. 产品；
4. 服装；
5. 场景；
6. 风格；
7. 道具或布局。

同角色内才继续按绑定权重和创建时间排序。身份资产不会再因为权重较低而落到图像 3 或更后面。

## 3. 强校验

以下情况在生成任务入队前直接阻止：

| 错误码 | 条件 | 用户处理 |
| --- | --- | --- |
| `multiple_identity_references` | 同一分镜绑定多个身份来源 | 只保留一个人物身份资产 |
| `identity_asset_type_invalid` | 非人物资产被标为人物身份 | 更正资产类型或参考角色 |
| `identity_asset_missing` | 已绑定的身份资产不存在或已归档 | 重新选择人物身份资产 |
| `identity_requires_reference_mode` | 有身份资产却选择纯文生图 | 使用关键帧编辑（文字 + 图片） |
| `identity_source_keyframe_required` | 有身份资产但没有图像 1 | 先从视频选择关键帧 |
| `identity_reference_missing` | 身份绑定存在，但身份图未进入实际模型输入 | 重新保存参考绑定后再生成 |
| `identity_model_unsupported` | 模型不支持图生图或多图参考 | 切换支持多图参考的模型 |
| `reference_count_unsupported` | 参考资产数量超过模型参考图上限 | 减少其他参考图或切换模型 |
| `identity_input_count_unsupported` | 模型输入图上限不足 | 减少其他参考图或切换模型 |

Gateway 在真正调用 Provider 前会再次执行同一校验，防止后台任务恢复、旧客户端或直接 API 调用绕过入口规则。

## 4. 提示词编译

身份模式下，系统在用户图片提示词之前写入不可含糊的职责声明：

- 严禁从图像 1 继承人物年龄、五官、脸型、肤色、发型和身份；
- 图像 2 是人物身份唯一来源；
- 不得融合图像 1 与图像 2 的脸，不得生成第三个人物身份；
- 发生冲突时，身份服从图像 2，动作与构图服从图像 1。

负面约束会优先加入身份漂移、面部融合、双人脸、人脸重影和第三身份等约束。Codex ImageGen 本机适配器也会用中文职责标签再次标注每张图，避免底层工具只看到通用的 `source` / `identity` 字段。

## 5. 工作台交互

- 点击“生成候选”时，先保存当前图片提示词、`@资产`、负面约束和参考绑定，再用返回的新 Revision 入队；
- AI 生图设置中显示“本次将发送给模型”的真实顺序预览，包含缩略图、图像编号和职责；
- 有人物身份资产时显示“身份来源已锁定”，并禁用纯文生图；
- 第二个人物资产默认不会再次成为身份角色；身份下拉选项也会防止创建第二个身份来源；
- 生成完成后，`GenerationRunResponse.execution_summary` 保存实际 `identity_policy` 与 `input_manifest`，用于问题追踪。

## 6. 输入快照与审计

`input.json`、结果 `manifest.json` 和 GenerationRun 执行摘要会记录：

- 协议版本；
- 唯一身份资产 UUID；
- 图像 1 身份继承为 `forbidden`；
- 冲突规则为 `identity_reference_wins`；
- 每张实际输入图的编号、角色和职责。

上述字段参与请求指纹。身份协议或输入顺序改变后不会错误命中旧缓存。

## 7. 当前边界与后续增强

当前已完成的是“输入与指令层硬约束”，仍需人工确认最终人物是否足够相似。后续可在不改变本协议的前提下追加：

1. 人物资产自动选脸／裁脸，为模型增加高质量面部近景；
2. 对图像 1 的人脸区域做弱化或遮罩，只保留身体姿态与构图；
3. 使用独立人脸嵌入模型计算候选与身份资产的相似度；
4. 相似度未达阈值时标记候选失败或要求人工复核；
5. 将当前分镜级身份绑定进一步细化为画面级身份绑定。

这些能力未实现前，UI 和报告不得显示“身份一致性自动通过”。

## 8. 人工验收

1. 打开含原视频人物的分镜，绑定一个人物类型资产并设为“人物身份”。
2. 在图片提示词中输入 `@人物资产`，不先点击保存，直接点击生成。
3. 核对“本次将发送给模型”：图像 1 是原关键帧，图像 2 是人物资产，且缩略图正确。
4. 核对纯文生图选项不可选，页面显示“身份来源已锁定”。
5. 生成完成后检查工作区对应 `input.json`：`identity_policy.enabled=true`，`primary_identity_asset_id` 正确，`input_manifest[1]` 为唯一身份来源。
6. 查看正向提示词，必须包含“严禁从图像1继承”和“身份一律服从图像2”；负面提示词包含“混合图像1与图像2的人脸或身份”。
7. 尝试把第二个人物资产也设为身份，确认 UI 不允许；直接调用接口时应返回 `multiple_identity_references`。
8. 人工比较候选与人物资产的年龄、五官、脸型和肤色。若仍不够相似，记录为模型能力／后续 FaceID 质检问题，而不是误判为参考图未发送。
