# Phase 2 Batch 4.8：质量、安全与成本执行计划

更新时间：2026-08-12

阶段状态：进行中；Batch 4.8.1“质量基线与黄金样本回归”和 Batch 4.8.2“跨分镜连续性质检”已完成，Batch 4.8.3～4.8.6 尚未实施。

## 1. 阶段目标

Batch 4.8 不增加新的图片或视频生成模型，而是在现有单视频分析、生成、剪辑和导出闭环之上补齐可持续运行所需的治理能力：

1. 用黄金样本阻止分镜数量、绝对时间、提示词、运镜和转场语义静默退化；
2. 对相邻分镜的人物、服装、产品、场景、动作阶段和镜头方向进行连续性质检；
3. 对人物肖像、参考资产、源视频和导出产物建立可审计的权利链路；
4. 对工作区容量、缓存、归档、删除、恢复和孤立文件建立配额与治理规则；
5. 汇总项目、阶段、分镜和单次调用四级成本，并明确区分估算、实扣、订阅配额和未知成本；
6. 建立服务重启、任务中断、Provider 超时和文件损坏情况下的恢复回归。

## 3. 分批范围

### 3.1 Batch 4.8.1：质量基线与黄金样本回归

首批使用纯本地、确定性规则，不调用模型，不产生费用：

- 建立版本化 `viral-dna-golden-analysis-v1` 期望契约；
- 检查源视频 SHA-256、分镜数量、绝对开始／结束时间和相邻边界；
- 检查提示词必须语义、禁止语义、运镜阶段和出场转场类型；
- 检查画面事实和运镜阶段是否落在当前分镜绝对时间范围内；
- 生成稳定报告指纹、期望指纹、质量分数和机器可读发现列表；
- 提供 CLI，供开发者、CI 或人工验收对归档报告运行回归。

本批不把用户源视频、Cookie、API Key 或未脱敏报告提交到仓库。仓库只保存期望契约、合成测试和执行工具；真实报告保留在用户工作区或受控 CI 制品中。

## 4. Batch 4.8.1 契约

黄金样本期望文件至少包含：

  "sample_id": "spring-ribbon-transition-v1",
  "name": "丝带遮挡转场分析基线",

  "minimum_score": 100,

## 5. CLI

```powershell
.\.venv\Scripts\python.exe -m viral_dna_api.quality `
  --expectation D:\quality\spring-transition.expectation.json `
  --report D:\quality\spring-transition.report.json `
  --output D:\quality\spring-transition.result.json
```

退出码：

- `0`：通过；
- `1`：报告有效，但发生质量回归；
- `2`：期望或报告文件无法读取／不符合 Schema。

## 6. 质量门禁原则

1. 黄金样本只比较稳定、经过人工确认的事实，不逐字冻结整份模型输出；
2. 分镜数量、绝对时间污染和源视频指纹错误属于硬错误；
3. 相邻分镜轻微时间空洞可记警告，重复从 0 秒开始属于硬错误；
4. 新增黄金样本必须记录来源、用途、权利状态和批准人；
5. 更新期望值必须经过差异审阅，禁止为了让失败测试通过而直接覆盖基线；
6. 回归引擎自身不访问网络、不读取模型 Key，也不产生模型费用。

## 7. Batch 4.8.1 验收标准

- 稳定报告得到 100 分并以退出码 0 结束；
- 分镜重复从 0 秒开始时产生 `timeline_overlap` 和 `shot_start_drift`；
- 关键运镜或遮挡转场语义丢失时产生明确发现；
- 禁止语义重新出现时回归失败；
- 报告 ID 和生成时间变化不改变质量指纹；
- CLI 可输出版本化 JSON 结果；
- API、Web、Ruff 和生产构建基线保持通过。

## 8. 后续边界

Batch 4.8 的连续性“检查”与候选 Batch 4.9 的连续性“桥接生成”不同：前者发现和阻止问题，后者生成中间关键帧及桥接视频。Batch 4.8 不提前实现 Batch 4.9，也不接入新的付费模型。
