# Phase 2 Batch 4.5.3：视频体验与音轨衔接执行与验收

更新时间：2026-08-07  
状态：已实现，待人工验收

> 2026-08-11 架构迁移：本文件保留 Batch 4.5.3 的历史实现记录。当前产品已将逐分镜“剪辑准备”UI、裁剪、封面、音轨和质检迁移到下一阶段的独立“视频剪辑”模块；视频候选确认采用后即可推进。`VideoClipPreparation` 与原 API 仅用于读取旧项目和兼容迁移，不再是新流程门禁。当前验收请以 [独立视频剪辑模块重构执行验收](./Phase2_独立视频剪辑模块重构_执行验收.md) 为准。

## 1. 本批目标

Batch 4.5.3 位于“视频候选审核”和“剪辑时间线”之间，负责把一个已采用的视频候选转换为可供剪辑阶段稳定读取的片段定义。

本批不修改或覆盖模型生成的原始候选文件。每个分镜独立保存一条可版本化的剪辑准备记录，包括：

- 候选入点、出点和裁剪后时长；
- 对齐原分镜时长所需的播放速率；
- 从候选中提取的封面帧；
- 原视频音轨的来源区间和使用策略；
- 映射到当前分镜的对白、字幕证据；
- 文件、时长、画幅、帧率、黑屏和持续静帧的基础技术质检；
- 准备状态、阻断原因和版本信息。

## 2. 已实现架构

### 2.1 独立领域模型

新增 `VideoClipPreparation`，通过 `shot_plan_id` 与分镜一对一关联，通过 `candidate_id` 锁定当前已采用的视频候选。记录状态分为：

- `ready`：可交给剪辑阶段；
- `blocked`：参数或质量存在阻断项；
- `stale`：候选、起始图或上游输入已变化，必须重新准备。

SQLite 工作区架构升级到版本 6，新增 `video_clip_preparations` 表及项目、分镜、候选索引。生产版本快照升级到 `production-revision-v3`，并继续兼容读取 v1、v2 快照。

### 2.2 媒体检查器

新增独立 `ProductionVideoInspector`：

1. 使用 FFprobe 读取候选真实时长、尺寸、帧率、编码、文件大小和原生音频信息；
2. 使用 FFmpeg 在指定时间提取 WebP 封面；
3. 使用 `blackdetect` 和 `freezedetect` 检查持续黑屏与静帧；
4. 对候选记录与真实媒体的时长、画幅差异给出警告；
5. 画面信号扫描不可用时降级为 `skipped`，不会伪装成已通过。

媒体检查与生产业务通过协议隔离，单元测试可注入假检查器，后续也可替换为更强的质量服务。

### 2.3 时长与播放速率

原分镜时长继续作为剪辑时间线时长。候选裁剪后时长与原分镜不一致时，系统计算：

`播放速率 = 裁剪后候选时长 ÷ 原分镜时间线时长`

- 差异不超过 2%：标记为 `exact`；
- 播放速率位于 0.8～1.25：标记为 `retime`，允许交接；
- 超出 0.8～1.25：标记为 `outside_safe_range`，显示节奏风险提示，但不阻止进入剪辑阶段；剪辑交接继续保留实际播放速率，供后续人工调整。

本批只保存确定性的变速参数，实际转码由 Batch 4.6 完成。

### 2.4 原音轨、对白和字幕

“原音轨”始终指被分析的源视频音轨，不是视频模型生成候选自带的声音。

- 每个片段保存原分镜的 `source_audio_start_seconds` 和 `source_audio_end_seconds`；
- 对白与字幕按时间交集裁切，并转换为分镜内相对时间；
- 所有采用原音轨的片段在源时间上连续时，交接清单使用 `continuous_source_track`；
- 存在静音片段或源区间不连续时，使用 `per_shot`；
- 所有片段均静音时，使用 `muted`。

如果用户选择原音轨但分析报告没有可用音频，当前片段会被阻断。生成视频自带音频、口型同步、声音克隆和 TTS 不在本批范围内。

### 2.5 剪辑交接清单

所有必需分镜均已确认且准备状态为 `ready` 后，才允许从 `shot_videos` 推进到 `editing`。推进时写入：

`records/<record_id>/productions/<project_id>/timelines/editing-handoff.json`

清单使用 `viral-dna-editing-handoff/v1`，包含：

- 项目、版本和基础分析 ID；
- 时间线总时长与全局音轨策略；
- 按有效分镜顺序排列的片段；
- 每个片段的候选 URL、封面 URL、时间线位置、裁剪区间、播放速率、音轨区间、对白、字幕和质检状态。

Batch 4.6 将以该文件作为首个时间线草稿的输入，不需要重新推断候选与原视频的关系。

## 3. API

- `PUT /api/v1/production-shots/{shot_plan_id}/video-preparation`：创建或更新剪辑准备并重新执行质检；
- `GET /api/v1/production-shots/{shot_plan_id}/video-preparation/cover`：读取当前准备记录的封面；
- `GET /api/v1/productions/{project_id}/editing-handoff`：读取已生成的剪辑交接清单；
- `GET /api/v1/productions/{project_id}/gate-status`：新增 `prepared_shot_count` 与 `quality_warning_shot_count`。

修改准备参数会创建新的生产版本。取消采用视频、创建新候选或使上游图片失效时，已有准备记录同步变为 `stale`。

## 4. UI

已采用的视频候选下方显示紧凑“剪辑准备”面板：

- 上方大播放器继续负责播放、暂停、进度拖动和下载；
- 面板只显示小型完整封面，不复制播放器；
- 三个滑块分别调整入点、出点和封面帧；
- 声音可选择“映射原视频音轨”或“静音画面”；
- 右侧显示基础质检、对白条数、字幕条数和原音轨区间；
- 分镜阶段顶部与步骤条显示“可交接”数量，而不是把“已确认”误当成已完成；
- 阻断原因保留在当前面板，操作结果继续通过顶部消息／Toast 提示。

## 6. 人工验收流程

### 6.1 单分镜准备

1. 打开任一创作方案，进入“分段视频”。
2. 选择一个已确认采用的视频；确认下方出现“剪辑准备”，状态为“待准备”。
3. 点击“检查并准备此片段”；确认生成封面，显示时长、画幅、帧率等质检项。
4. 调整入点、出点和封面帧后保存；刷新页面，确认参数与封面仍然存在。
5. 确认上方候选原视频仍可完整播放、拖动进度条和下载，原文件内容未被裁剪覆盖。

### 6.2 音轨与文本证据

1. 对有音频分析结果的视频选择“映射原视频音轨”。
2. 确认面板显示正确的原视频时间区间，以及当前分镜映射到的对白、字幕数量。
3. 切换为“静音画面”并保存，确认状态仍可交接，声音策略变为静音。
4. 对无音频记录选择原音轨时，确认系统明确阻止并提示改为静音或重新分析音频。

### 6.3 门禁与失效

1. 仅确认视频、不执行剪辑准备；确认“进入剪辑合成”按钮不可用，门禁提示仍有已确认视频未完成准备。
2. 完成所有必需分镜准备；确认“可交接”数量等于必需分镜数，按钮恢复可用。
3. 对一个已准备分镜执行“取消采用”；确认其准备状态变为“已过期”，门禁重新关闭。
4. 重新选择、确认并准备该分镜；确认门禁恢复。

### 6.4 交接清单

1. 所有必需片段可交接后点击“进入剪辑合成”。
2. 请求 `GET /api/v1/productions/{project_id}/editing-handoff`，确认返回片段数量、顺序和页面有效分镜一致。
3. 确认相邻片段的 `timeline_end_seconds` 与下一片段的 `timeline_start_seconds` 连续。
4. 确认每个片段都包含候选 URL、封面 URL、裁剪区间、播放速率、音轨区间和质检状态。

## 7. 已知边界与下一阶段

- 本批没有提供帧级双滑块波形或时间线编辑器；当前 0.1 秒步长用于剪辑准备，精细编辑进入 Batch 4.6。
- 黑屏和静帧检测属于技术信号，不代表人物、产品、动作或物理一致性已通过，仍需人工审核。
- 本批不混入生成视频原生音频，不实现降噪、响度归一、TTS、声音克隆或口型同步。
- 下一主线为 Batch 4.6：定义正式 `timeline.json`、受控时间线 UI、原音轨／字幕／转场轨，以及 FFmpeg 预览与最终渲染。
