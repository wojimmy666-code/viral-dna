# 独立账户与企业协作

> 现行功能说明 · 2026-09-09 整理。部署与首次使用见 [部署索引](../../deployment/README.md)；文中的历史验收记录保留原始时间和范围。

用户确认：个人与企业使用独立登录账户，不允许切换空间。同一企业成员各自登录，
共享企业资产与项目；项目同一时刻只有一个编辑会话，其他成员只读。

## 实施边界

- 沿用 FastAPI、现有工作区数据库及媒体路径接口，保留 Sites 构建接口，不发布外部站点。
- 身份及成员关系独立持久化。每个登录用户只能属于一个账户。
- 工作区由服务端账户绑定决定；请求与后台任务使用固定上下文，禁止进程全局切换。
- 单 admin 独立认证；负责人只管理本企业成员，不引入自定义权限或多后台账户。
- 编辑租约持久化，绑定账户、项目、用户、登录会话与独立标签页；过期旧令牌不可写。
- 首次启用需明确设置 admin 和数据归属。首次与后续账户统一采用 `accounts/<账户UUID>`；承接旧数据时，经归属确认后复制校验，保留原件，不自动认领或合并其他工作区。
- 测试使用隔离工作区，不提交真实生成任务，不自动推送 GitHub。

## 验收

1. 未登录拒绝私有 API；用户会话不能调用后台管理 API；后台会话不授予私有数据访问。
2. 两个账户并发访问、任务异步完成和媒体访问均不串数据。
3. 企业成员共享，个人不共享；停用和移除及时撤销会话及编辑权。
4. 两人/两标签同时争用仅一方取得编辑权；超时、退出和断线恢复不覆盖新编辑者。
5. Skill 与分析报告两条完整流程采用相同项目锁；只读不触发生成或隐式草稿保存。
6. 密码不明文存储；会话/邀请/重置令牌哈希存储、限时且可撤销；修改操作校验 CSRF。
7. 已有未提交创作流程改动、项目、媒体及采用记录保留。

## 首次启用

按 [账户初始化](../../deployment/账户初始化.md) 在部署本机完成首次设置，不需要初始化码。先备份并核对旧工作区归属；已启用系统不能删除认证数据库重新初始化。部署、升级与备份步骤只在部署目录维护。

## 日常使用

- 点击左上角 LOGO 或 ViralDNA 可返回工作台项目列表，手机端点击品牌图标同样可用；平台 admin 返回账户管理，不进入前端账户。跳转不会退出登录，须先完成当前已登记草稿的保存；保存失败时显示提示并留在原页，编辑权继续保留。存储管理页“返回资产库”入口不变。
- 登录后采用单行顶栏：LOGO 与 ViralDNA 位于最左上角，随后是工作台侧栏折叠入口、账户信息、页面原有搜索、通知与用户名菜单。侧栏不再重复品牌和“视频逆向拆解系统”副标题，导航上移；全局问号帮助入口移除。窄屏保留品牌图标，搜索通过放大镜按需展开，通知角标保留；空间不足时将账户名称和类型收纳到右上角菜单。用户名菜单仍可进入成员、存储、改密或退出等已有操作；成员、存储和只读页面保留品牌与账户入口，不显示无效的侧栏开关。
- 后台「账户管理」可创建个人或企业账户、设置名称、启用/停用、查看成员和签发密码重置链接。
- 前端手机号必须为中国大陆 11 位号码（以 13–19 开头），全局唯一，只属于一个账户；本期不做短信验证。没有个人/企业空间切换入口，也不提供切换 API；另一个独立账户需要另一个手机号。后台固定使用 `admin`，不套用手机号规则。
- 个人账户只有一个用户。企业负责人可在账户菜单「企业成员」添加、搜索、移除、恢复普通成员或重置其密码；普通成员共享项目和资产，但不能管理成员。
- 企业负责人添加成员时填写姓名、手机号、至少 8 位初始密码，创建后直接启用，不必领取邀请链接。平台 admin 新开独立账户及重置密码仍使用一次性链接（72 小时有效）；旧版企业邀请接口继续兼容。本期不自动发送邮件或短信，密码或链接须单独通过可信渠道交付本人。
- 密码为 8–128 个字符，不强制组合复杂度。初始化、登录、激活/重置与修改密码一致校验，错误提示指出具体字段且不回显密码。修改密码会撤销旧会话；停用账户、移除成员立即撤销其会话和编辑租约。移除成员不删除企业项目和资产。
- 消息内容按账户共享，已读状态和本地草稿按登录用户隔离。
- 新账户拥有独立的工作区和空资产库。内置公共 Skill/模型目录属于平台配置，不属于其他用户的私有资产。
- 若使用方舟真人资产目录，后台需为新账户分配独立 `ProjectName`；同一目录不能分配给两个账户。未分配时不会显示平台默认目录。平台 API Key 仍由后台统一管理。

## 登录自动续期（2026-09-20）

- 前端个人、企业成员：闲置窗口 12 小时，最长登录期限 7 天；后台 admin：闲置窗口 2 小时，最长 24 小时。每次有效续期同时更新服务端会话和 HttpOnly Cookie，最长期限始终从本次密码登录起算。
- 页面可见且有焦点时，真实输入、点击、拖拽、滚轮与触摸操作最多每 5 分钟续期一次。只挂着页面、播放视频、通知/任务轮询及每 20 秒的编辑锁心跳不续登录；短时等待生成无需持续操作。
- 切回页面、电脑唤醒与网络恢复先检查服务器登录状态，临时网络错误只重试状态检查/续期，不重放保存、生成或其他业务请求。服务端拒绝复活过期、已退出、改密或停用后的会话。
- 真正失效时保留当前页面和已挂载草稿，暂停提交，点击「重新登录」在原页弹窗验证原用户；不把草稿带给另一用户/账户。重新登录后重新获取项目编辑权，若被其他成员占用，继续保留内容但禁止写入。原有版本冲突检查仍生效，不自动保存或覆盖其他人的修改。
- 保留仅限当前页面内存，关闭、刷新仍可能丢失未提交内容；浏览器离开提示与复制/下载备份是补充保护，不承诺持久化尚未保存的内容。升级后旧页面先备份内容再刷新，已过期登录需重新登录一次。
- 跨标签页通过互斥和无凭据通知协调，并向服务器核实；广播不包含密码、Cookie、CSRF 或草稿。请求携带原用户标识，防止另一标签页切换登录后，旧页面混入其他用户数据。前端与后台互不续期。
- 不变更认证库结构，沿用 `created_at` 和 `expires_at`；登录最长期限也在项目编辑锁与实际数据库写入处核验。

验收范围与运行命令见 [登录续期与原地恢复验收](../../qa/accounts/session-renewal.md)。

## 企业成员管理（2026-09-13）

企业成员管理位于登录后的工作台 `/account/members`，不是 `/admin` 平台后台。

1. 负责人登录后，打开右上角账户菜单 →「企业成员」→「添加成员」。填写姓名、独立手机号、初始密码，点击「创建成员」，本人即可使用该手机号和密码登录企业账户。
2. 默认显示当前成员（已启用及历史待激活成员），支持按姓名或手机号搜索。姓名、手机号、身份、状态、创建时间和操作同列展示；手机端改为逐行信息，避免横向滚动。
3. 点击普通成员的「移除」，核对确认区内姓名和手机号，再确认移除。该成员软停用，旧会话、邀请／密码重置链接、同步令牌和项目编辑租约失效；负责人和其他成员不受影响。
4. 「已移除」中可恢复同一成员。必须设置不同于原密码的新密码，恢复原用户 ID 和企业归属，不恢复旧登录状态或设备授权。已移除手机号仍占用，不能通过再次添加绕过恢复流程。
5. 「重置密码」可为当前普通成员设置新密码并启用。提交后该成员须重新登录；负责人自己的密码继续通过账户菜单「修改密码」处理。

权限由后端再次校验：只允许启用企业的负责人操作本企业普通成员，不能移除负责人或跨企业操作。手机号必须全局唯一；其他账户占用时只返回通用提示，不泄露对方账户信息。企业负责人不能修改成员手机号、角色或企业归属。

成员软删除不删除企业资产、项目、生成结果、历史署名、操作日志或容量占用，不取消已经提交的后台生成任务。本次没有认证数据库结构迁移；`disabled` 继续表示软停用，并记录创建、移除、恢复和密码重置审计事件。管理界面的密码不持久化到浏览器，服务端只保存加盐密码哈希。

兼容接口：`POST /account/members` 携带 `password` 时直接创建；不携带时仍签发邀请。`POST /account/members/{id}/reset` 和 `/restore` 携带 `{password}` 时立即设置密码；不携带请求体时保持历史一次性链接流程。平台 admin 接口不变。

## 项目编辑规则

锁定的是最外层项目，覆盖大纲、分镜图片、分镜视频、剪辑、导出以及该项目下所有创作方案。

- 第一个打开项目的有效会话取得编辑权，同企业其他用户或其他标签页只能打开只读快照。
- 租约有效期 120 秒，编辑页每 20 秒续约。正常离开尽力释放；浏览器异常退出、断网或刷新时释放未送达，最长等待租约过期后可重试。
- 只读页面每 10 秒读取最新快照，不挂载有自动保存/生成副作用的编辑器。
- 编辑权或登录失效后，当前编辑器冻结并保留已挂载的未提交内容，可复制提示词或下载文本备份；核对最新版本后手动恢复，不自动覆盖其他人的修改。
- 服务端既校验请求入口，又在 SQLite 写事务中校验租约，拒绝旧页面失效后的保存。项目列表的重命名、归档等操作也不能绕过占用中的编辑锁。
- 已经提交的后台生成/分析任务固定归属提交时的账户，不因用户离开编辑页而取消；本期不支持任务迁移到其他账户。

## 部署与数据位置

| 配置 | 用途 |
| --- | --- |
| `VIRAL_DNA_AUTH_MODE=password` | 正式账户模式，默认值 |
| `VIRAL_DNA_ADMIN_CONSOLE_ENABLED=true` | 启用独立管理后台 |
| `VIRAL_DNA_AUTH_DB_PATH` | 身份、邀请、会话、租约和基础审计 SQLite 路径 |
| `VIRAL_DNA_ACCOUNTS_ROOT` | 所有账户的标准工作区父目录，包括首次账户 |
| `VIRAL_DNA_ACCOUNT_CATALOG_PATH` | 现有账户/设备/存储目录，用于兼容已有数据 |
| `VIRAL_DNA_CORS_ORIGINS` | 精确列出允许访问 API 的前端来源 |

认证数据库和账户目录默认位于账户目录文件所在位置下的 `accounts.sqlite3` 与 `accounts/`；Windows 通常为 `%LOCALAPPDATA%\ViralDNA`。测试与正式环境使用相同的账户内部布局，只是数据根目录可由部署配置指定。账户目录不得通过前端输入或 URL 更改。

2026-09-11 起，全新初始化不再将首个账户固定在旧工作区。已经初始化的旧账户暂时沿用原绑定，升级不会自动搬家；使用[停服迁移工具](../../deployment/账户目录统一与旧账户迁移.md)完成复制、备份、校验和绑定更新。新版 API 与迁移工具互斥，原目录不自动删除。

首版按单个 API 进程部署，SQLite 保存在本地磁盘，不放网络共享盘。编辑租约持久化不代表整个应用已经支持多实例或任务队列高可用；部分既有配置仓库仍使用进程内协调。

公网部署需要 HTTPS，推荐前端与 `/api` 同域反向代理。非本机的明文 HTTP 登录会被拒绝；应正确配置可信代理、HTTPS 转发和精确 CORS，不使用通配来源。Cookie 为 HttpOnly、SameSite=Lax，HTTPS 下启用 Secure；修改请求必须同时通过来源和 CSRF 校验。

`local_bootstrap` 仅保留给明确配置的本机开发及旧测试，不是正式账号模式，不能用来绕开账号控制；它只接受本机访问。切勿将免登录后端通过本机代理暴露给其他人。

一致性备份、Windows 凭据恢复及版本回滚步骤见 [升级备份与恢复](../../deployment/升级备份与恢复.md)。激活链接、密码和会话令牌不得提交 Git。

本期不实现：自助注册、企业/个人互转或切换、SSO、MFA、自定义角色、多个后台管理员、多人同时编辑和自动合并。单个 admin 的登录密码应由部署管理员安全保管。

## 自动化检查

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest services/api/tests/test_account_input_rules.py services/api/tests/test_accounts_repository.py services/api/tests/test_account_isolation_http.py services/api/tests/test_account_app_bootstrap.py -q -o addopts=
npm run test:web
npm --workspace apps/web run test:accounts-browser
npm --workspace apps/web run test:prompt-browser
npm run check:design
npm run build:web
```

账号 API 测试及完整服务启动测试使用临时 SQLite 和媒体目录；浏览器测试使用临时浏览器配置与内存 HTTP 服务，不连接线上环境，不实际生图或生成视频。
