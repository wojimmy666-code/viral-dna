# 项目全局与局部提示词

> 现行功能说明 · 2026-09-09 整理。部署与首次使用见 [部署索引](../../deployment/README.md)；文中的历史验收记录保留原始时间和范围。

## 已实现

- 大纲与分镜：创作思路、默认折叠的全局图片／视频提示词、逐镜局部图片／视频提示词；局部仍支持增删及自动保存。
- 分镜图片与视频：默认编辑局部，同类型全局提示词默认折叠；局部复制、只读完整预览与完整复制。视频局部编辑区默认展开。
- Skill 前后阶段共用项目级全局版本；原视频模式以独立创作方案为作用域，不影响同一来源的其他方案，也不修改平台 Skill。
- 大纲可读取后续分镜阶段的局部正文，包括视频生成草稿；修改大纲局部会同步现有对应分镜，结构增删仍经原确认流程衔接。
- 全局与局部分别自动保存，切换及生成前补保存。全局保存失败保留草稿，版本冲突不自动覆盖；重新加载后可核对并选择本地或服务器版本。
- 实际图片／视频请求保存全局版本、全局正文、局部正文、组合正文和内容摘要。参考素材与模型参数继续由原生成链校验与附加。批次每镜一张的原规则不变。
- 修改全局只影响新任务，不自动重新生成、删除候选或撤销已采用结果。新批次使用最新全局，已有带快照的批次恢复和单任务重试沿用原快照；分镜结构或素材已经改变时继续使用原有安全校验，不静默混入新输入。

## 旧数据与格式

- SQLite workspace schema 升至 18，新增 `project_prompt_revisions` JSON 表和索引；内存仓库具有相同的版本检查。
- 新的大纲生成格式分别接收 `common_image_prompt`、`common_video_prompt`，逐镜设计不重复全局。旧格式继续兼容。
- 历史项目仅提取能够确定的公共段落。无法确定是全局还是局部的人工文案保留原位，可手动整理；不进行语义猜测，不改写历史 Seed、候选或哈希。
- 全局允许留空。图片全局与局部继续执行静态图片规则，不引入连续镜头要求。

## 手工验收

1. 打开已有 Skill 项目的“大纲与分镜”：全局默认折叠，分镜编辑器只显示局部正文。
2. 展开全局，修改图片全局，等待“已保存”；进入分镜图片，展开全局，应看到相同内容。
3. 修改一个局部正文，切换分镜再返回：修改保留，其他分镜局部不被改写。完整预览含全局与当前局部，默认复制仅复制局部。
4. 在分镜视频修改局部正文，返回大纲应看到最新内容；在大纲继续修改后再进视频，正文一致。视频全局独立于图片全局。
5. 同时打开两个页面修改同一全局，后保存的旧版本应提示冲突并保留草稿，不能静默覆盖。
6. 断网后修改全局，确认失败提示及草稿保留；恢复网络后重试。刷新遇到旧版本草稿时必须先核对。
7. 使用隔离模型桩验证批次中途更改全局后再恢复：原批次继续原快照，新批次使用新版本；不能通过真实付费批次进行自动验收。

## 自动检查

- `services/api/tests/test_project_prompts.py`：内存／SQLite 版本、作用域、清空、保守提取、跨阶段同步、批次恢复快照。
- 大纲、生成队列、视频草稿、创作意图、ProductionSeed、SQLite、图片批次与静态图片投影回归测试。
- 前端自动保存会话及页面结构测试、生产构建、设计规范检查。
- 独立浏览器在 1600、1024、390 像素下检查真实页面的默认折叠、局部正文、完整预览和横向溢出；真实项目写请求被拦截，不提交付费生成。
- 视频页面使用仅存在于测试浏览器中的门禁／草稿响应，未批准真实项目图片。全局自动保存通过内存响应验证，未把测试文案写入真实项目。

2026-09-06 验证结果：81 项后端相关测试、273 项前端主套件测试、7 项设计规范检查通过，生产构建通过。三个阶段均完成三种宽度检查；全局自动保存的隔离浏览器测试通过。现有 2 个不可变 ProductionSeed 可正常校验。
