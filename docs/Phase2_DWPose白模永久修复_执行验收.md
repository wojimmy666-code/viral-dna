# Phase 2 · DWPose WholeBody 白模永久修复

更新时间：2026-08-15

状态：代码实现完成，等待首次模型安装、真实素材人工验收和 Seedance 最低成本任务验证

## 1. 修复目标

旧版 OpenCV 白模主要依据前景轮廓和人物包围框绘制。它能够隐藏原人物像素，但不能稳定表达关节、双手、人物朝向和连续动作；检测失败时还可能退化成居中的通用人形图标。因此“文件可打开”和“身份已去除”并不等价于“可以作为动作参考”。

永久修复把白模定义为一个具备可验证语义的派生资产：

- 图片白模必须表达当前帧的 WholeBody 姿态、人物位置和占画比例。
- 视频白模必须逐帧表达同一主体的连续姿态和运动轨迹。
- 输出不得复制源人物、服装、背景、五官或纹理像素。
- 只有身份去除、文件校验和姿态质量全部通过的资产才能跨过视频 Provider 请求边界。
- 旧 OpenCV 白模保留供预览和审计，但永久降级为不可提交的历史资产。

## 2. 生产链路

### 2.1 姿态引擎

当前生产引擎为 `dwpose_wholebody_mannequin`：

- 人体检测：官方 DWPose 配套 `yolox_l.onnx`。
- WholeBody 姿态：官方 `dw-ll_ucoco_384.onnx`，输出身体、足部、面部和双手关键点。
- 推理运行时：ONNX Runtime，第一期固定使用 CPU Provider，后续可以在同一引擎协议下增加 GPU Provider。
- 输出渲染：ViralDNA 自有的确定性无纹理白模渲染器，不把源图像素传入输出画布。

面部关键点可以参与源帧姿态估计，但不会写入持久化姿态清单，也不会被绘制为可识别五官。持久化清单只保留身体、足部和双手关键点。

### 2.2 图片白模

1. 解码已确认图片候选。
2. 检测全部人物并选择主主体。
3. 推理 133 点 WholeBody 姿态。
4. 检查身体核心点、双手可见性、主体占画比例和多人歧义。
5. 在新的中性画布上绘制无五官头部、躯干、四肢和手部骨架。
6. 保存 PNG、缩略图、姿态清单、质量报告和文件摘要。

### 2.3 视频白模

1. 只读取当前分镜的起止时间范围。
2. 对每一帧执行人物检测与 WholeBody 推理。
3. 使用人物框重叠、核心关节连续性和检测置信度跟踪同一主主体。
4. 只对不超过 0.35 秒的内部短缺失做线性插值；长缺失不伪造动作。
5. 对连续关键点做时序平滑，降低抖动但不改变动作节奏。
6. 逐帧绘制无纹理白模，以 H.264／yuv420p／faststart 输出浏览器可播放 MP4。
7. 校验输出帧数与姿态清单一致，再保存质量报告和摘要。

## 3. 质量门禁

`ReferenceProxyAsset.usable_for_generation` 采用失败关闭原则。必须同时满足：

- 生命周期为 `ready`。
- `identity_removed=true`。
- 文件基础校验为 `passed`。
- 姿态语义校验为 `passed`。
- 存在质量分数。
- 存在代理文件路径和 SHA-256。
- 存在 `pose-manifest.json`。
- 存在 `quality-report.json`。
- 存在固定模型组合摘要 `model_sha256`。

缺少任意一项时，代理只能预览和下载，不能启用、不能计入参考数量，也不能发送给视频 Provider。

### 3.1 图片质量

图片质量综合以下证据：

- 身体关键点可见率。
- 肩部和髋部核心点可见率。
- 左右手关键点可见率。
- 主体包围框占画比例。
- 是否存在多个可能的主主体。

身体／核心点不足或主体过小会直接失败；多人歧义或分数偏低进入“需复核”；只有通过状态才会自动启用。

### 3.2 视频质量

视频质量同时记录原始检测覆盖率和插值后的最终覆盖率。短缺失插值不能掩盖原始检测质量：

- 原始覆盖率过低、最终覆盖不足、身体可见率过低或剩余连续缺失过长时失败。
- 边缘质量进入“需复核”，生成文件保留但默认不启用。
- 通过时才允许作为 Seedance 的无身份动作参考。

## 4. 物理代码边界

- `video_references/domain.py`：代理资产、质量状态和最终可用性规则。
- `video_references/proxies/contracts.py`：可替换引擎契约；新引擎默认不具备生产资格。
- `video_references/proxies/dwpose/models.py`：固定版本、下载地址、大小和 SHA-256 校验。
- `video_references/proxies/dwpose/inference.py`：官方 ONNX 模型适配。
- `video_references/proxies/dwpose/tracking.py`：主体选择、短缺失插值和时序平滑。
- `video_references/proxies/dwpose/renderer.py`：无源像素白模渲染。
- `video_references/proxies/dwpose/quality.py`：图片／视频姿态质量门禁。
- `video_references/proxies/dwpose/engine.py`：图片／视频执行与证据包落盘。
- `video_references/proxies/opencv_silhouette.py`：只读兼容旧资产，不再是生产引擎。
- `video_generation/gateway.py`：发送 Provider 前的最终独立安全门。
- `apps/web/src/video-references/`：安装、生成、预览、质量状态和历史绑定 UI。

各层不依赖 Seedance 的具体请求格式。未来 MediaPipe、SMPL、远程姿态服务或 GPU DWPose 只需实现同一引擎契约，并显式提供生产能力和完整证据包。

## 5. 安装与存储

首次在“人物参考策略”中点击“安装 DWPose WholeBody”后，ViralDNA 下载约 351 MB 官方模型。文件默认保存在：

`%LOCALAPPDATA%\ViralDNA\models\dwpose\official-onnx-v1\`

也可以通过 `VIRAL_DNA_DWPOSE_MODEL_ROOT` 指定目录。安装过程使用临时目录下载，逐文件校验大小和 SHA-256，全部通过后再原子替换正式文件；中断或损坏文件不会被当作可用模型。

每个白模保存在工作区对应分镜下：

```text
reference-proxies/{proxy_id}/
├── proxy.png 或 proxy.mp4
├── thumbnail.png
├── pose-manifest.json
└── quality-report.json
```

## 6. 历史迁移策略

旧记录没有 `semantic_validation_status`、质量报告或模型摘要时，加载后自动归类为 `legacy_unverified`：

- 历史文件和缩略图不删除。
- UI 显示“旧版未校验”或“旧绑定不可提交”。
- 旧绑定不再显示为有效启用，也不计入当前模型参考数量。
- 用户可以解除旧绑定，但不能重新启用。
- 必须用当前 DWPose 引擎重新生成，才能获得可提交的新资产。

这是数据级兼容，不需要一次性破坏性迁移工作区 JSON。

## 7. API 与交互

- `GET /api/v1/video-references/proxy-engines`：返回引擎是否安装、是否生产可用、WholeBody／手部／视频跟踪能力和运行时。
- `POST /api/v1/video-references/proxy-engines/{engine}/install`：安装固定版本模型并热更新当前服务能力。
- `POST /api/v1/video-references/shots/{shot}/proxies`：生成图片或视频姿态代理。
- 分镜 PATCH：只允许启用 `usable_for_generation=true` 的代理；绕过前端同样会被拒绝。

UI 行为：

- 未安装时只显示安装入口，不显示无效生成按钮。
- 通过的最新同媒体类型白模会替换当前绑定，历史文件仍保留。
- “需复核”“失败”和“旧版未校验”只能预览或下载。
- 历史旧绑定显示“解除旧绑定”，不会伪装成当前启用。
- 质量摘要同时显示身份去除、姿态状态、质量分数和引擎。

## 8. 人工验收流程

### 8.1 首次安装

1. 启动 ViralDNA，进入包含人物的分镜视频阶段并选择 Seedance。
2. 在“人物参考策略”中确认出现“安装 DWPose WholeBody（约 351 MB）”；该入口不依赖是否已绑定火山方舟托管演员。
3. 如果能力接口暂时不可用，确认同一区域显示“重新检测 DWPose WholeBody”，重启 API 后可原地重试。
4. 点击安装，确认页面立即显示后台安装状态、真实百分比、已下载容量和总容量；安装期间页面不应表现为无响应。
5. 安装成功后确认出现成功 Toast，右上角账户消息中心保留成功记录，并显示图片、视频白模生成入口。
6. 如安装失败，确认进度区域显示明确原因，同时出现失败 Toast 和账户消息；模型目录中不应出现被当作正式模型的半成品。

### 8.2 图片白模

1. 选择一张人物手臂、身体姿势明显的已确认关键帧。
2. 生成图片白模并放大预览。
3. 确认白模的人物位置、身体朝向、手臂方向和大致手势对应源图。
4. 确认输出没有源人物五官、头发、服装、背景或纹理。
5. 确认卡片显示“身份已去除 · 姿态通过 · NN 分”，并自动成为当前图片白模。

### 8.3 视频白模

1. 在有明显人物位移或手势变化的分镜生成原视频白模。
2. 直接播放预览，确认总时长与分镜相符、人物会随源视频运动，不再是静止通用图标。
3. 观察人物连续运动，确认没有明显主体跳换和高频抖动。
4. 下载 MP4，用 Chrome 或系统播放器确认 H.264 文件可播放。
5. 确认通过时自动启用；质量不足时保留历史但不启用。

### 8.4 失败与迁移边界

1. 对无人图、人物极小图或严重遮挡图生成白模，确认明确失败或要求复核，不自动回退原图。
2. 打开旧 OpenCV 白模记录，确认仍能预览，但显示“旧绑定不可提交”，且生成参考数量不包含它。
3. 尝试绕过 UI 启用旧白模，确认 API 返回 `reference_proxy_quality_not_passed`。
4. 新生成一个通过质量门的同类型白模，确认旧绑定自动停用、历史资产未删除。

### 8.5 Provider 最低成本验证

1. 选择 Seedance，绑定托管演员并启用一个通过质量门的白模。
2. 发起最低分辨率、最短时长、单候选任务。
3. 检查任务参考清单：身份来自 Provider 托管演员，动作来自白模，原人物图片和原视频不在提交列表。
4. 切换 MiniMax H3 或百炼，确认仍按模型能力直接使用原始参考，不被强制转白模。

## 9. 当前边界

- 第一版使用 CPU 推理，长分镜的首次视频处理可能较慢；后续可增加 GPU Provider 和后台进度事件。
- 当前输出是二维 WholeBody 无纹理姿态白模，不是 SMPL 三维人体，也不保证精确复原手指接触关系。
- 白模是动作和构图参考，不是 Provider 审核绕过手段；最终可接受的素材类型仍由所选模型能力和 Provider 规则决定。
- 真实 Seedance 是否接受某一种图片／视频代理格式，仍需使用最低成本真实任务验证；失败时不得自动提交原真人素材。

## 9.1 Windows 运行时兼容边界

- Windows 环境固定使用 `onnxruntime>=1.20,<1.28`；已确认 `1.28.0` 在当前项目虚拟环境中可能出现 `onnxruntime_pybind11_state` DLL 加载失败。
- `scripts/start.bat` 会同时检查包是否可导入及版本是否低于 `1.28`；不满足时自动按 `reference-proxy` 依赖约束修复。
- DWPose 能力接口必须在模型文件尚未安装时仍返回引擎记录，使前端可以展示安装入口，而不是静默隐藏整项能力。
- 模型安装使用后台任务接口；前端轮询任务状态，服务端按实际下载字节更新进度，并在结束时发布账户级成功或失败通知。
