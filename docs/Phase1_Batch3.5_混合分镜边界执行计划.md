# Phase 1 Batch 3.5：混合分镜边界执行计划

更新时间：2026-08-04

## 1. 背景与结论

样本 `2257d6708577851e5cff45bdcc12c9fb_raw` 原报告只有两个镜头。原因不是前端漏渲染，也不是 VLM 没有理解画面，而是旧流程先用单一 FFmpeg `scene score` 硬阈值确定镜头，再要求 VLM 对每个既定镜头输出一份事实。连续运镜、遮挡和运动模糊会把变化分散到多帧，导致 3.6 秒和约 8.8 秒的语义转场未达到 0.24 硬切阈值。

本批次采用“程序召回候选、VLM 语义确认、程序重建最终时间线”的双层方案。模型只能选择程序提供的候选 ID，不能自行编造时间戳。

## 2. 本批目标

- 同时覆盖硬切、渐变、遮挡和连续运镜下的语义转场。
- 硬切边界由程序锁定，防止结尾卡等明确切换被模型漏掉。
- VLM 只审核候选边界，最终时间戳仍来自 FFmpeg 实测证据。
- 分镜确认只调用一次模型，并接入现有模型路由、缓存、成本上限和计费账本。
- 模型不可用、响应越界、图片缺失或超出预算时安全降级到程序硬切边界。
- 旧报告保持可读；重新分析时生成 `phase1-hybrid-segmentation-v5` 新版本。

## 3. 实现架构

1. 媒体预处理生成 H.264/AAC 代理文件。
2. 相邻帧低阈值检测召回短时变化候选。
3. 以 2 FPS 采样的时间窗口检测补充连续变化候选。
4. 在 0.65 秒窗口内执行非极大值合并，并锁定达到硬切阈值的候选。
5. 为每个候选生成“远前、近前｜近后、远后”四帧微时间线，同时生成最多 12 帧的全片上下文图。
6. 每张候选图前单独发送候选 ID、时间和四帧标签，避免模型把相邻图片的语义错配到当前候选。
7. `shot_segmentation` 模型任务一次性逐项审核所有软候选；keep 和 reject 都必须返回前后描述、粗粒度叙事组、连续运镜标记、理由和置信度。
8. 程序校验候选 ID 的完整性，并执行确定性一致性规则：仅当粗粒度叙事组改变且不属于连续运镜时接受 keep；硬切锁定点始终保留。
9. 根据最终边界重新抽取每个镜头的开始帧、中间帧和结束帧。
10. 重新构建 ASR、字幕和 OCR 时间线，再运行现有 `shot_facts` 逐镜头理解。

## 4. 数据与证据

`MediaEvidence.segmentation` 保存：

- 检测器版本、候选数量和候选时间点；
- 每个候选的检测方法、原始分数、硬切锁定状态、四帧时间戳和微时间线；
- VLM 原始决策、前后画面描述、连续运镜判断、确认理由、置信度和前后叙事组；
- 一致性规则是否覆盖模型原始 keep 决策；
- 程序边界、最终边界、最终镜头数和降级原因。

每个最终镜头保存 `boundary_method`、`boundary_confidence`、`source_candidate_ids` 和 `semantic_group`。前端默认展示最终分镜，并允许折叠查看原始候选证据。

## 5. 模型与成本设计

- 新任务：`ModelTask.SHOT_SEGMENTATION`。
- Prompt：`shot-segmentation-v5`。
- Schema：`shot-segmentation-selection-v4`。
- 质量和均衡档默认使用 GUI 当前选择的百炼模型；经济档可优先 Flash 并回退 Plus。
- 请求指纹包含视频哈希、检测器版本、候选数据、图片哈希、模型、Prompt 和 Schema 版本。
- 同一输入重复分析可命中模型缓存。
- 调用前执行费用估算和任务成本上限检查；成功、失败和缓存命中均写入现有模型账本。

## 6. 安全降级

以下情况不阻断视频分析：

- 没有配置 VLM；
- 分镜路由缺失或价格版本不一致；
- 候选证据图片不完整；
- 模型返回不存在或重复的候选 ID；
- Provider 不可用、调用失败或超过成本上限。

降级后仅保留硬切锁定边界，并在报告和 UI 中显示具体原因。`shot_facts` 额外输出 `contains_multiple_scenes`，用于发现仍可能过长的语义镜头并给出告警。

## 7. 单元测试与验收

已增加以下自动化测试：

- FFmpeg 元数据解析、候选合并和硬切边界生成；
- VLM 选择软候选后与硬切锁定点正确合并；
- 四帧微时间线的近/远时间计算和视频边界夹取；
- 百炼请求按“候选标签—对应图片”交错排列；
- 每个软候选必须恰好返回一次 keep/reject 审核；
- 模型 keep 与叙事组/连续运镜自相矛盾时，由一致性规则确定性合并；
- 分镜模型调用计费、结果缓存和模型任务路由；
- 模型返回未知候选 ID 时拒绝结果并计入实际成本；
- 成本上限在调用前阻止 Provider；
- 真实 FFmpeg 流程生成候选对比图、上下文图和最终分镜元数据。

目标样本验收时间线：

- 0.0–3.5 秒：人物行走与情境引入；
- 3.5–8.783 秒：产品展示；
- 8.783–15.35 秒：湖边生活方式场景；
- 15.35–18.342 秒：抖音结尾画面。

产品展示过程中的局部特写、遮挡和运动模糊不应被拆成多个独立语义镜头。
