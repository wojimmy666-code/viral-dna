# 用户账户与平台管理后台拆分

## 目标

ViralDNA 将“用户偏好”和“平台基础设施配置”划分为两个安全边界。当前版本仍是单机部署，但接口、路由、数据归属和页面外壳已经按未来独立登录设计。

本阶段明确不支持用户自带 API Key（BYOK）。所有 Provider 凭据由平台管理员维护，用户只能从平台已经启用的模型中选择默认偏好。

## 两类主体

### 用户账户

- 主体类型：`user`
- 当前实现：工作区中的默认本机账户
- 未来实现：独立用户登录，可拥有多个工作区、项目、分析记录和资产
- 页面入口：`/settings/profile`
- API 入口：`/api/v1/session`、`/api/v1/me/settings/preferences`
- 数据归属：按 `account_id` 隔离

用户可设置：

- 目标提示词模型
- 分析质量
- 单条分析成本上限
- 默认图片模型与候选数量
- 默认视频模型与分辨率
- 当前设备和工作区信息（当前只读展示）

用户不可读取或写入：

- API Key、AccessKey、SecretKey
- Provider Base URL
- 平台模型目录和启停状态
- 对象存储 Bucket 与签名策略
- 平台运行环境和计费规则

### 平台管理员

- 主体类型：`platform_admin`
- 当前实现：仅本机可访问的引导管理员
- 未来实现：独立后台域名或独立登录入口，使用管理员会话
- 页面入口：`/admin/providers`
- API 入口：`/api/v1/admin/session`、`/api/v1/admin/settings/*`
- 数据归属：平台全局，对所有用户账户生效

平台管理员负责：

- VLM、图片和视频 Provider 凭据
- 模型目录、默认模型、启停状态与能力声明
- OSS 私有桶、签名 URL 和媒体暂存
- 本机工具、深度推理和运行环境
- 后续的平台账单、配额与审计

## 页面结构

### 用户设置

用户设置使用独立页面，不再使用“模型与设置”弹窗。

```text
/settings/profile      账户与分析
/settings/generation   生成偏好
/settings/device       当前设备
```

页面保留返回工作台、平台连接和平台后台入口。平台后台入口只在本机引导模式下显示。

### 平台管理后台

平台管理后台使用独立页面外壳和导航，不复用用户工作台侧栏。

```text
/admin/providers       服务商与凭据
/admin/models          模型与默认值
/admin/media           媒体与对象存储
/admin/runtime         运行环境
```

该结构允许未来把 `/admin` 部署为独立前端或独立域名，而不改变业务接口语义。

## API 与权限边界

| API | 主体 | 范围 | 凭据字段 |
|---|---|---|---|
| `GET /session` | 用户 | 当前账户 | 无 |
| `GET/PUT /me/settings/preferences` | 用户 | 当前 `account_id` | 明确禁止 |
| `GET /admin/session` | 平台管理员 | 平台 | 无 |
| `/admin/settings/model` | 平台管理员 | 平台 | 支持 |
| `/admin/settings/image-generation` | 平台管理员 | 平台 | 支持 |
| `/admin/settings/video-generation` | 平台管理员 | 平台 | 支持 |
| `/admin/settings/media-staging` | 平台管理员 | 平台 | 支持 |

用户偏好模型采用 `extra="forbid"`，即使前端被绕过，提交 `api_key` 等未知字段也会返回 `422`，不会落盘。

平台后台在 `local_bootstrap` 模式下默认只接受本机请求。可通过未来的认证中间件替换为管理员会话校验，不需要修改业务路由。

## 数据模型

用户偏好保存在工作区账户目录旁的 `user-settings.json`：

```json
{
  "schema_version": 1,
  "revisions": {
    "account-uuid": 2
  },
  "accounts": {
    "account-uuid": {
      "target_model": "seedance",
      "analysis_profile": "balanced",
      "max_cost_cny": 1,
      "image_model_alias": null,
      "image_candidate_count": 1,
      "video_model_alias": null,
      "video_resolution": null
    }
  }
}
```

更新使用乐观修订号；两个页面同时修改时，旧修订提交返回 `409`，防止静默覆盖。

平台密钥继续使用现有服务端 Secret Store，不下发明文到浏览器；响应只包含 `api_key_configured` 等状态。

## 有效配置合并

生成任务使用两层配置：

1. 平台层提供可用模型、能力、凭据、基础默认值和计费。
2. 用户层只覆盖默认模型、候选数量和分辨率。

若用户偏好的模型已被平台停用或删除，前端回退到平台默认值；任务创建时服务端仍需再次做能力和权限校验。

## 未来独立登录

后续接入认证时按以下顺序演进：

1. 用户登录签发用户会话，`/session` 从会话读取 `account_id`。
2. 管理员登录签发独立管理员会话，`/admin/session` 校验管理员角色与权限。
3. 用户前端与平台后台可分别构建、部署，但继续共用契约化 API。
4. 增加平台管理员账户管理、角色、审计日志和密钥轮换。
5. 用户偏好可同步云端；本机工作区通过设备安装 ID 与账户绑定。

当前 `local_bootstrap` 只是单机开发期的适配层，不等同于把用户自动提升为管理员。代码和页面始终使用两个不同 principal。

## 人工验收

1. 从工作台点击“模型与设置”，应打开 `/settings/profile`，不出现弹窗。
2. 用户设置的“生成偏好”页面不得出现任何 API Key 输入框。
3. 修改分析质量、预算或默认模型并保存，刷新后仍保持。
4. 进入 `/admin/providers`，页面应使用独立后台侧栏，不显示工作台导航。
5. 管理后台可看到 Provider 配置状态和密码输入框，但服务端不会返回密钥明文。
6. 在平台后台切换“模型 / 媒体 / 运行环境”，URL 与内容同步变化。
7. 回到用户设置后，用户只能选择平台已提供的模型，不可编辑 Provider 地址。
