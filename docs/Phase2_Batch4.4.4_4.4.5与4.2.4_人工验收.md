# Phase 2 · Batch 4.4.4、4.4.5 与 4.2.4 人工验收

更新时间：2026-08-06

## 1. 验收结论边界

本轮代码、自动化测试、静态检查、生产构建和无费用浏览器冒烟已完成。人工验收分为两类：

- 无费用验收：资产迁移、跨项目引用、资产改名／移动、项目解除关联、任务状态 UI、自动化伪云端契约；
- 有外部成本验收：真实百炼图片生成、真实 Codex + ImageGen、可选 VLM 语义质检。

`FakeCloudStorageDriver` 只用于验证架构扩展缝，不代表已经接入 OSS、COS、S3 或 ViralDNA 云端。人工验收时不应看到或寻找“上传云端”按钮。

## 2. 验收前准备

1. 确认当前工作区是可用于测试的工作区，重要文件已自行备份。
2. 双击 `scripts\start.bat`；Web 地址应为 `http://127.0.0.1:4174`，API 为 `http://127.0.0.1:8000`。
3. 打开“模型与设置”，确认国内 API 或本机 ImageGen 至少有一种已配置；仅做资产验收时可不配置模型。
4. 真实模型验收前为创作方案设置较低但足够完成一次调用的预算上限。
5. 第一轮保持“生成后使用 VLM 做语义质检”关闭，先单独确认图片生成；VLM 在后续单独开启。
6. 选择一条已有完整分镜的分析记录，创建或打开一个可编辑创作方案。

建议把以下信息记录在验收备注中：工作区名称、项目 ID、分镜 ID、模型／工具、run ID、开始时间、结束时间、预计费用和实际费用。

## 3. Batch 4.4.4：项目资产引用与旧资产迁移

### 3.1 旧资产无感迁移

1. 打开左侧“资产库”。
2. 检查此前项目中上传的人物、产品、服装或场景参考是否出现，名称、类型、缩略图和权利信息应保留。
3. 打开一个竖版资产详情。
4. 关闭并重新启动 API，再次打开资产库。

通过标准：

- 旧资产只出现一次，没有因重启重复迁移；
- 原图和缩略图可正常读取；
- 竖版图片完整显示，不被中心裁切；
- 页面没有“工作区版本高于当前支持版本”提示；
- 不需要手工搬移旧资产文件。

### 3.2 从资产库关联到项目

1. 打开创作方案的“参考资产”区域。
2. 点击从资产库选择，选择一个已有资产并建立项目关联。
3. 在某个分镜绑定该资产，并在图片提示词中通过 `@资产名` 插入关联。
4. 保存后离开方案，再重新打开。

通过标准：

- 资产缩略图、类型和名称正确；
- 重新打开后项目关联、分镜绑定和 `@资产` 仍存在；
- 同一资产再次选择时不会创建第二份全局资产或第二份项目有效关联；
- 生成输入摘要显示稳定资产关联，而不是本机文件路径。

### 3.3 跨项目复用、改名和移动目录

1. 在第二个创作方案中关联同一个资产。
2. 回到资产库，将资产改名并移动到另一个一级目录。
3. 分别重新打开两个方案。

通过标准：

- 两个项目都显示新名称；
- 分镜绑定和 `@资产` 关系没有断开；
- 移动目录不触发媒体文件重新上传或复制；
- 原图和缩略图仍能正常读取。

### 3.4 解除项目关联不删除资产

1. 在第一个项目中解除该资产的项目关联。
2. 打开第二个项目和全局资产库。

通过标准：

- 第一个项目不再显示该资产；
- 第二个项目仍可使用该资产；
- 全局资产库中的资产、原图和缩略图仍存在；
- 已冻结 Revision 仍能读取其资产快照。

## 4. Batch 4.4.5：混合存储扩展缝

本批没有真实云端 UI，验收方式是运行伪云端契约测试：

```powershell
.\.venv\Scripts\python.exe -m pytest services\api\tests\test_storage_objects.py services\api\tests\test_project_assets.py -q
```

通过标准：

- 同一 `StorageObject` 可同时拥有本地和模拟云端副本；
- 重复复制保持幂等；
- 两个副本的对象 ID 和 SHA-256 一致；
- 本地副本缺失、模拟云端健康时状态为 `download_required`；
- 所有副本缺失时状态为 `unavailable`；
- 项目快照不包含绝对路径、工作区相对路径、`object_key` 或临时 URL；
- 逻辑目录移动不改变底层对象键。

若未来接入真实 OSS／COS，应另开验收批次，至少验证凭据隔离、分片上传、校验和、下载物化、签名 URL、限流重试、流量费用和唯一健康副本保护。

## 5. Batch 4.2.4：持久化图片生成任务

### 5.1 排队、轮询和跨页面恢复

1. 保持 VLM 质检关闭。
2. 打开一个未审批分镜，选择“关键帧编辑”或“纯文生图”。
3. 选择本次使用的国内 API 或本机 ImageGen，候选数量先设为 1。
4. 点击生成。
5. 立即观察状态，然后切换到其他分镜或资产库，再返回当前分镜。

通过标准：

- 创建操作立即进入 `排队中` 或 `生成中`，页面不会因长请求卡死；
- 返回分镜后仍能恢复当前 run 并继续刷新状态；
- 完成后只显示本次 run 的真实候选；
- 候选未被自动选中或审批；
- run 中能读取 provider／model／adapter、请求指纹、开始／结束时间和成本信息。

### 5.2 取消

优先使用本机 ImageGen 测试取消，避免远程 Provider 已计费但不支持服务端取消。

1. 再发起一个生成任务。
2. 在 `排队中` 或 `生成中` 时点击“取消任务”。
3. 等待状态稳定后重新打开分镜。

通过标准：

- 状态最终为 `已取消`，不会停留在 `正在取消`；
- 本机工具进程被结束，不继续写入候选；
- 已取消 run 不进入候选审批区；
- 页面刷新或 API 重启后仍显示取消结果；
- 如果远端调用已被 Provider 接收，界面不会声称平台费用已撤销。

### 5.3 失败重试与 lineage

1. 使用一个可控失败场景，例如暂时选择未配置的本机工具、让假工具返回错误，或选择一条已有失败 run。
2. 确认错误码、简体中文说明和处理建议可读。
3. 修正配置后点击“重试”。

通过标准：

- 重试创建新的 run ID，不覆盖原失败记录；
- 新 run 显示 `retry_of_run_id` 和递增重试次数；
- 修正后可正常完成；
- 原失败 run 仍可用于审计；
- 重试不会自动改用另一种引擎。

### 5.4 API 重启恢复

远程任务在 Provider 已接收后重启可能已经产生费用，不建议用付费模型故意中断。该策略默认通过自动化测试验收：

```powershell
.\.venv\Scripts\python.exe -m pytest services\api\tests\test_generation_jobs.py -q
```

预期策略：

- 尚未 claim 的 `queued` 任务在启动时重新排队；
- 已是 `running` 且外部状态未知的任务标记为 `generation_interrupted`，由人工决定是否重试；
- `cancellation_requested` 在启动时终结为 `cancelled`；
- 不自动重发状态未知的远程任务，避免重复计费；
- 两个 SQLite worker 只有一个能原子 claim 同一任务。

## 6. 可选 VLM 语义质检

此步骤会额外调用大模型并产生 Token 费用。

1. 在“模型与设置”启用“生成后使用 VLM 做语义质检”，保存设置。
2. 选择一个包含人物或产品参考资产的单镜头，只生成 1 张候选。
3. 等待图片生成和语义质检都完成。
4. 查看候选质检说明和 run 成本。

通过标准：

- 候选显示 `通过`、`风险`、`证据不足` 或 `预算跳过`之一，而不是把未执行显示为通过；
- 结果包含人物、产品、服装、场景或异常文字的结构化证据；
- 低置信度不会自动淘汰候选；
- 高置信度通过也不会自动审批候选；
- VLM Token、请求 ID、预计费用和实际费用并入 run 明细；
- 项目预算不足时在调用前跳过，不继续产生 VLM 费用；
- 最终仍由人工选择和确认候选。

完成后如暂时不需要语义质检，建议关闭该开关以控制后续成本。

## 7. 真实双模式单镜头验收

### 7.1 国内大模型 API

1. 核对百炼区域、模型、API Key 校验状态和项目预算。
2. 选择 `国内大模型 API`，候选数量为 1，VLM 先关闭。
3. 发起一次关键帧编辑或纯文生图。
4. 核对输出尺寸、参考资产一致性、Provider 请求 ID 和实际费用。

### 7.2 Codex + ImageGen

1. 在设置中执行本机检测和网络／登录测试；这些检查本身不生成图片。
2. 确认包装器、Codex CLI、模型策略、推理强度、超时、单并发和成本口径。
3. 选择 `本机 ImageGen`，候选数量为 1，发起一次生成。
4. 核对原关键帧、提示词、参考图是否被正确传递，输出是否进入当前 run 目录。

通过标准：两种模式都使用相同候选区、人工选择、审批、Revision、缓存和成本台账；任何一种失败都不会静默降级到另一种。

## 8. 四分镜端到端验收

只有单镜头通过后再执行：

1. 对目标视频的 4 个分镜逐一生成 1 张候选。
2. 每个分镜人工选图并确认；不满意时修改提示词或参考资产后重新生成。
3. 检查上游修改是否创建新 Revision，并使受影响的旧候选／审批过期。
4. 4 个分镜全部审批后检查阶段门禁。

通过标准：图片阶段显示 4/4 已确认，并允许进入下一阶段；任意未确认、已舍弃或已过期分镜不能被错误计入门禁。
