# 视频生成模型参考路由实施说明

> 状态：已确认实施
>
> 生效日期：2026-08-16
>
> 范围：分段视频生成阶段的人物身份、动作视频、图片白模和 Provider 素材映射。本文不代表“原视频 + 替换资产一键生成”整体产品方案已经定稿。

## 1. 目标

同一套分镜和资产不能用同一种请求格式发送给所有视频模型。ViralDNA 在创建付费任务前先解析一条模型专属参考路由，并明确回答：

- 谁是人物身份的唯一来源。
- 动作和运镜来自视频、图片还是文字。
- 白模是否会提交给 Provider。
- 原始真人关键帧是否会被排除。
- 当前能力是结构控制、动作参考还是提示词引导。
- 发生降级时实际采用了什么方式。
- 哪些基础设施尚未就绪，因而必须阻止生成。

路由解析是服务端的最终安全边界。前端只负责展示，不能绕过服务端策略。

## 2. 当前模型路由矩阵

| 模型族 | 人物身份来源 | 动作／运镜来源 | 白模 UI | 语义强度 | 当前状态 |
|---|---|---|---|---|---|
| Seedance 2.0 / 2.0 Fast / 2.0 Mini | 火山方舟托管演员 Asset ID | 视频白模；缺失时回退图片姿态与文字 | 显示图片、视频白模和托管演员 | 动作参考 | 可用；必须先绑定托管演员 |
| MiniMax H3 | 已确认目标人物图 | 视频白模；缺失时回退图片姿态与文字 | 显示图片、视频白模 | 动作参考 | 可用；官方全能参考接口已支持图片与视频组合 |
| 阿里 Wan VACE | 一张目标人物参考图 | `video_repainting` + `posebody` 控制视频 | 显示视频白模 | 结构控制 | 请求映射已实现；公网／OSS 媒体暂存完成前禁用 |
| 百炼 Wan 2.7 参考生视频 | 按顺序确认的目标画面 | 有序目标画面与文字 | 不显示视频白模 | 多图参考 | 可用 |
| MiniMax Hailuo 2.3 / Fast | 已确认的单张目标关键帧 | 文字动作描述 | 不显示视频白模 | 提示词引导 | 可用；不宣称视频动作控制 |

“白模生成成功”不代表模型一定会接收白模。切换模型时由路由重新计算提交清单；不支持视频参考的模型不会收到历史视频白模。

## 3. 能力模型

核心能力定义位于：

~~~text
services/api/src/viral_dna_api/reference_routes/
├── domain.py
└── resolver.py
~~~

`VideoReferenceRouteCapability` 与 Provider 请求分离，主要字段包括：

- `route_id`：稳定的模型无关路由标识。
- `identity_transport`：托管资产、参考图或无人物身份。
- `motion_transport`：参考视频、控制视频、图片姿态加文字或无动作输入。
- `motion_semantics`：`structural_control`、`guided_reference`、`suggestive`。
- `accepts_raw_person_images`：是否允许原始真人画面跨越 Provider 边界。
- `supports_pose_proxy_image` / `supports_motion_proxy_video`：中间资产能力。
- `show_motion_proxy_controls`：前端是否显示白模操作。
- `fallback_route_id`：主路由不可用时允许的显式回退。
- `requires_public_media_url`：是否依赖 Provider 可访问的媒体 URL。

模型目录在 `video_generation/catalog.py` 中声明能力。新增模型时必须先声明完整路由，不能再仅用“是否支持有序多图”判断可用性。

## 4. 路由解析规则

### 4.1 Seedance

1. 托管演员是唯一身份来源。
2. 原始真人或身份不明的关键帧不提交给 Seedance。
3. 已启用的视频白模只提供动作、姿态、人物位置和镜头运动。
4. 没有视频白模时，明确回退为图片姿态或文字动作描述，并提示动作还原强度降低。
5. 未绑定托管演员时，在创建付费任务前阻止生成。

### 4.2 MiniMax H3

1. 第一张已确认目标人物图是身份与外观来源。
2. 视频白模以 `role=reference_video` 发送，只用于动作与运镜参考。
3. 其余未提交画面保留在项目中，并写入排除清单，不能静默丢弃。
4. 视频白模缺失时回退到目标人物图加文字动作描述；UI 标记为回退，不伪装成强控制。

官方参考：[MiniMax H3 视频生成与全能参考](https://platform.minimaxi.com/docs/guides/video-generation)。

### 4.3 Wan VACE

Provider 请求结构为：

~~~json
{
  "model": "wanx2.1-vace-plus",
  "input": {
    "function": "video_repainting",
    "prompt": "目标视频描述",
    "video_url": "https://provider-visible.example/motion.mp4",
    "ref_images_url": ["https://provider-visible.example/actor.png"]
  },
  "parameters": {
    "control_condition": "posebody",
    "strength": 1.0,
    "prompt_extend": false,
    "watermark": false
  }
}
~~~

VACE 不接受工作区本地文件路径。当前代码已实现请求映射和阻断错误，但媒体暂存层尚未实现，因此模型保持“预留”状态。只有目标人物图和控制视频都获得 Provider 可访问的 HTTP、HTTPS 或 OSS 临时 URL 后才能开放。

官方参考：[万相 2.1 VACE 视频编辑 API](https://help.aliyun.com/zh/model-studio/legacy-wanx-vace-api-reference)。

### 4.4 不支持视频参考的模型

- 不显示“生成视频白模”与视频白模历史。
- 使用已确认的目标关键帧作为首帧／人物画面。
- 动作只由文字描述引导。
- 不能在 UI 中显示“动作视频已应用”或“结构控制”。
- 已存在的视频白模继续保存在本地，但不进入 Provider 请求。

## 5. Provider 物理隔离

各 Provider 请求映射继续放在独立文件：

~~~text
video_generation/providers/
├── seedance/request_mapper.py
├── minimax/h3_request_mapper.py
├── minimax/hailuo_request_mapper.py
└── bailian/request_mapper.py
~~~

Provider mapper 只接收服务端规划后的素材，不自行猜测路由。路由 ID、有效路由、动作语义和控制条件进入请求快照与任务指纹，用于审计、重试和防止重复计费。

兼容旧任务时，会接受“仅缺少新增路由元数据、其余输入完全一致”的旧指纹；任何真实输入变化仍会阻止自动重提。

## 6. UI 与交互

“人物参考策略”区域按所选模型动态显示：

- 路由名称。
- 身份来源与动作来源。
- `结构控制`、`动作参考` 或 `提示词引导` 标签。
- 安全回退提示。
- 阻塞原因。
- 白模安装、生成、启用、停用、预览和历史，仅在当前路由需要时显示。

“生成依据与中间过程”默认收起，展开后显示：

- 人物身份来源。
- 动作与运镜来源。
- 真人素材隔离规则。
- Provider 媒体传输状态。
- 被排除素材和回退警告。

切换模型、绑定演员、启用或停用白模、方案 Revision 变化后，前端重新请求服务端策略；不能复用旧模型的 UI 判断。

## 7. 安全与费用边界

- Seedance 不得因托管演员缺失而回传原始真人关键帧。
- H3 缺少视频白模时可以显式回退，不得显示为视频动作控制。
- VACE 缺少公网媒体 URL 时必须阻止，不得创建上游任务。
- 历史白模不因切换模型而删除，但不支持的模型不会收到它。
- 请求快照保存实际路由、实际提交素材、排除素材和动作语义。
- 路由解析和素材校验发生在创建上游任务之前。

## 8. 后续工作

1. 实现账户／工作区级媒体暂存接口，为 VACE 生成短期签名 URL 或 OSS 临时 URL。
2. 对 VACE 北京／上海地域、Workspace ID、Endpoint 与 API Key 进行同地域校验。
3. 增加真实 Provider 沙盒验收记录和最近验证时间。
4. 在生成结果详情中展示实际路由、Provider 请求 ID 与真实成本。
5. 为自动选模加入动作还原度、隐私限制、成本和速度权重。

## 9. 人工验收清单

1. 选择 Seedance 2.0：未绑定演员时应阻止；绑定后显示托管演员与白模操作，原始真人图标记为不提交。
2. 为 Seedance 启用视频白模：策略应显示“动作参考”；停用后显示已回退和动作还原较弱。
3. 选择 MiniMax H3：显示目标人物图和视频白模；启用视频白模后，生成依据应为 `reference_video`。
4. 停用 H3 视频白模：仍允许生成，但必须显示回退提示。
5. 选择 Hailuo 2.3：不显示视频白模入口，生成依据显示目标关键帧与文字动作描述。
6. 在项目中保留 Seedance 托管演员后切换 H3/Hailuo：不应强制切回 Seedance，也不应把火山 Asset ID 发给 MiniMax。
7. Wan VACE 在媒体暂存未配置时不应出现在可调用模型中；直接构造请求也应返回 `video_public_media_transport_required`。
8. 查看生成任务快照，确认包含 `route_id`、`effective_route_id`、`motion_semantics`、提交素材和排除素材。
