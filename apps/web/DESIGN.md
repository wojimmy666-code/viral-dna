# ViralDNA UI System 1.0

ViralDNA 是面向长时间桌面创作与分析工作的产品界面。用户通常在室内常规光线下持续阅读报告、编辑提示词并操作生成任务，因此界面采用安静的浅色工作台、克制的紫色交互强调和高可读性的紧凑排版。

本文件是 Web 端的设计契约。新页面和新组件必须遵守这里的规则；页面样式只能决定业务布局，不能自行创建新的字号、文字灰度、按钮或状态视觉。

适用边界：本文件下述“全系统”“Web 端”“业务页面”规则均指账户工作台及其业务界面。公开官网 `/` 使用独立的 [首页设计契约](src/landing/DESIGN.md) 与邻近 sidecar；其深色影像、大标题和 `--home-*` 令牌仅限 `src/landing/`，不改变本文件的工作台规范。

## Typography / 排版

全系统只使用系统无衬线字体与以下四档字号：

| 角色 | 令牌 | 尺寸 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| Page | `--type-page-size` | 20px | 600 | 页面唯一主标题 |
| Heading | `--type-heading-size` / `--type-subheading-size` | 16px | 600 | 区块、面板、弹窗标题 |
| Body / Label | `--type-body-size` / `--type-label-size` | 14px | 400 / 600 | 正文、输入、按钮、字段标签、提示词 |
| Caption | `--type-caption-size` | 12px | 400 / 600 | 时间、模型、状态和辅助信息 |

- 普通字重只能使用 `--type-weight-regular` 与 `--type-weight-semibold`。
- 中文标题与 UI 文本使用正常字距，不使用大写眉题或宽字距标签。
- 标题行高使用 `--type-leading-tight`，控件使用 `--type-leading-ui`，正文与编辑器使用 `--type-leading-copy` / `--type-leading-editor`。
- 长正文建议限制在 65–75ch；提示词编辑器按业务要求占满可用宽度并正常换行。
- 移动端输入框保持 16px，防止移动浏览器自动缩放。

## Color / 颜色

普通文字只有两个层级：

- `--text-primary`：标题、字段值、关键数据。
- `--text-secondary`：正文说明、标签、元信息。

`--text-disabled` 只表示不可操作状态。深色媒体界面使用 `--text-on-dark` 与 `--text-on-dark-muted`。

紫色 `--accent` 只用于：

- 主操作；
- 当前选中或活动状态；
- 键盘焦点；
- 可点击链接；
- `@` 素材引用。

成功、警告、错误、信息必须使用 `--status-*-text/bg/border`。不能使用颜色作为唯一状态线索，必须同时提供图标或文字。

普通结构使用 `--surface-*` 与 `--border-*`。页面不得通过新增近似灰色或大量浅色卡片制造层级。

## Spacing and geometry / 空间与形状

- 间距只使用 `--space-1/2/3/4/6/8`，对应 4/8/12/16/24/32px。
- 默认控件高 `--control-height`（40px），紧凑控件 36px，突出控件 44px。
- 控件使用 `--radius-control`，普通面板使用 `--radius-panel`，弹层使用 `--radius-overlay`。
- 胶囊圆角只用于状态标签或真正的 pill 控件。
- 普通面板依靠边框和空间分组；不同时叠加边框与大面积柔和阴影。
- z-index 必须使用 `--z-dropdown/sticky/modal-backdrop/modal/toast/tooltip`。

## Shared components / 共享组件

新页面优先使用 `src/ui/system`：

- `PageShell`：页面字体、颜色和最小宽度基线。
- `PageHeader`：唯一页面标题、说明与页面级操作。
- `SurfacePanel`：需要真实边界的内容面板。
- `SectionHeader`：区块标题与操作。
- `StatusBadge`：neutral / active / info / success / warning / danger。
- `InlineMessage`：行内信息、成功、警告和错误反馈。
- `Button` / `IconButton`：普通操作与纯图标操作的唯一实现。

设置页继续使用 `src/ui/settings`，其底层已复用 `PageShell` 和 `SurfacePanel`。按钮样式集中在 `ui/system/buttons.css`；已有角色类仍用于布局兼容及保留原生语义的链接，不为单个页面重新发明按钮。

### Action buttons / 操作按钮

| variant | 视觉 | 用途 |
| --- | --- | --- |
| `primary` | 紫底白字 | 生成、保存、确认；同组一个主操作 |
| `secondary`（默认） | 白底、中性细边 | 取消、返回、刷新、重试 |
| `text` / `quiet` | 透明底、紫字 / 次级中性字 | AI 修订、复制、辅助查看 |
| `warning` | 白底、红字淡红边 | 停止任务、断开、移除确认 |
| `danger` | 红底白字 | 最终永久删除确认 |

- 默认高 40px，`size="compact"` 为 36px，`size="prominent"` 为 44px；圆角 8px，边框 1px，文字 14px／600，图标 18px，间距 8px。触屏和窄屏最小点击区域 44px；顶栏图标始终 44px。提示词预览辅助按钮仍遵守已批准的 12px 弱化规范。
- `loading` 是受控状态，自动禁用按钮并提供 `aria-busy`；`loadingLabel` 在空闲与处理中均参与测量，防止宽度跳变。调用方继续负责请求锁、错误显示、幂等 ID、费用与二次确认，组件不自动执行任何请求。
- `IconButton` 必须提供 `label`、`aria-label` 或 `title`，普通表单按钮必须显式声明 `type="submit"`。导航及下载保留链接，不伪装成点击处理器。
- 统一悬停、按下、焦点、禁用、加载及减少动态效果状态；悬停不位移。布局允许换行；移动端主要操作按页面需要全宽。官网和媒体控件不套用工作台按钮皮肤。

```jsx
import { Button, IconButton } from "./ui/system";

<Button variant="primary" type="submit">保存设置</Button>
<Button variant="warning" size="compact" loading={stopping}
  loadingLabel="正在停止…" icon={<Stop />} onClick={cancelTask}>停止任务</Button>
<IconButton label="关闭" onClick={close}><X /></IconButton>
```

`npm run check:design` 会阻止普通按钮回退为原生裸按钮，并检查图标名称及提交类型。导航、菜单、媒体、选择卡等特殊控件使用既有类名或显式 `data-ui` 用途标记，不得用标记绕过普通操作按钮检查。

### Business dialogs / 业务弹窗

2026-09-26 统一实施约定：共享弹窗组件及存量迁移已实现；范围、盘点和实际验证记录见 [统一弹窗方案](../../docs/roadmap/business-dialog-unification.md)。浏览器视觉验收仍待环境恢复后完成，不代表已部署。本规范覆盖已有站内确认／输入窗口，不仅替换浏览器 `alert/confirm/prompt`。

#### 结构与视觉

- 共用 `Dialog` 外壳；`useActionDialog` 提供默认确认、`kind: 'input'`、`kind: 'generation'` 三类用途。大型资产／风格选择器、空间参考和构图窗口只统一外壳，保留内容布局与业务校验。基础组件不发业务请求；`onConfirm` 的 `mutate` 包裹调用方的最终写入，以控制超时与重复提交。
- 工作台使用 `--surface-panel` 白底、`--border-default` 细边、`--radius-overlay` 12px 圆角与 `--shadow-overlay`；遮罩统一使用 `--overlay-backdrop` 的 40% 黑色、不模糊背景，不在页面各设透明度。官网深色主题、媒体预览、抽屉不套用白色居中窗口；媒体使用 `skin="media"`，设置等抽屉使用 `placement="drawer"`，共享适用的基础交互。
- 从上至下为标题／关闭、正文／字段／影响说明、错误反馈、底部操作。标题左对齐 16px／600，正文及字段 14px，辅助信息 12px；重要费用与不可恢复警告不能降为弱化脚注。不堆叠大图标、重复标题或多层卡片。
- 桌面内边距 24px，窄屏 16px，字段和区块间距使用既有空间令牌；底部按钮间距 8px，取消在左、主动作在右，复用 `Button`／`IconButton`。一个窗口只强调一个主动作；保存／生成用 `primary`，断开／移除用 `warning`，最终永久删除用 `danger`。
- 确认、简短输入、费用确认的目标宽度分别为 440／480／560px；大型窗口按内容使用 960／1200px 上限，不强行压缩成确认框。所有尺寸必须受可视区域限制，窄屏至少留 16px 安全边距，长正文在窗口内部滚动，标题和操作区保持可达；手机输入 16px、触控目标至少 44px，软键盘不能遮住唯一提交入口。
- 按钮用明确动作和必要数量，如“创建目录”“保存名称”“生成 1 张”“永久删除 3 个项目”；不统一为含糊的“确定／是”。批量摘要展示真实数量，名称可换行，不能截掉关键对象或风险。

#### 用途与反馈

| 用途 | 内容要求 | 反馈与关闭 |
| --- | --- | --- |
| 普通确认 | 动作、对象、实际影响 | 取消不修改数据，成功后关闭 |
| 危险确认 | 删除／保留范围、恢复能力、对象数量 | 风险色仅强调必要区域，失败原位显示 |
| 输入 | 明确标签、现有值、实际校验规则 | 无效输入就地提示，提交失败保留草稿 |
| 生成确认 | 本次真实模型、范围、数量及适用参数；真实估价或未知费用说明 | 保留原费用门禁，受理成功后关闭并在工作台跟踪任务 |
| 大型业务窗口 | 保留选择器／编辑器自己的内容与校验 | 共用外壳，保留草稿、权限、容量和版本保护 |

- 成功与一般状态沿用 Toast／通知；字段错误与操作失败优先就地反馈，不使用连续消息弹窗。已批准的候选删除／恢复内联确认、历史展开等模式保持不变。
- 未知费用显示“费用暂不可估算”及原因，并说明不代表免费；有估价时标明估算依据与实际结算差异。禁止编造金额或显示虚假零费用；不借统一 UI 移除预算限制、已有显式确认或人工采用。

#### 生命周期与可访问性

- HTML `<dialog>` 可以作为统一外壳的底层；禁止新增浏览器业务 `alert/confirm/prompt`。浏览器文件选择、权限与 `beforeunload` 不可替换成普通站内窗口；刷新离开保护必须保留。
- 提供关联标题、必要说明与错误的可访问名称；背景不可交互，Tab 留在当前模态内，关闭后归还焦点至触发入口或仍存在的合理后继。关闭按钮有可访问名称；解除窗口时恢复原滚动状态。
- 普通无草稿窗口允许 Escape／点击遮罩取消；费用及危险确认不以点击遮罩关闭，但提交前允许取消／Escape。输入或复杂编辑窗口有未保存草稿时先沿用离开保护，必要时在原窗口内切换到舍弃确认。会话恢复等安全窗口保留专用关闭限制。
- 风险窗口初始焦点放取消或说明，避免打开窗口的 Enter 连带触发主动作；简短输入初始聚焦字段，校验通过后可提交，中文输入法组合期间的 Enter 不提交。错误出现时可感知，不依赖颜色。
- 提交中禁用重复操作与意外关闭；超时必须退出无限等待，区分已失败和结果待核验。失败保留内容和可操作反馈，结果不明不得创建新的重复收费请求；普通关闭不代表取消已受理任务。
- 弹窗不能依赖阻塞浏览器来冻结上下文。打开时绑定目标与参数，提交前重新验证权限、租约、版本和草稿；变化时停止提交并要求重新核对。卸载／切项目／换账号后不得执行迟到的确认，恢复登录不自动重放操作。
- 不让资产选择器再层叠通用确认遮罩；相关确认优先作为原窗口内的下一步。确需会话恢复等受控嵌套时，仅顶层可交互，并验证焦点、滚动与恢复行为；不能只增加 z-index 掩盖问题。

#### 防回退检查

`check:design` 已接入共享弹窗控制器、实际业务处理函数及静态规则测试。原生业务调用存量已清零；禁止页面新增私有模态外壳、根节点皮肤和遮罩。保留原有站内内容类用于业务布局，不使用全局 `dialog` 样式强行覆盖官网或媒体窗口。少量官网／导航／非模态菜单例外按文件列入测试白名单。

最终写入经 `mutate` 时，60 秒无回复会退出忙碌并提示核验；网络／服务端结果未知禁止原窗口再次提交。已有幂等接口复用原请求 ID，其余接口不提供自动重试。不能以按钮防重代替服务端幂等性，也不能把模拟测试通过写成真实付费任务验证。

验收必须覆盖真实请求次数、取消零写入、失败保留草稿、费用与危险说明、防重／未知结果、权限／编辑锁失效、中文输入法、焦点归还、长名称、390px 和 200% 缩放。使用隔离数据及模拟请求，不为弹窗验收调用真实付费模型或删除用户数据。

## Page patterns / 页面模式

### 账户与工作台顶栏

- 登录后使用单一 56px 顶栏，`--account-header-height` 同步通知抽屉与侧栏偏移；不堆叠账户条和第二行工具栏。
- DOM 与视觉顺序均为紫色播放标识与 ViralDNA、侧栏折叠入口、账户名称／类型、页面原有搜索、通知、用户名菜单。品牌固定在最左上角，侧栏不重复显示品牌及“视频逆向拆解系统”副标题，菜单导航上移。账户类型使用 Caption／次级文字；账户名和用户长名省略，保留完整 title，不缩小正文。
- 主要操作目标 44px，组间距沿用 16px／窄屏 8px，白色表面与一条底部分隔线；无全局问号帮助按钮。
- 820px 及以下，品牌只保留图标，账户图标和类型让位于名称与操作；600px 及以下，账户名称和类型移到账户菜单中。原有搜索改为点击图标打开浮出输入框，Escape 关闭并归还焦点，不生成常驻第二行。导航开关在桌面折叠侧栏，在窄屏打开抽屉，抽屉内保留关闭按钮。专注页面继续不显示搜索。
- 账户菜单独立于工作台控件；成员、存储、只读及独立设置页面无工作台控件时也保留品牌和账户入口，但不显示无效的侧栏开关。品牌整体为“返回工作台”链接，普通账户回 `/projects`、admin 回 `/admin/accounts`，不跳官网或退出登录；保持原标识外观，点击区域至少 44px，键盘焦点清晰。跳转须等待统一草稿保存，失败时在品牌下方短提示并保留原页；等待中防重复点击，取消过期跳转。存储页仍保留“返回资产库”。公开官网和独立登录表面不应用此顶栏。

### 分析报告

- 结论优先，证据和推断过程渐进展开。
- 章节标题 16px，正文 14px，证据元信息 12px。
- 普通摘要、编号和依据标签使用中性色，不使用装饰性紫色。
- 减少嵌套卡片；同一报告区块优先使用分隔线、列表和留白。

### 设置

- 页面标题 20px，设置组标题 16px。
- 字段标签 14px/600，值 14px/400，帮助文字 12px。
- 所有输入、选择、开关必须提供 default、hover、focus、disabled、error 状态。
- 设置组使用分割线组织；只保留一个页面级主保存操作。

### 提示词与生成工作台

- 提示词与高亮镜像层统一为 14px、1.55 行高和 10px 12px 内边距。
- `@` 引用与正文同字号，只用紫色和 600 字重区分。
- 图片和视频提示词必须复用相同文本角色。

## Responsive / 响应式

- 1440px：完整桌面布局。
- 1280px：保持主要双栏，不允许内容横向溢出。
- 1024px：受限工作区按容器宽度降为单栏。
- 768px：侧栏或设置导航切换为横向/折叠结构。
- 390px：操作换行，主按钮可占满一行；不能通过缩小正文塞入内容。
- 响应式调整布局结构，不使用流式字体缩放。

## Accessibility and motion / 可访问性与动效

- 普通正文和占位符对比度至少 4.5:1。
- 所有交互可键盘访问并显示统一焦点环。
- 触控目标至少 44×44px；桌面紧凑控件必须保留足够点击区域。
- 状态变化使用 150–200ms 的 ease-out 过渡，不使用无意义的入场动画。
- 所有非必要动效必须提供 `prefers-reduced-motion` 关闭方案。

## Engineering rules / 工程约束

- CSS 中的 `font-size` 和 `font-weight` 必须引用系统令牌；只有图形隐藏可以使用 `font-size: 0`。
- 普通 `color` 属性必须引用语义令牌；强制颜色模式的 `CanvasText` / `HighlightText` 是例外。
- 禁止新增 `--production-*` 等页面私有排版或文字颜色变量。
- 禁止新增 500、700、800 等普通 UI 字重、数值字距和 `text-transform: uppercase`。
- 业务页面不得使用旧兼容变量 `--purple/--ink/--muted/--line/--panel/--canvas`。
- 修改 UI 后必须运行 `npm run check:design`、`npm run test:web` 和 `npm run build:web`。
