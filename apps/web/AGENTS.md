# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Branding

- 浏览器标签页图标始终复用侧边栏的项目标识：紫色圆角方块与白色播放三角。

## Independent accounts

- 资产与生成历史使用账户级服务器存储：个人默认 2 GB、企业默认 10 GB，企业成员共用额度，admin 手动调整。一个账户内按原文件内容去重，加入资产库不重复计量；系统缩略图和缓存不计用户额度，回收站仍占容量。生成完成即归档，不依赖采用或入库，不因项目归档和再次生成删除历史。同步只处理当前账户登记的文件，先确认 HTTPS 目标账户，再增量上传；本地文件保留，只有原文件校验成功才显示已同步。存储入口放账户菜单及资产库紧凑工具行，不增加主导航或持续弹出的成功提示。

- 个人和企业必须使用独立登录账户；本期不提供空间切换、个人/企业互转或一个登录用户加入多个账户。企业成员分别登录，共享本企业资产和项目，个人账户不提供成员管理。
- 前端登录与单 admin 后台登录相互独立。企业负责人管理本企业成员，后台管理账户开通/停用和平台配置；不引入自定义角色或多个后台管理员。
- 首次设置不显示、不生成、不读取初始化码；保留部署本机首次设置与旧数据归属确认。个人、企业负责人和成员的前端登录名强制为中国大陆 11 位手机号，后台仍固定 `admin`；创建、邀请和登录使用同一规则。所有账户密码至少 8 位，不强制复杂度组合；设置、登录、激活、重置、改密的前后端校验与文案必须一致。
- 最外层项目同一时刻只有一个用户会话/标签页可编辑，Skill 和分析报告流程遵循相同规则；其他成员可只读查看。租约失效时保留当前未提交内容供备份，禁止旧页面覆盖新编辑者。
- 账户入口、成员表单、只读提示沿用现有紧凑浅色紫色 UI。首次启用必须明确设置密码和旧工作区归属，不自动认领、复制或清空旧数据。

## Primary navigation

- 平台主侧边栏支持 232px 展开与 72px 图标栏；保留现有浅色、紫色视觉。进入原视频或 Skill 具体项目时自动收起，直接链接与刷新同样生效；同一项目内切换步骤、分镜或后台刷新不得覆盖用户手动展开。切换其他项目或离开后重新进入时重新收起，离开项目恢复普通页面的本机偏好；新建、列表、归档和回收站页面不触发项目自动收起。
- 收起后的主入口仍可直接点击，悬停或键盘聚焦显示名称；项目生命周期通过图标旁的浮层访问。仅改变外层布局，不因折叠卸载工作台、清空草稿或重置播放器。820px 及以下通过顶部菜单打开原生导航抽屉，保留全部主入口和生命周期，支持 Escape、点击遮罩关闭和焦点恢复；不再展示横向主导航或常驻窄图标栏。

- 第一期左侧主导航只显示新建项目、项目、资产库和品类库；不显示“工作台”或“提示词模板”独立入口。“项目”使用区别于资产库目录的项目类图标，并内嵌当前项目、已归档和回收站生命周期入口。逐视频生成的提示词仍保留在分析报告的“提示词”页签中，底层模板能力不因导航精简而删除。

## Platform connections

- 抖音、小红书、TikTok 和 Instagram 登录状态统一放在左侧“系统”分组的“平台连接”页面，不挤占第一期四个主导航，也不混入模型 API Key 设置。
- 四个平台按默认账户和当前设备分别配置、验证、暂停与断开；页面必须明确提示登录信息仅保存在本机，不在 API 响应、日志、工作区或分析报告中显示 Cookie 值。
- 新建分析识别粘贴链接的平台后，在输入框下方显示紧凑连接状态和配置入口；匿名采集仍优先执行，只有平台要求登录时才按策略读取该平台连接。
- 登录失效类失败使用可操作错误区，提供“配置平台”和“更新后重试”；重试复用原视频记录并新建分析版本，不重复创建分析记录。

## Record detail layout

- 分析报告与创作方案共用专注的项目详情布局：顶部不显示全局搜索和“新建项目”，正文不显示产品介绍区与“导入短视频”模块；项目卡上方保留紧凑面包屑，支持返回项目和方案列表；这些入口只保留在项目页和新建项目流程中。
- “新建项目”使用独立的 `/projects/new` 页面，只显示导入与分析参数表单；分析进度、分析报告和创作方案不得在该页面下方继续渲染。创建任务成功后立即进入 `/projects/:projectId` 项目详情，浏览器刷新、前进、后退和通知深链都必须恢复同一项目。
- 不再提供独立工作台首页；`/`、`/workbench`、`/records`、`/analyses/new` 和 `/workbench/records/:recordId` 仅作为旧链接兼容入口，分别跳转到对应 `/projects` 路由。

## Analysis record lifecycle

- 平台链接分析记录的默认名称使用采集到的视频真实标题；“抖音链接视频 / 小红书链接视频 / TikTok链接视频 / Instagram链接视频”只允许作为采集前的短暂占位名。真实标题返回后自动回填记录名称，但不得覆盖用户已经手工修改的名称。
- 用户界面将分析记录这一业务实体统一称为“项目”；“分析报告、分析状态、重新分析”等动作或结果名称继续保留。后端 API、数据库和前端内部 `recordId` 命名保持不变，避免与创作方案的内部 project 模型混淆。
- 项目管理采用高密度单列列表，不恢复双列卡片网格；列中显示缩略图、名称、分析状态、来源、一级目录、创作方案数量、更新时间和更多操作。创作方案数量在桌面端使用独立的克制文字链接，点击直接进入该项目的方案列表；窄屏端合并到项目元信息中。目录选择使用按内容收缩的紧凑触发器，目录名称与自定义下拉箭头间隔约 6px，箭头到创作方案入口至少保留约 28px；底层继续使用原生选择框保证键盘与系统菜单能力。行内方案入口显示“1 个方案”等完整文字，不放容易与下拉箭头混淆的魔法棒图标。
- “当前项目 / 已归档 / 回收站”是独立于分析状态的生命周期入口，桌面端嵌套在左侧“项目”导航下，窄屏端使用正文顶部紧凑切换栏；公开地址分别使用 `/projects`、`/projects/archived` 和 `/projects/trash`。
- 列表复选框始终可见；多选后使用页面底部悬浮批量操作栏。当前项目支持批量归档、移入回收站；归档支持恢复、移入回收站；回收站支持恢复和永久删除。
- 页面只保留一个生命周期主标题，项目数和当前目录筛选合并显示在主标题旁；不要在筛选栏与列表之间重复一行“当前项目 / 项目数”。
- 已有记录的后台刷新不得用整页加载态卸载列表；已经成功加载的缩略图在同一应用会话内需要保持显示，真实首次加载使用图片与骨架交叉淡入，禁止骨架先消失再露出空白底色。
- 移入回收站时保留原来的当前／归档来源，恢复后回到原生命周期；永久删除只允许在回收站执行，并保留资产库中的共享资产。

## Asset library home

- “全部资产”是资产库首页，不再平铺所有目录中的资产；正文先显示带封面的一级目录，再显示未分类资产。进入具体目录后才显示该目录的平铺资产列表；在“全部资产”使用搜索或类型／存储筛选时切换为跨目录的扁平结果列表。
- 目录封面优先使用用户手动指定的当前目录资产；未指定、指定资产被归档或移出目录时，自动回退到该目录最近更新的有效资产；空目录显示稳定的目录占位图。只保存资产 ID，不持久化临时缩略图 URL，以便未来本地／云端存储切换。
- 目录卡片与封面选择器中的横版、竖版和方形图片统一使用 `object-fit: contain` 完整显示。封面管理放在目录卡片的更多菜单和资产详情中的“设为所在目录封面”，不在卡片上堆叠常驻操作按钮。

## Prompt document editor

- 分析报告“提示词”页使用紧凑的内联折叠列表；所有分镜首次进入时默认收起，点击分镜摘要行独立展开或收起，允许多个分镜同时展开。切换到另一分析记录时重新恢复默认收起，自动保存产生的新修订不得改变当前展开状态。
- 每个展开分镜只有一个连续的纯文本 contenteditable 编辑区，不再暴露主体、场景、时序、转场和约束的表单控件，也不重复显示编译后的“模型输入”。底层 PromptShotDraft 仍是保存、冲突处理和模型编译的唯一事实源，连续文本必须可靠地序列化和解析回结构化草稿，禁止改存为不可编译的 HTML 字符串。
- `【主体与服装】`、`【场景】`、`【时序运镜】` 等语义标记与正文保持在同一文本流中，只通过克制的字重、灰度和浅色底区分；提示词正文统一为 14px／1.55、移动端 16px。编辑区域粘贴时剥离外部样式，语义标记和 @ 资产引用都按原子内容处理；@ 引用使用紫色与 600 字重，删除键或回退键一次删除完整引用。
- 收起行只显示分镜名称、时长与字数、一行内容摘要和复制操作；展开区只补充实际检测到的语言问题、恢复 AI 版本和连续编辑器，不常驻显示语言使用说明。列表保持白底、细分隔线和单层边界，不增加嵌套卡片或装饰性阴影。
- 工具栏统一提供自动保存状态、复制全文和“下载 TXT”；复制与下载必须复用同一个按文档顺序输出的纯文本序列化器，不包含 HTML 标签、JSON、内部 ID、保存状态或按钮文案。

## Production aspect ratios

- 新建创作方案时，默认输出画幅必须根据源视频尺寸或宽高比选择最接近的受支持画幅；当前支持 `9:16`、`16:9`、`1:1` 和 `4:5`，用户仍可在创建前手动调整。
- 分镜图片工作台中的“当前关键帧”和“AI 生成图”必须共用方案输出画幅作为预览画布；图片始终使用 `object-fit: contain` 完整显示，禁止用固定竖向高度或 `cover` 裁剪横版、竖版素材。

## Production video controls

- 分段视频的“原分镜时长”和“AI 生成时长”是两个独立概念：原时长保留精确小数用于时间线和剪辑，生成时长必须根据当前视频模型能力归一化后单独提交。
- 深度视频生成期间，进度、预计时间与取消操作必须直接显示在深度视频和引擎操作行下方，并取代生成按钮；不得同时保留一个禁用的“正在生成”按钮重复表达同一状态。
- 视频生成时长使用模型能力驱动的滑块；固定时长模型只显示合法停靠点，范围模型读取最小值、最大值和步长。切换模型时必须映射到最接近的合法时长，并同步更新成本预估。
- 视频候选预览必须把图片和视频完整约束在预览容器内，保持 `object-fit: contain`，不得因媒体固有宽高比裁掉画面或位于视频底部的播放控件。
- 视频候选阶段只负责生成、比较、确认采用和选择参与剪辑，不显示入点、出点、封面或基础质检面板；生成参数只提供“沿用原音频／生成新音频／静音”三种互斥声音策略。至少选择一个有效已采用视频即可进入“视频剪辑”，不再要求全部必需分镜完成。
- 入点、出点和逐片段声音调整统一放在下一阶段的独立视频剪辑模块中。候选时长与原分镜差异过大只作为节奏风险提示，不阻止进入视频剪辑。
- “沿用原音频”必须映射当前分镜在源视频中的精确音频区间且不把音频提交给视频生成模型；“生成新音频”只允许支持原生音频能力的模型，并以候选文件实际存在音轨为准；“静音”不进入任何主音轨。

## Production parameter controls

- 视频生成参数字段统一采用“标题行、主控件行、辅助说明行”的结构；标题行固定 22px，主控件固定 44px，辅助说明不得撑高或下移同排的其他控件。

## Production workspace layout

- “创作方案”列表和项目详情使用全宽专注布局，不显示分析报告右侧的 VLM 状态面板；VLM 状态只保留在“分析报告”工作区。
- 报告标题栏不放“创建方案”快捷按钮，创建入口统一保留在“创作方案”列表及空状态中；项目页顶部栏不显示“新建项目”，页面正文入口继续保留。
- 进入“创作方案”工作区后，共享报告标题栏不显示分析版本、重新分析或导出；这些报告级操作只在“分析报告”工作区保留。

## Production workflow navigation

- Skill 与“分析报告 → 创建视频”共用图片阶段门禁：至少一张有效、实际已采用的分镜图即可进入分镜视频；只生成或选择预览、归档／删除、不可读取图片不计数。按有效分镜中的逐画面采用计数，不要求一个多画面分镜全部采用，不以 `required` 标记筛选。图片页移除“必需分镜”复选框与阻断说明，摘要为“已采用 N 张”，按钮为“进入分镜视频”。前端、后端推进和 Skill 图片审批必须共用后端核验结果；返回图片页时使用图片阶段门禁，不能错用当前视频／剪辑门禁。保留历史 required 数据、候选、未采用分镜和已有下游结果，不自动采用、补图或回退阶段；单镜视频生成所需参考、视频到剪辑与导出校验不因此放宽。
- 原视频与 Skill 项目共用五步主导航：创作方案、分镜图片、分镜视频、视频剪辑、导出成片。Skill 的简报、风格、大纲分镜放在创作方案内；剪辑、配乐与字幕使用同一编辑器，人工画面锁定与声音确认仍分别保留。
- 共用工作台只保留一处标题和主导航；参考资产和版本记录通过标题工具栏进入。紫色只标识正在查看的页面，流程进度使用已采用数量、待确认、已完成表达。后台刷新不抢占正在编辑的页面。
- 切换步骤、分镜和离开编辑器之前必须刷新自动保存；失败时保留当前草稿与页面。按项目记忆步骤、分镜和候选，刷新与浏览器前进后退能够恢复定位。
- 原视频片段保留、源关键帧选择、原音频和源视频深度操作按实际素材能力显示；Skill 无对应源视频时隐藏这些操作，禁止展示不可用原图空框。

- “参考资产”是可选准备步骤，不得作为进入“分镜图片”的门禁；新建方案后至少解锁到分镜图片，零参考资产时允许直接使用原关键帧或纯文字生成。
- 当前查看页面与生产阶段必须分离：创作方案、参考资产和分镜图片可以自由切换；新增或修改上游输入只提示关联结果可能与新输入不同，不撤销人工采用、不强制重新生成或确认、不回退阶段。
- Skill 和分析报告创建视频共用非阻断更新规则：全局／局部提示词、参考资产、关键帧及画面结构更新后，保留已采用图片、视频、剪辑和导出。采用状态与输入新旧分别记录；新生成使用新输入且不自动替换采用结果。旧项目仅根据真实人工采用记录与可读取文件恢复，不能把未采用候选自动采用。未采用、必需素材缺失、权限／权利、并发版本冲突继续校验。
- 重新分析完成后，已有创作方案不得静默覆盖提示词。工作台使用常驻更新提醒和页内差异预览，按“当前方案 / 新分析”逐字段比较图片与视频提示词；未手工修改字段默认建议更新，存在手工修改的字段默认建议保留。
- “仅同步提示词”必须创建新 Revision，只修改用户明确选择的新提示词及方案的分析基线；参考资产、画面结构、图片／视频候选、已采用结果和工作流阶段全部保留。检测到分镜增删或画面拆合时停止自动应用，并明确留给后续结构同步流程处理。

## Production shot navigation

- 从图片阶段点击“进入分镜视频”时，后端按每个有效分镜中实际可读取的已采用图片记录参与名单；一个分镜多张采用图仍只算一个视频分镜，明确保留原视频的有效分镜也入选。至少一张实际采用图片的门禁不变。名单通过项目 Revision 持久化，两条创建流程的列表、数量、默认定位、排序、生成、参与剪辑和交接共用；不按预览、候选数或 required 标记推断。不在 GET／轮询中重新匹配，返回图片页明确再次进入才更新；未入选分镜、已有候选、提示词、采用、时间线和导出一律保留，不回退实际阶段。历史无名单项目在首次明确重新进入前保留原范围。视频列表拖拽只交换参与分镜的现有位置，不删除或挪乱未选分镜；越界深链回到名单内分镜。

- Skill 与分析报告创建流程的分镜视频列表标题只显示“分镜1”等编号，不拼接提示词。通过独立拖拽手柄排序，也支持手柄聚焦后上下方向键；先刷新草稿再保存项目分镜顺序，稳定 ID、原始时间范围、引用、候选和采用记录不变。列表点击、勾选参与剪辑和排序互不触发。
- 视频参与剪辑使用独立 `include_in_editing` 偏好，历史及新分镜默认允许参与，但仅实际有效已采用视频才呈现勾选；没有有效采用视频时禁用。用户取消后刷新或改用候选不得自动重新勾选。两条流程的前端、后端推进、Skill G4 和交接统一核验有效选择，至少一个即可；摘要显示“已选 N 个视频”，0 个时禁用进入剪辑按钮，原因仅通过按钮的悬停／键盘聚焦说明提供，不显示常驻黄色提示条或重复正文提示。未勾选和未完成分镜保留，不能自动采用预览或删除候选。首次时间线消费最新有效选择及排序；已保存的剪辑／导出继续保留，主动“使用最新分镜”才创建新时间线版本。

- Skill 分镜图片阶段使用 220–240px 紧凑导航，显示“分镜 01”等文字编号、缩略图与真实生成／采用状态，不显示时段，缩略图左上角不重复编号。缩略图优先显示实际已采用图片（轻量绿色对勾），否则显示最新成功生成图片，不加未采用圆圈；仅选择预览不等于采用，重新生成／失败不能清空旧结果。列表按内容高度紧凑排列，不拉伸行高，保留至少 44px 的选中触控区域。无结果显示稳定占位，不用项目参考素材冒充生成图。时间数据继续用于剪辑。摘要只传图片元数据，懒加载缩略图，不为列表读取全部候选／视频详情。
- Skill 分镜图片支持显式一键生成全部有效分镜的主画面；按稳定画面 ID 创建持久化子任务，最多并发三张，逐张显示结果、进度和心跳，允许停止排队与失败重试。新手动批次生成全部分镜但不覆盖历史或人工采用；自动工作流仍只补缺，未知上游结果不得盲目重提。模型、尺寸、单图参考与预算保持用户确认的契约，生成前刷新自动保存，生成成功不能代替人工采用。
- 图片阶段按需读取分镜摘要和当前详情，不预读视频草稿、时间线、导出或全部版本；后台进度更新不得重载整个工作台或覆盖人工草稿。
- 批量图片的完成摘要只显示“完成 X/Y 个画面”，不拼接批次状态、跳过、排队或未完成数量；进度条、运行中心跳、停止／继续与折叠错误详情保留。图片画布不展示“可生成”的常驻徽标，实际生成中／失败等状态仍可见。
- 分镜列表的当前状态不能由历史批次失败永久决定：单镜重新生成后的可用图片或较新的真实任务应覆盖旧批次结果，已生成未采用显示“待采用”，正在重新生成显示“生成中／排队中”。保留批次时间用于判断先后，批次记录本身不改写；已有旧图不能掩盖新的生成失败，多画面中一张成功不能抹掉另一张失败。当前分镜复用已加载详情中的最新任务，不为状态展示逐镜读取全部候选。

- “分镜列表”和“有效分镜”统一显示紧凑缩略图导航项：原视频流程编号叠加在缩略图上，Skill 图片流程仅在文字标题显示编号；图片使用 `object-fit: contain` 完整显示。图片阶段优先显示当前图片候选（Skill 按上条优先采用图），视频阶段优先显示当前视频候选并回退到已采用图片和原关键帧。缩略图失败时必须继续回退或显示稳定占位，不显示浏览器破图。

## Production image candidate history

- 两条流程的单镜生图数量默认都是 1 张，不继承账户设置或 Skill 契约中的多候选默认值。旧界面缓存中的数量按新版默认策略回到 1，但模型、分辨率和输入方式保留；用户此后明确为单镜／画面选择 2–4 张时独立记忆，切镜或后台刷新不得重置。界面摘要、成本预估与实际提交使用同一个数量；历史生成任务和恢复／重试快照不改写，批量生图继续固定每镜 1 张。

- 生成素材的入库状态按候选稳定 ID 独立核验。只有确认未入库才显示“加入资产库”；核验中、核验失败和已入库都不展示按钮或常驻状态文字，切图与过期异步响应不得串用状态。点击后以紧凑原生窗口填写名称、目录和类型，可新建目录，说明与标签默认折叠；窗口固定打开时的素材，取消不创建资产，失败保留草稿，重复提交不重复入库。按账户、工作区和项目记住上次成功入库的目录。Skill 与原视频流程复用同一组件，图片预览区不显示“已选择”标签，保留选中边框与“已采用”。
- 每次真实 AI 生图产生的候选按生成批次保留；生成新候选、改用源视频关键帧或取消采用都不得自动隐藏、归档或删除旧候选。历史候选仍可重新选择并采用，只有用户明确执行删除或归档动作时才移除。
- 分镜图片工作台继续使用“当前关键帧 / AI 生成图”双预览；选择关键帧只改变待采用目标，右侧 AI 预览和下方候选历史始终保留。候选使用固定尺寸的单行横向轨道，最近批次默认显示，展开历史时旧批次追加到同一轨道并横向滚动，禁止恢复为每个批次独占一行的纵向堆叠，也不使用弹窗或下拉框承载候选历史。
- 候选缩略图和主预览都使用 `object-fit: contain`，并明确区分“已采用”“待采用”和“历史候选”；已经采用一张图时允许直接选择另一候选并执行“改用”，无需先取消采用。
- 图片候选审核不显示“退回原因 / 退回修改”独立行；用户通过切换候选、重新生成或取消采用完成调整，避免重复的拒绝流程。
- 横向候选轨道中的卡片只显示图片，不重复显示“候选 1”页脚或“候选 / 历史 / 待采用”角标；状态通过选中边框和无障碍标签表达。轨道使用自由横向滚动，不启用会阻止回到绝对左端的滚动吸附。
- 分镜图片“取消采用”直接执行，不显示影响确认弹窗；只取消当前画面的采用，已有下游视频、剪辑和导出保留，操作结果通过账户消息提示。

## Production video candidate lifecycle

- 视频候选按生成批次永久保留并可重新预览、选择和采用；生成新候选不得覆盖旧视频。候选过多时使用候选区内的“管理”模式逐个勾选，并通过顶部“全选可删除／清空选择”完成批量操作；批次标题不重复显示第二个复选框，也不在每张缩略图上常驻堆叠删除按钮。
- 浏览状态下的视频候选缩略图在精细鼠标悬停约 180ms 后才按需加载 `content_url`，静音循环预览；同一时间只加载和播放一个候选，移出后停止并释放媒体地址，悬停不得改变主预览选择。管理模式、回收站、触屏设备和启用“减少动态效果”的系统继续显示静态缩略图。
- 用户删除视频候选采用可恢复的软删除：状态写为 `archived` 且原因写为 `user_deleted`，默认候选轨道隐藏，回收站可批量恢复为“可采用”。媒体文件、生成任务、成本记录和历史 Revision 继续保留；在建立引用感知的垃圾回收器前不提供物理永久删除。
- 当前已采用的视频候选禁止移入回收站，前端显示锁定状态，后端必须再次校验；批量操作保持原子性，任一候选不符合条件时整批不执行。删除当前预览但未采用的候选后，预览依次回退到已采用视频、同批次其他候选或最新可用候选。
- 删除和恢复使用候选区内联确认条，不使用阻断式弹窗；每次批量操作只创建一个 Revision，并通过账户消息与 Toast 报告完成或失败。

## Production visual beats and ordered references

- 一个“分镜”对应一次独立视频生成任务，但可包含多个按时间排序的“画面”；每个画面必须拥有独立的关键帧／AI 图片候选、提示词、采用状态和稳定 ID，不能把多个场景重新压回一个图片提示词。
- 分镜图片与视频提示词编辑器统一使用自动保存：停止输入后保存，失焦、折叠、切换分镜／画面和点击生成前立即补保存；界面不显示手动“保存”按钮，也不常驻“提示词修改后自动保存，不会自动生成图片”等说明。提示词标题行仅显示“待保存／保存中／保存失败”的动态状态，成功后不显示“已保存”；失败保留重试入口，不改变保存流程。
- 分镜图片工作台使用紧凑横向“画面轨道”显示图1、图2……；支持新增、删除和排序。画面名称与画面间转场由系统按轨道顺序自动管理，不显示逐画面的名称、转场类型或转场秒数表单。切换画面只切换当前编辑目标，不得隐藏其他画面的候选历史。
- Skill 与“分析报告 → 创建视频”的分镜图片页共用单／多画面显示逻辑：只有一个画面时，标题只保留分镜编号与轻量“新增画面”，隐藏时间段、画面序号、整个画面轨道及其外框留白；实际生成中／失败等反馈保留。增加到两个画面时展开轨道，删除到一个时自动收起并选中剩余画面。判断只依据分镜内 `visual_beats` 数量，不按候选、历史图片或资产数量判断。原视频片段保留模式不展示新增画面，继续保留精确时间范围。隐藏展示不能删除时间数据、提示词、绑定、候选或采用结果。
- 图片提示词只描述当前静态画面的主体与服装、场景、构图、光线和色彩，不包含时间轴、动作阶段、镜头运动或转场；动作、运镜、时间与转场只进入视频提示词。
- 图片提示词编辑器依靠输入占位和 `@` 菜单表达资产引用能力，不在编辑器下方重复显示“输入 @ 选择资产”及内部 ID 保存说明。
- 分段视频工作台不再额外显示独立的“有序参考画面”故事板卡片；已采用图片统一在“生成参考”和提示词引用中呈现。视频请求仍须按画面轨道顺序提交全部必需画面，缺少任一必需画面时禁止生成。
- 进入分段视频时，系统按画面轨道顺序自动把当前分镜的已采用图片加入“生成参考”，并在视频提示词开头写入对应的原子化 `@分镜图/图N` 引用。用户手动移除的自动参考按稳定画面 ID 记忆，候选图片更新后不得失效；提供“恢复默认”以重新同步全部画面。参考顺序与提示词顶部引用顺序保持一致，模型容量不足时必须阻止生成并说明上限，不得静默丢图。
- 自动分镜图引用覆盖当前分镜全部已采用画面，不按 `required` 筛选，也不使用其他分镜、未采用候选或资产库图片补齐。首次进入、切换、刷新和采用变化共用同步规则；前后端默认绑定、编辑器缩略图与实际生成输入一致。按稳定画面 ID 更新采用候选或编号，保留正文内引用位置及手写内容，缺失引用才补入顶部；引用按完整标签匹配，不能把“图10”误认成“图1”。后台刷新与未保存草稿合并时同步引用和待提交数据，不逐键重写正文，不覆盖明确移除记录；必需素材、权限和容量校验继续保留。
- 当前流程只允许声明 `multi_image_reference` 与 `ordered_reference_images` 的视频模型。能力不足的模型不得出现在可用选择器中，也不得由 Provider Adapter 静默丢弃参考图或降级为单首帧调用。

## Production video creative intent

- 分析报告创建视频保留“创作意图”入口：用户用自然语言说明人物、服装、产品、场景、对白、动作、镜头和转场的保留、替换或重设计要求；语义理解与提示词草拟由文本大模型完成，资产 ID 解析、权限检查、去重、顺序、模型兼容和最终绑定由程序完成。Skill 分镜视频已有提示词，隐藏创作意图入口，旧意图状态不得阻止生成，直接编辑局部／全局提示词。
- 创作意图只允许读取和改写当前分镜的原始视频提示词；图片提示词与图片标题只作用于图片生成，禁止进入创作意图模型上下文或最终视频提示词。已采用的原图／生成图仍可按稳定 ID、顺序和时间范围作为视频模型的视觉参考，但更改图片提示词不得改写视频提示词正文。
- 创作意图编辑器必须支持原子化 `@` 引用项目资产、托管角色、分镜图片、深度视频和可用参考视频；显示文本与稳定对象 ID 分开保存，复制时仍是纯文本。Backspace／Delete 一次删除完整引用，未完成或已失效的 `@` 引用禁止提交，不得按名称静默替换。
- 未绑定托管角色时，创作意图的 `@` 菜单必须提供托管资产目录入口；用户选择后先绑定到当前分镜，再自动插入带内部稳定 ID 的 `@托管角色/...`，不得要求用户离开编辑器预先配置。
- 用户显式 `@` 的资产优先于名称模糊匹配。大模型只判断该引用承担人物、服装、产品、场景、动作或转场等哪类职责，并原样返回稳定 `reference_key`；对象权限、类型兼容和最终绑定继续由程序校验。
- 创作意图生成后自动更新资产引用和局部视频提示词；局部默认展开，全局默认折叠且不得被意图解析改写。分镜视频移除“资产引用与控制”及重复生成参考选择器，引用统一通过提示词编辑器的缩略图、`@`、添加资产和按需恢复默认完成。深度视频、托管人物等独有操作放在默认折叠的“高级控制”，按真实能力显示；原有绑定、顺序、负面约束与容量校验保留。
- 创作意图生成完成后不再展示大模型理解摘要或“替换／保留”说明段落；结果区只保留状态，以及打开引用和提示词编辑区的紧凑操作，详细内容在已有编辑区中查看。
- 人工修改不得被后续意图解析静默覆盖。系统保存最近自动基线；提示词存在人工修改时重新解析只更新自动基线并显示冲突，用户必须显式选择恢复自动版本。用户手动移除的意图引用也应记忆，重新解析不得自动加回。
- 深度视频只有在意图明确要求保留动作、姿态、节奏、空间或运镜时才承担这些职责；默认只是引导参考，不得固定解释为逐帧复刻，也不得提供人物身份、服装、颜色或纹理。
- 转场继续由视频模型生成。要求保留原转场时，优先使用真实原片段证据；暂不支持片段输入的模型使用分析事实和前后分镜图，并明确提示证据降级，禁止默认改为硬切。
- 创作意图解释与视频模型提示词必须分层保存：界面摘要和结构化指令可以描述“替换／保留／重新设计”，提交给视频模型的提示词只能描述这些操作完成后的最终画面、表演与时序状态，不得把编辑过程直接拼入模型输入。
- 视频提示词折叠区只显示一处可见标题和字数；展开后的编辑器使用无障碍名称标识输入区域，不再重复显示同名字段标签。

## Account notifications

- 异步操作的完成、失败、余额不足等结果统一进入顶部账户消息中心，并用短暂 Toast 提醒；主工作区不重复放置大块状态卡。消息按账户隔离，前端只传业务跳转参数，不传账户 ID。
- 视频候选下载使用媒体右上角悬浮图标；模型、候选数量和预计／实际费用放在生成操作行或候选审核行内，避免单独占据整行。
- 通知深链必须在 React StrictMode 的 effect 重放下保持幂等；不要用会跨越 StrictMode 二次执行的一次性 ref 提前阻断项目或候选定位。

## Account text model preferences

- 文案与提示词模型是账户级生成偏好，默认使用 `Qwen3.7 Plus`；设置页只返回版本化模型目录中的别名和说明，不读取或保存 Provider 凭据。
- 设置页提供一个默认文案模型、一个“失败时自动回退”开关，以及默认折叠的按任务覆盖区。任务只对应真实调用链：分析结论与复刻方案、分镜说明与图片提示词、创作意图与视频提示词；不得增加不能改变实际路由的伪设置项。
- 文案模型设置不得改变图片生成模型、视频生成模型、分镜切分、实体消歧或图片质量检查的路由；任务覆盖和回退行为只作用于文案任务。
- 复刻、分镜图片和分段视频等生成入口统一显示只读短标签 `文案模型：{模型名}`；不得追加“在设置中修改”、链接或第二层说明。

## Production editing timeline

- 已有时间线不会因读取页面、保存、预览、恢复历史或上游修改自动同步最新分镜。只显示轻量提醒；用户明确点击“使用最新分镜”才刷新待保存修改、校验当前版本并生成新时间线版本，保留旧版本和导出。恢复历史必须恢复该版本的原始素材，不得随即自动替换成最新素材。
- “视频剪辑”是独立的 `src/video-editor/` 功能模块，不尝试复刻专业 NLE 的任意拖拽能力；桌面端使用左侧工作列与右侧检查器：监看播放器和 V1／A1／A2／T1 时间线在左侧以约 12px 间距紧邻排列，右侧为片段／音轨／字幕属性检查器。检查器内容过长时内部滚动，不得再把时间线推到检查器下方；1080px 以下按“预览、时间线、检查器”改为上下结构。
- 勾选“保留”的分镜只保存原视频 ID 与精确源时间范围，不生成独立分镜 MP4 或分镜封面；同一原视频上首尾相连、未裁剪、未变速且无转场的保留分镜在预览和导出时必须自动合并为一个连续原片区间，只保留逻辑分镜边界，禁止在内部边界重复裁切、补尾帧、逐段编码或逐段处理原音。
- V1 时间线片段使用纯色块、分镜编号与时长表达，不生成或展示分镜封面、胶片缩略图或封面时间戳；最终成片封面属于导出产物，不受分镜无封面规则影响。
- 首期轨道固定为 V1 视频、A1 分镜音频、A2 附加音频和 T1 字幕；A1 支持每个片段在“沿用原分镜音频／候选新音频／静音”之间切换，并支持片段启停与排序、裁剪、直接切换／淡入淡出／叠化、音量、附加音频上传／启停／音量／循环和字幕编辑；分段视频不提供手动封面帧控件，也不实现专业 NLE 的自由拖拽、多层特效或关键帧动画。
- 时间线首次初始化直接消费已采用的视频候选；旧项目若存在匹配候选的 `VideoClipPreparation`，继续迁移其裁剪、封面、音轨和质检数据，但旧准备记录不再作为推进门禁。
- 时间线内的入点、出点、成片时长、声音、转场、轨道和字幕修改必须在停止输入后自动保存为新版本，不提供手动保存按钮；附加音频上传、历史恢复和生成低清预览前必须先刷新待保存修改，并始终携带最新时间线版本。自动保存失败时保留草稿与撤销历史，显示可重试的紧凑状态，禁止把未保存的界面状态提交给后续任务。
- 视频剪辑不展示自动质检结论或“重新质检”入口；片段画面、节奏和衔接由用户通过实时预览与合成预览人工核对。
- 横版、竖版和方形预览继续使用方案画幅容器与 `object-fit: contain`，完整保留画面，并在视频下方使用固定自定义播放控制条。
- 实时时间线预览和最终渲染必须使用同一片段声音路由：“沿用原分镜音频”静音候选视频并同步播放源视频精确音频区间，“候选新音频”播放候选文件的实际内嵌音轨，“静音”不播放主音轨；候选没有实际音轨时必须禁用候选音频选项。异步渲染进度只在工具栏紧凑显示，完成、失败和取消统一进入账户消息中心。
- 版本历史优先使用页内渐进展开；恢复旧版本会创建新版本，不覆盖历史快照，也不使用阻断式弹窗。
- 低清预览画布的宽度上限必须根据方案输出宽高比与最大预览高度成比例计算，不得同时用全宽和固定 `max-height` 破坏竖屏画幅；控制条不依赖会自动隐藏的浏览器原生控件。

## Production final export

- “导出成片”是视频剪辑后的独立工作流步骤；最终任务必须绑定已保存的 `timeline_revision_id`，不能读取仍在编辑的时间线草稿，也不能把低清预览当作最终交付文件。
- 导出设置首版提供 720P、1080P、方案尺寸，烧录字幕、内嵌字幕、无字幕，以及标准／高质量编码；默认使用 1080P、烧录字幕和高质量，输出 MP4/H.264/AAC。
- 导出完成、失败和取消继续通过账户消息中心通知；主页面只显示紧凑进度、最新成片和历史产物，不放重复的大型完成状态卡。
- 最终成片播放器对横版、竖版和方形媒体统一使用 `object-fit: contain`；播放器画布本身必须按成片宽高比和可用高度共同缩放，不能把竖版视频放进固定横向容器后依靠 `overflow: hidden` 裁剪；成片质量由用户人工核对，页面不展示自动校验结论或导出清单入口，产物行只保留下载与必要的成片元信息，旧导出不得被新任务覆盖。

## Production project lifecycle

- 删除创作方案采用回收站生命周期。移入回收站后从当前方案列表隐藏，保留恢复能力，并通过短时“撤销” Toast 提供快捷恢复。
- 永久删除只允许在创作方案回收站内执行，并且必须二次确认。确认文案需要说明方案版本、分镜规划和方案生成文件会被删除，但资产库中的共享资产和来源分析记录会保留。
- 当前方案卡片和方案详情通过克制的更多菜单提供“移入回收站”，不常驻展示红色删除操作；回收站卡片直接提供“恢复”和“永久删除”，无需先打开已删除方案。

## Category profile library and concept generation

- “品类库”是账户级长期配置入口，固定放在左侧主导航的“资产库”之后。页面使用紧凑的主从布局：左侧搜索和选择档案，右侧编辑品牌、品类、一句话定位、目标人群、核心卖点、常用场景、禁用表述与视觉风格；不得改成宽松的卡片宫格。
- 删除品类档案使用可恢复的软删除。删除后不再出现在方案生成选择器中，但已经生成的方案必须继续显示生成当时的不可变档案快照，后续编辑或删除不得使历史方案过期。
- “复刻与改进”必须先选择一个品类档案，禁止用临时自由输入替代。三套方案固定承担结构迁移、场景叙事、证据说服三种不同创意任务，并分别展示创意主张、钩子、叙事结构、视觉记忆点、结尾兑现和核心改动；不得只在同一套逐镜头提示词前追加不同策略前缀。
- “复刻与改进”的品类选择器使用紧凑单行控件，管理入口与选择框并排；不使用大面积外层卡片或重复的目标人群／卖点／场景摘要。生成区只保留必要状态、文案模型和主按钮，不再用第二个大卡片重复说明三套方案。
- 桌面端允许三套方案并排比较，移动端改为单列，不使用无提示横向滚动。方案名称使用 16px／600，正文使用 14px／1.55，交互控件使用 14px、移动输入使用 16px；紫色只用于主操作、焦点和当前选中态。

## Production video enhancement

- “AI 清晰化”只出现在当前已采用的视频候选中；未采用候选不显示该入口。默认使用 Real-ESRGAN 本地快速档，安装必须由用户显式触发，不得因打开页面而自动下载。
- 清晰化结果是同一候选的派生分辨率版本，不创建新候选，也不自动替换成片来源。播放器允许在原始版与已完成的 1080p／4K 版本间比较，只有用户点击“用于成片”后才切换有效媒体版本。
- 原始视频始终保留；任务需要持久化进度、支持后台继续、取消、失败重试和服务重启后的明确中断状态。480p 提升到 4K 时必须提示其不等于原生 4K 细节。

## Platform Skill workflow

- 首次大纲与分镜把用户已选资产的名称、目录、类型和稳定 ID 一同交给创作模型，由模型同时产出提示词与引用用途；只接受能明确对应所选资产的选择。同名歧义、无信息名称或不确定时留空，不轮流分配、不补齐、不搜索整个资产库。历史或人工修改的提示词不在刷新时重新匹配。
- 大纲、分镜图片与分镜视频使用统一的原子引用编辑器：上方紧凑缩略图列，正文标签只显示“缩略图＋图片1”等编号，不显示素材名称；字体和字重继承提示词正文，使用中性浅底、细边框与圆角。完整名称保留在预览、悬停和无障碍标签内。`@` 只搜索当前项目已选素材；“添加资产”须由用户显式打开资产库，选择后加入项目并插入当前提示词。悬停／聚焦预览，点击支持定位、替换与移除；文字与稳定 ID 一起保存，最后一次引用删除同步解绑，撤销恢复原绑定。全局提示词仍默认折叠，不把全局和局部正文重新混合。
- 中文输入法组合期间不得重建编辑器 DOM；回车和粘贴不得删除相邻引用，手动编辑的视频提示词不得被逐键 trim 或重建引用声明。生成参考按真实绑定与顺序编译，不能把 UI 的临时编号作为资产标识；素材不可用须明确反馈，不得换成另一张图。
- `@` 菜单只滚动内部候选列表，禁止通过 `scrollIntoView` 滚动外层页面；页面／编辑器滚动时菜单重新定位，不直接关闭。普通输入和自动保存回显不得重建未变的引用 DOM、抢焦点或关闭菜单；支持中文输入、键盘选择、Esc 和点击外部关闭，使用真实浏览器隔离测试覆盖长文本和滚动场景。
- 复合提示词编辑器不得包在原生 `label` 内，避免正文点击被转发到第一颗缩略图按钮；标题通过 ARIA 关联。只有引用标签和缩略图能打开预览，点击普通正文应关闭预览并正常定位光标。预览 Grid 和图片元素都必须限制最小尺寸，横竖图完整显示且不能覆盖名称或操作按钮；这些行为必须通过真实浏览器回归测试。

- Skill 广场封面是平台级展示配置，与不可变生成 manifest 和项目快照分离。管理员在“平台 Skill 目录 → 封面与预览”维护；首期仅一图一视频，接口保留展示项数组、稳定 ID、排序和主展示项，不提前实现轮播。只允许绑定本 Skill 的平台素材，不能借用账户私有资产地址。
- 封面优先使用自定义图片，其次视频首帧，最后原有默认图；卡片保持 16:9 容器，媒体完整显示，不拉伸或裁切主体。默认不加载视频，鼠标停留约 200ms 后静音循环播放，同一时间只播一个；移开、离开视口、切换标签页均停止并释放视频。触屏和减少动态效果模式用显式播放按钮，封面点击与“用这个 Skill”入口继续保留。
- 封面上传必须展示真实上传进度、后台处理阶段和失败重试；素材全部可用后才能保存替换，处理中或失败时旧封面不变。视频原件保留，提取第一可解码帧并生成浏览器兼容的静音预览。未发布或未绑定的素材仅管理员可访问；保存使用版本冲突校验，不能覆盖另一管理操作。

- 风格确认不展示创作目标摘要、风格／品牌标签或重复的 Look Test 标题；约束仍保留在冻结快照和实际生成请求中。大纲与分镜的视频提示词不包含“剪辑落点”；这些建议单独保留并传入视频剪辑的可编辑、自动保存字段，不能因此丢失结束状态或运镜，也不自动改写入点、出点。
- Skill 图片选择复用原视频流程已有的本机 ImageGen，入口显示“image-2（本机 ImageGen）”，不是新增 Images API。创建页的图片、视频参数是明确标注的默认配置，不是后续模型白名单；Look Test、单图、批量和单镜视频可以独立选择当前平台模型与支持的分辨率，选择后不反写项目默认值。实际提交时冻结本次参数，恢复沿用原任务快照；不得静默切换或降档。调度模型与图片工具分别记录；未知本机费用只有在无硬预算的引导模式下经过显式确认才可执行，能力限制按单张请求校验，任务先恢复输出再考虑重试。
- 创建阶段不设置配乐、旁白、字幕，新契约将这些意图保存为未配置，在配乐与字幕阶段人工处理；不凭隐藏默认值强制生成或阻塞前置阶段。历史契约和候选不重写。
- Skill 分镜图片批量入口只保留“一键生成全部分镜图”；点击后在原生弹窗选择本次模型／分辨率、确认费用与数量，参数不常驻页面。打开、取消、Escape 都不触发生图；确认后冻结参数，成功提交后关闭，页面只保留进度与结果。新手动批次每个有效分镜固定只生成 1 张，多画面分镜只处理排序第一的主画面，不继承项目或单镜候选数；前后端与费用计算保持一致。每次主动确认创建新批次并保留历史和已采用结果；运行中禁止重复提交，网络重试幂等，“继续未完成任务”沿用原批次参数、数量和画面集合。自动流程仍只补缺并覆盖必需画面，不因手动按钮改成全量而反复生成已完成画面；单镜独立生成仍可一次生成多张。
- 单镜模型按钮使用紧凑名称（本机工具显示 `image-2`），长名称省略但不能挤掉图标／箭头；悬停和模型列表保留完整信息。选中资产不显示参考角色下拉框，保留内部角色、权重、身份检查和自动分配，类型只用中文静态文字展示。
- 全局／局部提示词使用共享标题行组件，统一字体、间距和保存状态位置；局部默认展开，全局默认折叠。图片面板不再重复显示“分镜配置”，单类全局展开后不重复标题。系统编译及当前视图清理连续中文句号，不逐键改写、不中断输入法；引用标签、链接、英文小数点和省略号保留，历史候选与不可变快照不重写。
- “复制局部”“查看完整提示词”和全局提示词折叠入口使用共享弱化样式：12px、常规字重、中性辅助文字色，减少留白与装饰性分隔线，悬停／聚焦时增强反馈。全局适用范围放在悬停和无障碍说明中，不常驻重复文字；展开后的正文保持正常可读字号。局部标题、生成主操作以及真实保存失败／冲突信息不得一起弱化。
- 图片候选选择以选中样式反馈，不弹出“候选已选择，请继续人工确认”；选择不等于采用，人工确认、刷新与失败提示继续保留。
- 图片提示词的界面、复制与实际生成请求统一移除“连续性锁定”“主体一致性”段落及公共／负面约束中的运镜、跨帧和连续镜头要求；保留构图、光线、材质、静态机位与焦段、景深及参考产品准确性。视频提示词不受影响。历史项目通过只读投影清理当前视图与新请求，不改写历史快照、候选或哈希。
- 图片与视频分辨率选择及相关摘要使用 480p／720p／1080p／2K／4K 等档位，后端仍保存实际尺寸。只提供当前模型真实支持的档位，不默认降档；无法精确对应的已有尺寸显示“原有规格”，不能伪称 720p 或 4K。

- Skill 分镜数量仅作风格与节奏建议，不设固定数量、最小范围或数量上限；模型结果和人工增删均以实际镜头列表为准，只有 0 个镜头禁止确认与推进。不得因与案例数量不同自动补齐、裁减或重试；已返回结果和完成的编译进度需持久化，恢复不能覆盖人工草稿。失败后展示实际模型、停止时间、耗时和具体原因，不继续展示运行中心跳。

- Skill 的风格确认和大纲与分镜共用全宽正文边界；生成、失败和确认区不得因按钮式左对齐而收缩成左侧窄卡片。Look Test 按容器可用宽度展示宽屏最多四列、中屏两列、手机单列，预览画布按项目画幅与窗口高度共同计算，完整显示图片，不能只拉宽背景框。分镜图片／视频提示词在足够宽时并排，不足时按编辑器容器宽度上下排列；不新增右侧说明面板，按钮保持内容尺寸，自动保存与生成行为不因布局变化而改变。
- Skill 的“大纲与分镜”展示简短创作思路、默认折叠的全局图片／视频提示词和逐镜可编辑的局部提示词。桌面两栏、移动单栏，直接输入并自动保存；支持插入、添加、删除及撤销。全局跨准备、图片、视频阶段共用同一版本，后半程默认只编辑局部，全局默认折叠。复制默认局部，完整预览为只读组合；生成任务与批次冻结全局、局部及版本，不修改历史候选和采用状态。旧项目仅提取确定的公共段落，不猜测改写人工正文；跨页面版本冲突需保留草稿并提示核对。导演元数据与帧级时长继续内部保留，空白分镜允许存草稿，人工确认前再校验。生成文案除专业术语和品牌名外用中文，禁止静默翻译用户手写正文。

- Skill 项目不经过原视频分析和分析报告，从 G0 创作简报开始依次经过风格、分镜、图片、视频、画面锁定、声音字幕和交付；后半程复用现有创作方案、候选、时间线和导出能力。分析项目继续保持原有流程，两类项目在统一项目列表中通过来源和阶段区分。
- 图片模型、图片尺寸、视频模型、视频分辨率、是否生成新音频、guided／full_auto 和预算上限都由用户显式决定；不得默认改用便宜模型、先做 360p 草稿、静默回退 Provider 或把未知价格显示为零。
- 图片提示词只定义静态画面，视频提示词只定义基于已采纳图片的动作、运镜和时间变化；两者独立保存。系统校验、AI 评分和自动执行均不得替代 G0–G7 的人工批准，full_auto 只在人工通过当前门禁后推进下一阶段执行。
- Logo、包装文字、认证标识等 `exact` 素材不得交给生成模型重绘；提示词只预留安全区域，最终导出通过可追溯素材哈希执行确定性叠加。当前合成器不支持的跟踪、透视、缩放或混合方式必须阻止公开交付并提示人工后期。
